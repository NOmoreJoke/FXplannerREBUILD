# Design Commands（五步标准设计协作规程）

所有前端界面改版与新增组件严格遵循以下 5 个动作推进至 **Design Complete**：

| 动作 | 触发时机 | 执行要点 |
| :--- | :--- | :--- |
| **1. `Steer`（定舵）** | 新页面、大改版或方向未定时 | 动手写代码前先把品味、受众视角（Solo vs Team）与克制度交由人类拍板，不盲猜审美。 |
| **2. `Concept`（发散）** | 关键核心屏探索期 | 给出 2–3 个结构或气质真正不同的概念方向对比取舍，收敛后再进实现。 |
| **3. `Tune`（宏观调参）** | 方向已定但整体呼吸感或语气偏离 | 成组调节留白密度、语义 Token 或知禾文案温度，不零碎打裸样式补丁。 |
| **4. `Comment`（定点精修）** | 针对具体局部元素微调 | 精准修改目标区域，保持周边已验证通过的对齐、等宽数字与状态流转不变。 |
| **5. `Review`（交付前门禁）** | 每次宣称前端改动完成前（强制） | 对照 `foundations/*` 与 `intelligence/policy.md` 逐条核验，并在 `1440px` 与 `390px` 双视口实测检查无横向溢出、无断行孤字、无违规色阶。 |
