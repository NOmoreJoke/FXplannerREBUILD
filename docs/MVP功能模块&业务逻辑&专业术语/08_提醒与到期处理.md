# 08 提醒与到期处理

MVP通过站内通知提醒，首页和计划详情同时显示当前状态。用户可以关闭主动提醒，但页面仍显示日期、缺口和计划进度。

## 什么时候提醒

准备日期和使用日期的提醒适用于进行中的计划。

| 场景 | 显示或提醒内容 |
|---|---|
| 到了某次准备日期 | 提醒查看本次安排；钱已备齐则停止准备提醒 |
| 旧安排需要更新 | 提示先查看并确认新安排，不再按旧日期提醒 |
| 最晚准备日仍缺钱 | 显示“未备齐” |
| 最晚准备日过了仍缺钱 | 从次日起显示“准备逾期” |
| 到了预计使用日 | 提醒核对实际用了多少钱；钱已备齐也可以提醒 |
| 预计使用日已过 | 从次日起显示“预计使用日已过” |
| 已用金额等于目标，剩余分配为0 | 提示确认计划完成 |
| 计划已完成或已取消 | 停止主动提醒 |
| 计划重新开启 | 按当前状态恢复提醒，不补发以前的提醒 |

准备提醒不表示已经换汇，使用日提醒也不会自动扣钱或判断用户未付款。钱备齐、计划完成或取消后，清除准备逾期提醒。

## 避免重复打扰

- 同一计划同一天合并为一条提醒。
- 逾期状态持续展示，不每天重发。
- 刷新、更新安排、重新开启计划，都不重复发送当日已有提醒，只更新内容。
- 关闭后重新打开提醒，同一天也不重复发送。
- 错过的日期不补发，只显示当前状态；以后的新日期仍正常提醒。

## 还缺多少钱

缺口＝目标金额−已经使用的金额−本计划剩余分配，最低为0。账户未分配的余额不会自动抵扣。

| 例子（USD） | 结果 |
|---|---|
| 目标10,000，已用4,000，剩余分配6,000 | 缺口0，停止准备提醒；进行中计划到使用日仍提醒核对 |
| 目标10,000，已用4,000，剩余分配5,000，账户另有未分配1,000 | 缺口仍为1,000，用户分配后才计入 |

## 完成后纠正使用金额

正常完成的计划，把误录的使用金额调小后，仍显示“已完成”。页面列出目标、修改后的实际使用、两者差额和账户可分配余额，不把差额标成待补资金，也不催用户补齐。

例如目标10,000 USD，已用由10,000改为9,600，原账户余额为0且无剩余分配：账户可分配余额增加400，计划仍已完成。这400属于账户，不专属于原计划。

## 待确定

提醒使用的时区、当天截止时间、跨天处理，以及更新后的剩余准备日期怎样对应原安排。邮件等其他通知方式放在后续版本。
