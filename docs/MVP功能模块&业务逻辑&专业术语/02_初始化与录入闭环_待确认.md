# 02 初始化与录入

## 填写已有外币

1. 选择地区和语言，确认已满18岁及必要条款。
2. 选择本位币及准备偏好，再选择是否已有外币；没有则跳过。
3. 有外币则选择币种，填写此时实际持有的总金额。同一币种只填一行；不能把本位币填作外币。
4. 系统查询最新汇率，显示来源、报价时间及初始成本。
5. 设置站内提醒，核对各币种金额与成本，确认填写的是现在实际持有的金额，最后一起入账，不重复勾选年龄与条款。

若填写草稿后又买入或使用了外币，最后确认前先更新金额。确认之前发生的变化都包含在初始余额中，之后不能再补录一次。

支持香港和中国大陆、简体中文和英文，默认简体中文及均衡准备偏好。币种见[币种清单](附录/币种清单来源核对.md)；首次设置完成后不能更换本位币。

首次设置草稿从最后一次成功修改起保存30天。未提交的填写内容不增加账户余额，也不能分给计划。登录、草稿和账号数据操作见[首次使用与设置](01_首次使用与设置_待确认.md)。

## 初始成本怎么算

汇率统一显示为“1单位外币＝多少本位币”。

**初始成本＝已有外币金额×本次采用的汇率。**

例如本位币为人民币，已有1,000美元，汇率为1美元＝7.20元人民币，初始成本为7,200元。后来汇率变为7.30，这笔已经记下的7,200元不随之变化。

这个成本只是首次记录时的折算金额，不是当年买入这些外币的实际花费。不要求补填历史买入价或当年的手续费，也不能手填一个成本覆盖系统计算。

## 汇率什么时候刷新

| 场景                             | 处理                                                                             |
| -------------------------------- | -------------------------------------------------------------------------------- |
| 打开录入页、换币种或重新继续草稿 | 立即查询对应币种的最新报价                                                       |
| 停留在可编辑的金额页面           | 每60秒查询一次；金额输入不变，参考汇率及预计成本随查询更新                       |
| 可编辑金额页切到后台             | 暂停自动查询；返回前台后重新查询。最后核对页返回前台时只检查是否过期，不自动换数 |
| 进入最后核对页                   | 为所有已填币种重新查询，展示本次准备采用的金额、汇率、来源、时间及初始成本       |
| 停留在最后核对页                 | 不自动改动本次数字；显示报价剩余有效时间                                         |
| 报价过期                         | 暂停确认，重新查询后展示新旧差别，由用户再次核对                                 |
| 改回前面修改金额或币种           | 原核对结果作废，重新进入核对页时再次查询                                         |

### 哪些报价可以使用

- 从报价来源标注的时间起，未满5分钟才有效；恰好满5分钟视为过期。不能用“刚刚收到数据”的时间代替报价时间。
- 来源、币种方向和报价时间必须齐全，汇率必须是大于0的有效数字。时间在未来、方向不匹配或缺少时间的报价不能采用。
- 多个币种分别检查，以最早过期的一笔决定本次确认剩余时间。提交时再检查一遍，但不悄悄换成另一组数字。
- 刷新后若仍拿到同一份旧报价，不延长有效期。已入账的历史报价不再受5分钟期限影响。
- 查询失败或来源休市、未更新时，显示最后报价时间与原因，保留草稿；超过5分钟的旧价不能用于初始入账。没有有效报价时，不能改用手填价、昨日收盘价或0。

例：来源报价时间为09:00，09:01收到，最晚只能在09:05之前提交。09:05再次收到同一份09:00报价，也不能继续使用。

## 金额和小数怎么处理

| 内容                     | 规则                                                                                                                            |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| 日元JPY、韩元KRW金额     | 整数，最小单位为1                                                                                                               |
| 其余支持币种的金额       | 最多2位小数，最小单位为0.01；包括HKD、USD、GBP、AUD、CAD、CNY、EUR、SGD、NZD、TWD、CHF、THB、MYR                                |
| 用户输入金额             | 首次填写必须大于0；超过允许小数位时提示修改，不擅自改小或改大                                                                   |
| 采用的汇率               | 将来源报价四舍五入到8位小数，用这个值显示并实际计算；原报价和来源一并保存                                                       |
| 初始成本                 | 按本位币的小数位数四舍五入；人民币保留2位，日元取整数                                                                           |
| 系统计算出的普通买入数量 | 按目标币种的小数位数四舍五入；实际到账不同可改用实际金额填写方式                                                                |
| 正数被舍入为0            | 汇率或自动算出的买入数量变为0，或初始金额大于0但成本舍入为0时，不提交。把误填初始金额更正为0则成本也为0，但仍检查后续使用和分配 |
| 本模块金额上限           | 单币初始金额和该笔折算成本均须小于100,000,000,000（各自币种单位）；超限提示修改，不截断保存                                     |

四舍五入采用“5及以上进一位”，不采用逢双才进位。例如人民币成本10.005元记为10.01元。

用确定后的8位汇率进行十进制计算。乘法保留完整结果；除法不先截成固定小数位，再算金额。只在最终金额处按对应币种四舍五入一次。8位汇率展示的末尾0可以省略，但计算值不变。

分批准备金额仍按“前几次向下取整，最后一次收齐零头”处理，不改成各次分别四舍五入。见[分批准备计划](07_分批准备计划.md)。

## 最后入账和记账起点

- 最后确认成功时，各币种初始记录一起保存。任何一笔失败，全部不入账；重复点击或重试，不重复增加余额。
- 记录初始金额、本次采用的8位汇率、原报价、报价来源和时间、计算后的初始成本，以及最后确认时间。
- 账本从首次设置最后确认成功的时刻开始，不能由用户回填到过去。记录日期按UTC+8显示与判断，不因设备时区变化改动历史日期。
- 每个币种只有一笔有效初始记录；金额先进入未分配余额，不自动留给任何计划。更正币种时，如果新币种已有初始记录，不能提交；应先检查原记录，不自动合并金额或生成第二条。
- 已完成设置后清空全部业务记录，新的记账起点为清空完成时刻；本位币仍不变，清空前的记录不恢复。

### 同一天的成本顺序

同一天依次处理：初始持仓 → 普通买入 → 实际使用。

普通买入之间按实际买入日期排序；同日按第一次录入的顺序。多笔使用同样按第一次录入顺序。更正不会把一笔旧记录变成最后新录入的一笔。

这是计算成本时的顺序，不表示系统自动记录了买入或支出。首次录入使用时仍要有足够可用资金，不能先透支再补买入。

## 怎样补录过去的记录

| 想补录的内容                                   | 处理方式                                                                                   |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 记账起点之后已经发生、只是忘记录入的买入或使用 | 可以按真实日期补录，不能填未来日期；先展示对余额和成本的影响，通过检查再确认               |
| 与记账起点同一天发生的买入或使用               | 用户额外确认“发生在记账起点之后，且未包含在初始金额中”；不符合时不能补入账本             |
| 记账起点之前的买入或使用                       | 不支持补入；这部分已经体现在开始时持有的余额中，不能再记一次                               |
| 补录使用                                       | 仍须属于计划，检查当时是否有足够同币种资金，以及当前分配和目标限制；不能绕过计划内使用流程 |
| 清空记录之前的旧数据                           | 不补回新账本，不提供旧数据迁移                                                             |

普通买入的历史记录填当时真实的支出本金及实际汇率或到账金额；今天的参考汇率不能自动代入历史成本。

例如初始已填1,000美元，其中包含当天早些时候买入的200美元，就不能再把这200美元录成一笔新买入，否则余额会错误变成1,200美元。

如果最初填的余额本身有误，应更正初始记录；不要通过伪造新买入、补一笔退款或改记账起点来修正。

## 初始记录填错了怎么改

从账户里的初始记录进入更正，先填原因，再看修改后的余额、计划分配、已使用成本和剩余成本，最后确认保存。原记录和修改记录都保留。

| 修改内容           | 处理                                                                                                                         |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| 金额填多或填少     | 改成最初确认那一刻实际持有的金额，不填今天的余额；沿用原来采用的汇率重算成本                                                 |
| 当时实际没有该币种 | 可以把初始金额改为0，保留一条更正记录；是否能保存仍须检查后续使用和分配                                                      |
| 币种填错           | 使用原确认时点对应币种的报价重算，不能用今天报价；先处理受影响计划分配，不迁移其他使用记录                                   |
| 当时漏填一个币种   | 可补一笔“初始记录更正”，金额填原确认时刻的余额；不是新增一笔今天的买入。该币种已有初始记录时，只能改原记录，不能再添第二笔 |
| 初始日期、本位币   | 不可修改                                                                                                                     |
| 初始成本或汇率     | 不可随意手填。计算错误按已保存金额和汇率修复；只有来源更正了原时点报价，且能取得该更正记录时，才可预览并替换汇率             |

币种更正或漏填币种需要原时点报价：先找当时保存、币种方向正确、报价不晚于原确认时刻且相差不足5分钟的数据；没有时，再向同一来源查询符合这些条件的历史报价，取最后一笔。当时保存但已经过期的报价也不能采用。仅有某日平均价、确认之后的报价或无法核对来源时，不能提交该更正。

每次报价替换都要显示原值、新值、来源和原因；不能因今天行情变化自动更新历史初始成本。漏填和币种更正使用的历史报价也采用8位汇率规则。

### 更正后哪些内容会变化

- 重算受影响币种从记账起点开始的余额、成本先后顺序、使用成本和剩余成本；使用数量、用途及所属计划不自动改变。
- 只改初始金额，不直接改计划目标、剩余分配或已完成状态。减少初始金额后，如果账户余额不足以覆盖现有分配，先提示到计划中调整。
- 如果更正后某一天已经发生的使用没有足够资金，阻止提交，并显示那一天和缺少的金额；不能拿之后买的钱补以前的缺口。
- 提交更正时重新检查最新余额、分配及后续记录。预览后若数据有变化，重新展示结果并再次确认，不能按旧预览直接保存。
- 金额、币种、成本、相关摘要与新报告一起更新。失败、取消或校验不通过时，不保存其中一部分；原数据保留。
- 提交后暂时不知道是否成功时，显示“正在确认结果”，先查询原请求，不再次创建初始记录。确认失败后可重试；成功则直接显示已保存结果。
- 更正成功后显示更新时间和修改记录入口，已经下载的PDF不改。

## 初始持仓是否计算收益

初始持仓可以用于计划分配、实际使用、账户成本和计划成本，但不计入收益率、节省金额或“多换了多少外币”的比较，因为没有记录它当年真实买入的成本。

初始持仓与后续买入混合使用时，分开显示两种来源的使用数量和成本。后续收益比较只考虑后续真实买入来源，不把初始部分混入其中；具体收益公式和后续买入的统计范围见[收益指标与报告细则](12_收益指标与报告细则_待确认.md)。

若全部使用都来自初始持仓，显示“本次使用全部来自初始持仓，不计算收益比较”，不能显示收益率0%。更正改变了资金来源分配时，数量和成本分类同步重算。

### 成本例子

初始1,000美元按7.20折算；后来另买1,000美元，成本7,400元；计划实际使用1,200美元。假设没有手续费或其他资金变动：

| 项目                   | 更正前：初始1,000美元 | 更正后：初始应为800美元 |
| ---------------------- | --------------------: | ----------------------: |
| 初始成本（人民币）     |                 7,200 |                   5,760 |
| 使用中的初始美元       |                 1,000 |                     800 |
| 使用中的后来买入美元   |                   200 |                     400 |
| 合计使用成本（人民币） |                 8,680 |                   8,720 |
| 账户剩余美元           |                   800 |                     600 |
| 剩余成本（人民币）     |                 5,920 |                   4,440 |

使用总额始终是1,200美元。更正只改变资金来源和成本；初始来源不计收益，后续买入来源单独列出。计划没有额外剩余分配时，以上更正可以进入确认流程；若另有分配，还要检查余额是否足够。
