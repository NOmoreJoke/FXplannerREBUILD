# 09 交易更正与日志

换汇记录填错后，可以更正。系统保留原记录和修改记录，不能直接覆盖或删除历史。

## 进入单笔记录与更正

在币种账户的交易记录台账中，点击对应行最右侧“操作”列的“查看详情”。买入记录打开该笔“换汇记录详情”，初始持仓打开该币种初始持仓详情。

“更正记录”保留在换汇记录详情内，始终操作当前所选记录；台账右上方的“录入换汇”用于新增记录。

换汇记录详情显示实际关联的计划名称，点击进入该计划；没有关联时显示“未关联”，不跳转默认计划。点击“返回账户”时保留进入详情前的来源币种。

## 可以修改什么

| 内容 | 规则 |
|---|---|
| 换入外币 | 可以修正，例如USD改为CAD；同时重新核对金额及账户影响 |
| 原记录的金额币种 | 本金、手续费和成本保留各自来源币种及记录采用的本位币；账号本位币变更不改写原金额或单位，也不自动折算。更正金额按原记录币种处理 |
| 换出本金 | 可以修改，不包含单列手续费 |
| 换入数量 | 可以修改 |
| 手续费 | 可以修改金额，以及“未知”或“已明确”的状态；未知与0不同 |
| 交易日期 | 可以修正实际发生日期；首次录入时间和修改时间保留原记录 |

## 怎样更正

1. 在当前“换汇记录详情”点击“更正记录”，填写新内容及原因；原因必填。
2. 先看前后差异，以及对余额、分配、计划和成本的影响。
3. 用户确认后，系统重新检查数据。
4. 成功才保存新记录；原版本及修改历史仍可查看。

仅打开修改页面、查看结果或取消，都不改变正式记录。手续费未知时，只要其他检查通过，仍可提交。

历史记录不随账号本位币变更折算，不代表禁止纠正误填。原交易仍按本节流程更正；后续新记录明确保存其发生时采用的本位币，不能用账号当前本位币覆盖历史字段。切换本位币时停止旧计划、另建接续计划的规则见[创建换汇计划](06_创建换汇计划.md)。原记录仍归原计划，不因更正迁移给接续计划。

## 哪些情况不能提交

- 改完后账户余额为负数。
- 改完后账户余额不足以覆盖仍分配给各计划的金额。
- 改日期后，过去某笔使用发生时，没有足够的同币种资金。

页面显示预计余额、受影响计划或使用记录，以及缺少的金额。已使用金额已从余额扣过，不能再重复当作当前分配扣除。系统不会自行减少计划分配或撤销真实使用。

## 修改币种

如果会影响已有计划分配，先到计划中调整或解除受影响的分配，再回来重新查看币种更正结果。不能自动把USD分配转成CAD分配，也不会按汇率自动换算原来填写的数量。解除分配后，仍需重新检查，符合条件才能提交。

已有使用记录的币种、金额和所属计划不变。账户曾经用过钱，不代表一律不能改币种，仍按余额和分配检查。

例如只有一笔买入1,000 USD，后来用了400，余额600；把买入改成CAD后，USD会变成−400，因此不能提交，原余额仍为600，使用400 USD的记录保留。

新币种没有账户时，先提示将新增账户，确认且更正成功后才创建。同一用户同一币种只保留一个账户，有则复用。原账户归零仍显示余额0，保留历史；以后再次买入继续用原账户，余额0时不计算单位平均成本。

## 修改日期与成本

成本按“先买的先计算使用成本”处理。修改日期可能改变买入先后顺序，因此要重算受影响的分配成本、使用成本和剩余外币成本。重算按各来源原币分别保留本金、手续费及成本；跨本位币变更的来源仍沿用原来的FIFO数量顺序，不把不同成本币合成单一成本或单一平均成本。

| 情况 | 影响 |
|---|---|
| 只分配、还没使用 | 重算分配对应的成本；分配数量、计划目标和账户数量不变 |
| 本金、数量、费用都不变，也没有使用 | 各成本币的已记录总成本及相应成本分项不因排序改变；只有单一成本币且资料完整时才计算单一平均成本 |
| 已有实际使用 | 按来源成本币重算使用及剩余外币成本；单一成本币的平均成本可能变化，多成本币分别列示 |

原使用的币种、数量、计划和日期不随交易日期更正而改变。提交前展示原日期、新日期、买入排序以及实际受影响的成本；只更新有关记录，费用未知的提示继续保留。

### 同一天怎样排序

- 普通买入先按交易日期由早到晚排列；同日按第一次录入的顺序排列。
- 修改日期后放回新的日期位置；如果落到同一天，仍用原来的首次录入顺序。
- 最近修改的记录不会因此排到最后；顺序必须固定，不能随机变化。
- 重算已有记录时，同一天先计初始持仓，再计普通买入，最后处理使用；多笔使用按首次录入顺序处理。

例如前一天余额0，当天买入1,000 USD、使用400，重算后余额600。这个顺序用于重算已有记录；首次录入使用时，仍要有足够资金，不能先透支。

### 过去的钱是否够用

例如9月1日买入1,000 USD，9月2日使用400；把买入日期改为9月3日后，虽然现在仍可算出600余额，但9月2日没有钱支持这笔使用，因此提示缺400，不能提交。

如果当时另有足够的同币种资金，则继续检查并重算成本，不能只凭一笔买入日期判断。不能用未来买入覆盖过去使用，也不自动补一笔初始余额或改动使用日期。

记录日期以UTC+8判断，不能早于当前账本起点；同日补录或改日期时需确认发生在起点之后且未包含在初始金额中。清空业务记录后，起点为清空完成时刻。

## 初始记录更正

初始金额有误，改为原确认时刻真实持有的金额，按原采用汇率重算，不用今天报价。可以改为0，但仍检查历史使用和现有分配；改币种或漏填币种需要同来源、原确认时点前不足5分钟的历史报价，没有就不能提交。不能修改初始日期或因账号本位币变更改写该初始记录的原成本币种。更正与受影响成本一起保存，失败不部分生效，详见[初始化与录入](02_初始化与录入闭环_待确认.md)。

## 怎样保存修改记录

保存修改原因、前后内容、涉及的账户与计划、实际金额及成本影响、操作人、时间和结果。页面可以查看原记录、新记录以及每次修改。

例如买入1,000 USD，本金7,800 HKD，手续费原为未知；补录20 HKD后，外币余额不变，已记录成本变为7,820 HKD。旧记录应写“费用未知”，不能写成“费用0”或“原完整成本7,800”。

正式提交后，如果系统确认失败，也保存尝试记录：关联交易、操作人、提交时间、拟修改内容、失败原因及“提交失败”。失败不产生有效新版本，也不改变余额、分配或报告。

输入检查、只查看修改结果、主动取消不属于失败提交。断网或超时造成结果不明时，不直接显示提交失败；核对及重试办法还需确定。

## 报告怎样更新

更正成功后，只重算受影响期间和指标；日期改变时检查原日期、新日期所在的两个期间。报告显示“已根据更正记录更新”、更新时间及相关修改记录。取消、失败或仅查看修改结果，不更新报告。

已导出的PDF及旧报告快照保持原内容；重新生成时使用更正后的相关记录，另存报告并标明依据的记录版本与生成时间，不折算历史成本。存在有效使用记录的计划可以下载，包括进行中、已完成、已取消及因本位币变更而停止的计划；后者即使零使用，也生成停止摘要。原计划记录不归入接续计划，目标汇总按有效记录去重。报告内容与生成重试见[成本摘要与报告](11_成本摘要与报告_待确认.md)。

## 待确定

- 资金冲突后的具体处理指引，以及交易与分配的对应细节。
- 已经使用过的资金补录或修改费用后，历史成本怎样逐笔调整。
- 补充分配记录与历史使用的具体对应顺序。
- 修改记录的展示字段、保留时间；是否设置单独的全局日志页。
- 超时后如何核对提交结果、怎样重试。
- 报告具体样式、收益计算及历史报告的保存期限和归档方式。

## 界面要求

| 界面 | 字段与内容 | 主要操作与返回 |
|---|---|---|
| 交易记录台账 | 沿用所选账户币种；每行绑定该笔实际记录，最右侧为“操作”列 | 点击该行“查看详情”进入对应记录，不能以默认记录替代 |
| 换汇记录详情 | 按实际记录显示日期、外币数量、本金、手续费及成本，各金额保留原币；显示实际关联的计划名称，无关联显示“未关联” | “更正记录”操作当前记录；计划名称进入实际关联计划；唯一返回按钮为“返回账户”，回到来源账户 |
| 更正换汇记录 | 保留当前记录身份，填写金额、日期及原因；金额字段明确原币种 | “查看影响”进入该笔更正核对；“取消”回同笔详情 |
| 确认换汇更正 | 显示原记录与更正后日期、金额、原币种、账户及成本影响；多成本币分别列示 | “确认更正”保存当前更正；“返回修改”回同笔编辑并保留输入 |
