# 14 业务逻辑清单

## 一、从首次使用到查看报告

### 1. 登录和首次设置

- 普通邮箱加验证码登录。支持香港、中国大陆，简体中文和英文；共15种币种，见[功能清单](<13_MVP功能清单.md>)。
- 首次配置由用户选择本位币；之后可在设置修改。新交易估算与新计划使用最新本位币，历史金额、费用和成本保留各来源原币，不因设置变化折算。
- 登录／注册页确认年龄和必要条款；首次配置选择地区和本位币，填写已有外币、设置站内提醒，最后核对。首次不选择语言、风险偏好；默认简体中文和均衡节奏，计划内仍可选节奏。
- 已有外币按币种填写总金额，每个币种只填一行。没有外币可跳过。
- 系统查询当前汇率，显示来源和时间。按“1单位外币等于多少本位币”计算：初始成本＝已有外币金额×汇率。
- 汇率过期时刷新并重新确认。查询失败时保留草稿，重试后再提交，不能用0或手填汇率代替。
- 最后确认时，各币种的初始记录一起保存；失败时全部不保存，重试不会重复增加余额。
- 初始外币先放在未分配余额中，以确认日记账；之后行情变化不会改变这笔初始成本。
- 初始录入编辑页每60秒刷新，来源报价时间距当前不足5分钟可用，核对页固定本次数据。汇率取8位，金额按币种最小单位只在最终结果舍入一次。同日先初始持仓、再普通买入、后实际使用；只补记账起点之后的记录，避免重复。初始更正沿用原时点报价并重算受影响余额、成本，详见[初始化与录入](02_初始化与录入闭环_待确认.md)。

### 2. 记录买入外币

- 首页“快速录入”打开直接买入表单，单笔A→B，不提供中间币或多段路径；新记录采用当前默认本金币种，历史记录保留原交易对。切换B使旧报价和自动计算值失效并要求重新核对。
- 填本金和汇率，自动算出取得的外币金额；也可填本金和实际取得金额，反算汇率。
- 手续费以该笔采用的本金币种单独填写并保存币种，不随账号本位币改变标签，不混入兑换本金。填0代表没有手续费；留空代表暂不知道，可以先保存。
- 系统显示的当前汇率供填写参考；历史买入记录应填写实际成交数据。
- 可以关联计划，也可以不关联。关联计划不代表已经分配资金。
- 每个币种只有一个账户。首次保存初始外币或买入记录时自动建立，余额为0时仍保留。
- 这里记录的是账本，买入、转账和退款仍由用户在银行等渠道办理。

### 3. 分配资金给计划

| 名称 | 计算方式 |
|---|---|
| 还需使用金额 | 目标总额减去该目标全部历史计划及当前计划的有效累计使用，最低为0 |
| 计划剩余分配 | 已分给这个计划、尚未使用或退回的金额 |
| 未分配余额 | 账户余额减去该币种所有计划的剩余分配 |
| 还需准备金额 | 还需使用金额减去计划剩余分配，最低为0 |
| 最多可新增分配 | 未分配余额与还需准备金额，取较小值 |
| 修改分配总额的上限 | 还需使用金额与“未分配余额＋这个计划原有分配”，取较小值 |

例如：账户有600，全部已分给计划，计划还需使用1,000。虽然计划还差400，也不能再分配，因为没有未分配余额。

- 创建计划或在计划详情中分配资金；账户页展示分配结果。
- 草稿和预览不占用资金，确认时重新检查；同一笔余额不能重复分给多个计划。
- 分配不会扣减账户余额，也不会产生使用成本。
- 未分配余额不会自动填补计划缺口。
- 计划还需使用金额大于0，且剩余分配足够，才显示“资金已备齐”。已经全部用完时显示“资金已使用完成”。

### 4. 分批准备和提醒

- 预计使用日期与最晚准备日期分开。默认从使用日前一天向前数3个工作日，也可在创建和预览时调整天数；工作日采用哪个地区的日历，待确定。
- 默认分3次，安排在可用日期的第一天、中间一天、最后一天；中间有两个候选日期时选较早一天。

| 风格 | 分3次 | 只剩2天时 |
|---|---|---|
| 安心 | 50%、30%、20% | 60%、40% |
| 均衡 | 三等分 | 50%、50% |
| 主动 | 20%、30%、50% | 40%、60% |

- 只剩2天时，确认后缩为2次；只剩1天时一次准备100%；没有可用日期时不能生成安排。
- 前几次按币种最小金额单位向下取整，差额留到最后一次。出现0金额的安排时不能生成。
- 不支持逐次修改日期、金额、次数，也不提供每周或每月模式。风格不会自动改变提前天数。
- 金额或日期变化后，先预览新安排，再确认替换；保留旧安排。
- 仅提供站内提醒。同一计划同一天合并提醒，不每天重复催办逾期事项。
- 资金备齐后停止准备提醒，预计使用日仍可提醒核对用途。
- 已停止、已完成或已取消计划不再提醒；重新开启时按当前状态提醒，不补发过去的提醒。
- 关闭提醒后，页面仍显示计划状态。

### 5. 记录使用、调整目标和结束计划

- 记录已经实际发生的计划用款，可分次填写。确认后扣减账户余额和计划剩余分配，增加累计已使用金额。
- 使用达到目标、剩余分配为0后，由用户确认完成计划，不自动完成。
- 调整目标先看预览。新目标不能低于已使用金额。
- 调低目标后，多出的分配随本次修改一起退回未分配余额，账户总余额不变。
- 已完成计划提高目标，仅在目标有效累计使用等于原目标、剩余分配为0且不存在其他进行中计划时开放“重新开启”；条件不满足不展示可点击入口。旧计划本位币与当前不同时，走新本位币规划，不直接更换旧计划币种。
- 取消计划只退回尚未使用的分配，保留买入和使用记录，不恢复已经使用的金额。
- 已完成计划中，将误填过大的使用金额调小时，差额回到未分配余额，计划仍已完成，不催促补齐差额。
- 修改日期适用于哪些状态，以及其他已完成或已取消计划的更正方式，待确定。

### 6. 更正记录和重算成本

- 更正先填原因、查看影响，再确认保存。失败时不保存任何一部分修改。
- 买入记录可以更正换入币种；原本金币种和手续费币种不能因账号本位币修改而改写，历史误填仍按相应更正规则处理。若影响现有分配，先到计划中调整分配；不会自动迁移使用记录。
- 普通买入按买入日期先后计算使用成本；同一天按首次录入顺序。更正记录不改变首次录入顺序。同日初始外币先于普通买入；记录日期按UTC+8判断，不补记账起点之前的记录。
- 重算同一天的历史记录时，先计入取得的外币，再计算使用。不能拿后来买入的资金填补以前的用款缺口。
- 更正使用金额：调小的差额退回未分配余额，不自动恢复原计划分配；调大时先用原分配，不足部分从未分配余额补入计划并立即使用。只扣增加的金额，不重复扣整笔。
- 更正使用日期时，检查当时资金是否足够，并重算成本。
- 不单独提供撤销使用功能；使用金额能否改为0，待确定。
- 保留更正前后记录。买入更正正式提交失败时，保留失败记录；提交结果不明确时怎样处理，待确定。

### 7. 成本和报告

- 可查看计划已经使用的成本、账户剩余外币的成本，以及报告中心。
- 有有效使用记录的计划可下载使用成本报告；本位币变更停止旧计划时另自动生成停止报告，零使用也生成且使用均价不适用。已停止历史计划和当前计划分别归属报告，不重复统计。
- 更正成功后更新相关摘要和新下载的报告，显示更新时间，可查看更正记录；已经下载的PDF不变。
- 收益率和成本节省，都与“在最晚安全时间一次性换汇”的结果比较。
- 例如用美元换人民币，在花相同美元的情况下，比较多换了多少人民币。
- 初始外币参与账户和使用成本，不参与收益率或节省比较，混合使用分来源显示。具体公式、费用计算、报告内容和版式后续补充。

### 8. 本位币切换与目标交接

- 同一目标同一时间最多一个进行中计划，旧停止计划保留独立身份、原规划币、历史版本及报告。一般金额／日期／节奏调整使用同计划版本；本位币切换创建新计划身份。
- 本位币切换先列所涉进行中旧计划、释放分配与后继计划。确认时重新校验目标全历史累计使用及余额、新方案；旧计划停止、剩余分配释放、报告依据、新本位币和后继计划一次保存，失败或取消不部分生效。
- 新计划需求＝目标总额−目标历史累计使用；新计划本次使用从0记，旧使用只在原计划保留，在目标层汇总一次。已有未使用外币回未分配余额，不自动进入新计划。
- 停止报告按停止时依据生成。文件生成失败可重试原报告任务，不重复停计划或新建计划；不能在文件未就绪时显示已可下载。
- 仍有剩余需求、需要后继计划时，若新本位币等于目标币或新安排不能生成，预览说明并阻止本次确认，可改选本位币或取消；原设置和计划不先改变。累计已用恰好等于目标且剩余分配为0时，只停止所涉旧进行中计划并生成停止报告，不新建零额计划。状态处理见[创建换汇计划](06_创建换汇计划.md)。
- 历史使用更正不迁移计划归属；目标累计使用和仍进行中的后继计划剩余需求一起更新，实际分配不自动增加。后继已完成、取消或停止时仅显示目标差额，不恢复计划或提醒。已停止记录只按[使用记录更正](10_资金使用记录更正.md)允许的范围处理，目标超额等校验失败时不修改任何正式数据。
- 同一目标币可有多个成本来源币。FIFO按外币数量消耗，每份来源成本保留原币；不能直接汇总成单币总成本或平均成本。历史金额不重估不等于禁止正常使用摊销或误填更正。

### 9. 账号和待确定功能

支持退出、导出、清空业务记录和注销。导出7个自然日内提供、下载期限24小时；清空业务记录7个自然日内处理，本位币不变；注销有7个自然日撤回期，提交后30个自然日内清理在线数据。请求冲突、异常和备份处理见[首次使用与设置](01_首次使用与设置_待确认.md)。设备管理页面后续再做。

个人能否另设更早的准备截止日，以及是否需要汇总全部操作记录的页面，待确定。

## 二、15个计算例子

- 各例独立，除特别说明外，没有其他计划、记录或资金变化；买入和使用均发生在各自账本起点之后。
- 金额默认以美元计；涉及港币成本时另行注明。
- 所有“修改后”结果都指用户确认并成功保存之后。仅输入、预览、取消或失败，不改变原数据。
- 使用记录都属于某个计划；计划剩余分配为0，不代表该笔使用没有所属计划。

### 例01：计划内使用4,000，仍然备齐

已分配10,000，记录该计划实际使用4,000。

| 指标 | 使用前 | 确认使用后 |
|---|---:|---:|
| 目标金额 | 10,000 | 10,000 |
| 累计已使用金额 | 0 | 4,000 |
| 还需使用金额 | 10,000 | 6,000 |
| 计划剩余分配 | 10,000 | 6,000 |
| 账户余额 | 10,000 | 6,000 |
| 未分配余额 | 0 | 0 |
| 资金缺口 | 0 | 0 |

状态：仍资金已备齐，使用尚未达到目标。确认内容为本次已发生的计划内使用4,000；记录使用、对应分配减少及余额变化，不自动完成计划。

### 例02：已使用4,000误录，实际只有400

仅更正使用金额，日期及计划归属不变。

| 指标 | 更正前 | 更正后 |
|---|---:|---:|
| 目标金额 | 10,000 | 10,000 |
| 累计已使用金额 | 4,000 | 400 |
| 还需使用金额 | 6,000 | 9,600 |
| 计划剩余分配 | 6,000 | 6,000 |
| 账户余额 | 6,000 | 9,600 |
| 未分配余额 | 0 | 3,600 |
| 资金缺口 | 0 | 3,600 |

状态：备齐→尚未备齐。确认界面说明账本余额回增3,600，全部进入未分配；不自动恢复原计划分配。保留原使用版本、纠错原因、前后值与成本影响；没有分配变动就不写“恢复分配”事件。账面纠错不代表银行退款。

### 例03：使用4,000改为5,000，原分配足够

原计划仍允许处理本次纠错，使用日期、币种、计划不变。

| 指标 | 更正前 | 更正后 |
|---|---:|---:|
| 目标金额 | 10,000 | 10,000 |
| 累计已使用金额 | 4,000 | 5,000 |
| 还需使用金额 | 6,000 | 5,000 |
| 计划剩余分配 | 6,000 | 5,000 |
| 账户余额 | 6,000 | 5,000 |
| 未分配余额 | 0 | 0 |

确认界面：本次增加使用1,000，来源为原计划分配。确认后同步扣减，不要求用户先手动把分配改为5,000；仍为资金已备齐。使用来源明细关联原分配及本次更正，不能再次扣除整笔5,000。

### 例04：原计划分配为0，使用增加1,000

原使用仍关联该计划，当前有未分配6,000。

| 指标 | 更正前 | 更正后 |
|---|---:|---:|
| 目标金额 | 10,000 | 10,000 |
| 累计已使用金额 | 4,000 | 5,000 |
| 还需使用金额 | 6,000 | 5,000 |
| 计划剩余分配 | 0 | 0 |
| 账户余额 | 6,000 | 5,000 |
| 未分配余额 | 6,000 | 5,000 |
| 资金缺口 | 6,000 | 5,000 |

确认界面明确：“从未分配余额补充分配1,000给原计划，并立即用于本次使用更正”。补分配使计划剩余分配暂增1,000、未分配余额减少1,000，但不扣账户余额；对应使用再使计划剩余分配减少1,000、账户余额减少1,000。两步整体生效，最终计划剩余分配仍0。

保留补充分配和对应使用的记录，并标明它们属于同一次更正。不能只留下余额减少的结果。

### 例05：增加1,000，原分配只有600

目标10,000、累计已使用金额=4,000；原分配600，未分配2,000，账户余额=2,600。

| 处理 | 计划剩余分配 | 未分配余额 | 账户余额 |
|---|---:|---:|---:|
| 更正前 | 600 | 2,000 | 2,600 |
| 补充分配400（同次更正内部步骤） | 1,000 | 1,600 | 2,600 |
| 使用原分配600（内部步骤） | 400 | 1,600 | 2,000 |
| 使用补分配400，确认后 | 0 | 1,600 | 1,600 |

最终累计已使用金额=5,000、还需使用金额=5,000、资金缺口5,000，仍尚未备齐。确认界面同时展示原分配600和补充分配400两种来源，用户一次确认。

记录本次使用分别来自原分配600和新补分配400，保留补分配400及对应使用的明细，并标明属于同一次更正。上面的各步一起保存，不能只保存其中一步；共增加使用1,000，不再按汇总额重复扣一次。

补充分配的系统操作时间为本次更正时间；原使用日期不倒改为当天，也不把本次补分配倒签成过去的实际操作。这类更正怎样影响历史记录，待确定。

### 例06：目标从10,000提高到12,000

进行中计划；账户另有未分配2,000，足够填缺口也不自动占用。

| 指标 | 修改前 | 修改后 |
|---|---:|---:|
| 目标金额 | 10,000 | 12,000 |
| 累计已使用金额 | 4,000 | 4,000 |
| 还需使用金额 | 6,000 | 8,000 |
| 计划剩余分配 | 6,000 | 6,000 |
| 账户余额 | 8,000 | 8,000 |
| 未分配余额 | 2,000 | 2,000 |
| 资金缺口 | 0 | 2,000 |

状态：备齐→尚未备齐。用户先预览新目标和缺口，再确认修改；保留初始目标及修改历史。若要补齐，另经计划分配流程确认分配2,000，不能在修改目标时自动分配。

### 例07：目标从10,000降低到8,000

此案例与例06独立，均从修改前状态开始。

| 指标 | 修改前 | 修改后 |
|---|---:|---:|
| 目标金额 | 10,000 | 8,000 |
| 累计已使用金额 | 4,000 | 4,000 |
| 还需使用金额 | 6,000 | 4,000 |
| 计划剩余分配 | 6,000 | 4,000 |
| 账户余额 | 8,000 | 8,000 |
| 未分配余额 | 2,000 | 4,000 |
| 资金缺口 | 0 | 0 |

确认界面明确：“将目标改为8,000，同时释放超额分配2,000”。用户确认后两者一起生效，仍资金已备齐；不先保存超额状态，也不在取消后释放资金。

保留原目标、新目标和退回分配的记录，并标明属于同一次修改。退回分配不减少账户总数量，不改变已有使用，也不是退款。

### 例08：已使用4,000，目标拟改为3,000

原目标金额=10,000、累计已使用金额=4,000、还需使用金额=6,000、计划剩余分配=6,000、账户余额=8,000、未分配余额=2,000。

提示：“新目标不能低于已使用的4,000 USD。”禁止提交；上述所有数值保持原值，不因目标减去已使用金额变成0就接受修改或释放分配。

若使用本身误录，应另走使用纠错流程；不能在修改目标时抹除已使用事实。此次不生成成功目标修改或分配释放记录。

### 例09：剩余需求10,000，已分配6,000，又输入5,000

当前目标金额=10,000、累计已使用金额=0、还需使用金额=10,000、计划剩余分配=6,000、账户余额=12,000、未分配余额=6,000。

新增分配上限=4,000（计划还差4,000，账户有6,000可分配）。输入5,000时提示超出1,000，禁止提交；原计划剩余分配=6,000、未分配余额=6,000、账户余额=12,000不变，不自动将输入截成4,000。

若用户主动改为4,000并成功确认，则计划剩余分配=10,000、未分配余额=2,000、账户余额=12,000，资金已备齐。账户总额可超过计划需求，超出的余额仍未分配。

编辑分配总额时直接比较拟新计划剩余分配与还需使用金额，不再额外加一次旧计划剩余分配。提交被拦截时，不生成成功分配记录。

### 例10：交易日期更正改变先买先用的成本计算顺序

假设费用已明确且已包含在下表成本中；只有两笔买入与一笔计划内使用，计划仍进行中。使用日期为9月4日，使用1,200 USD。

| 取得批次 | 数量USD | 已记录成本HKD | 原日期 → 更正日期 |
|---|---:|---:|---|
| 第一笔买入 | 1,000 | 7,800 | 9月1日 → 9月3日 |
| 第二笔买入 | 1,000 | 8,000 | 9月2日 → 不变 |

| 指标 | 更正前：第一笔先用 | 更正后：第二笔先用 |
|---|---:|---:|
| 使用数量USD | 1,200 | 1,200 |
| 使用成本HKD | 7,800＋200×8＝9,400 | 8,000＋200×7.8＝9,560 |
| 剩余数量USD | 800 | 800 |
| 剩余成本HKD | 6,400 | 6,240 |
| 剩余单位成本HKD/USD | 8 | 7.8 |
| 已使用成本＋剩余成本HKD | 15,800 | 15,800 |

确认预览：先买先用的成本计算先后变化，使用成本增加160 HKD、剩余成本减少160 HKD；使用数量及日期不变。保留日期前后值、批次成本归属与差异，不产生额外银行收支。

### 例11：更正引起当前或历史资金不足

各子例独立，均无期初余额及其他入账。

| 子例 | 准备修改 | 不能修改的原因 | 正式结果 |
|---|---|---|---|
| 原入账1,000 USD，已用400、剩600，当前无剩余有效计划分配 | 入账币种改CAD | USD预览余额−400 | 原入账/使用不变，USD仍600 |
| 9月1日买1,000，9月2日用400 | 买入日期改9月3日 | 9月2日缺400，当前仍可算600也不能通过 | 原日期、余额及分配不变 |
| 9月3日买1,000，9月4日用400 | 使用日期改9月2日 | 9月2日缺400 | 原日期、余额及分配不变 |

提示明确对应日期、使用记录与缺口；不借未来资金、不自动补期初、不替用户修改其他记录。若币种更正仍影响有效分配，须先到计划中调整相关分配，再进行该次更正的余额校验；上表第一个子例已限定无剩余有效分配。若在对应使用时点确有其他可用来源，应按完整记录校验，不依据单一买入日期一律阻止。

### 例12：手续费从未知补录为20 HKD

买入1,000 USD，本金7,800 HKD，无计划分配或使用。

| 项目 | 更正前 | 更正后 |
|---|---|---|
| 手续费 | 未知 | 明确20 HKD |
| 已记录成本 | 7,800 HKD，费用未完整 | 7,820 HKD，单列费用已明确 |
| 该笔记录单位成本 | 按已录金额7.8 HKD/USD，费用未完整 | 7.82 HKD/USD |
| 外币数量 | 1,000 USD | 1,000 USD |

确认预览及日志写“未知→20”，不写“0→20”。若汇总仍含其他费用未知的交易，报告/加权成本的费用说明继续保留；不能只补一笔费用就声明所有成本完整。

### 例13：使用达到目标后确认计划完成

目标金额=10,000、累计已使用金额=10,000、还需使用金额=0、计划剩余分配=0，无其他资金则账户余额=未分配余额=0。

| 阶段 | 展示与操作 |
|---|---|
| 使用达标 | 资金已使用完成，不再显示资金已备齐；计划尚未由用户确认完成 |
| 用户确认计划完成 | 计划变为已完成，不再次扣款，保留全部交易/分配/使用/更正历史 |

调低目标造成的超额分配在目标修改时按例07处理。完成后提高目标重开按例14；已完成、已取消计划的其他更正方式，待确定。

### 例14：已完成计划提高目标并重新开启

正常已完成计划目标金额=累计已使用金额=10,000、计划剩余分配=0，无其他资金时账户余额=未分配余额=0；拟提高目标至12,000。

| 指标 | 修改前 | 确认后 |
|---|---:|---:|
| 目标金额 | 10,000 | 12,000 |
| 累计已使用金额 | 10,000 | 10,000 |
| 还需使用金额／资金缺口 | 0 | 2,000 |
| 计划剩余分配 | 0 | 0 |
| 账户余额／未分配余额 | 0 | 0 |
| 计划状态 | 已完成 | 进行中 |
| 当前资金状态 | 资金已使用完成 | 尚未备齐 |

一次确认“重新开启并修改目标”，校验后整体生效；不自动分配、不增加使用，既有使用成本不变。保留原目标、使用及完成历史，新增关联的重新开启和目标修改记录。取消/失败不改正式数据，提交依据变化须刷新预览并重新确认。已取消计划能否重新开启，待确定。

### 例15：使用金额更正，计划仍已完成

正常已完成计划目标和累计使用均10,000 USD，账户余额、未分配余额及剩余分配均0。其中一笔误录4,000，实际应为3,600。

| 指标 | 更正前 | 确认更正后 |
|---|---:|---:|
| 目标金额 | 10,000 | 10,000 |
| 累计已使用金额 | 10,000 | 9,600 |
| 账户余额 | 0 | 400 |
| 未分配余额 | 0 | 400 |
| 计划剩余分配 | 0 | 0 |
| 计划状态 | 已完成 | 已完成 |

原因必填，预览后经用户确认及校验生效；重算受影响成本，保留原使用版本、更正原因及日志、原完成历史。差额400为账面纠错回增，非银行退款，不恢复分配、不调整目标、不要求重新开启，也不新增重开记录。取消/失败不改变正式数据。

目标金额-累计已使用金额的数值差额由0变400，不据此撤销完成状态。页面展示目标、有效使用、差额及账户未分配余额；差额不标待补，不触发补齐提醒。

## 三、本位币变更交接例子

目标10000 USD，旧计划累计使用4000 USD、剩余分配3000 USD，默认本位币从CNY改HKD。

| 项目 | 确认前 | 确认后 |
|---|---|---|
| 目标总额与历史使用 | 10000 USD；4000 USD | 原样保留；旧使用仍属旧计划 |
| 旧计划 | 进行中 | 已停止，停止报告按来源原币 |
| 旧计划剩余分配 | 3000 USD | 0；3000 USD回未分配，账户总余额不变 |
| 后继计划 | 无 | 独立计划，HKD规划，待完成6000 USD，初始分配0 |
| 之后确认分配3000 USD | 尚未发生 | 后继计划仍需准备3000 USD，不是重新买入6000 USD |

历史一批1000 USD成本7200 CNY，另一批1000 USD成本7800 HKD；按FIFO使用1200 USD时，成本分别为7200 CNY与1560 HKD，不能写成8760“总成本”。剩余800 USD来源成本6240 HKD。原交易事实及成本币种不因当前本位币变化而重写。
