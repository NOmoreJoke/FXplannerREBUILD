# 06 创建换汇计划

## 填写内容

| 内容 | 填写方式 |
|---|---|
| 目标币种 | 选择需要准备的外币；生成换汇计划时必须与该计划本位币不同 |
| 目标金额 | 填写最终需要准备的外币总额，不是本次买入金额 |
| 预计使用日期 | 填写预计何时需要用钱 |
| 最晚准备日期 | 系统根据预计使用日期，往前扣除准备所需的工作日 |
| 提前准备天数 | 默认3个工作日；创建计划时可以调整，先看重算结果再确认 |
| 开始准备日期、准备节奏 | 见[分批准备计划](07_分批准备计划.md) |
| 计入已有外币 | 自己选择从账户余额中分配多少给本计划，可以填0 |

新计划采用创建时用户设置的本位币，不在计划表单中重复选择。用户首次选择本位币，后续可以在设置中变更；每个计划保留自己采用的本位币，历史记录不随设置重估。变更处理见下文。地区、语言及币种见[功能清单](13_MVP功能清单.md)。

每笔换汇及其计划只支持本位币 A → 目标币 B；不生成 A → B → C 的跨币种路径。

例如最终需要10,000 USD，选择计入已有3,000 USD，剩余需要准备7,000 USD。选择计入0，不改变账户原有余额。

## 目标与计划的关系

目标可以单独创建并保存，之后再制定计划；保留“新建目标”和“新建计划”各自入口。目标记录最终需要的目标币种总额，同一目标同时最多有一个进行中计划。

| 内容 | 规则 |
|---|---|
| 目标累计使用 | 汇总该目标全部历史计划的有效实际使用，包含已停止、已完成、已取消计划；每笔只计算一次 |
| 目标剩余需求 | 目标总额−目标累计使用，最低为0；不能仅扣当前计划使用 |
| 计划身份 | 每个计划具有独立编号和本位币；已停止计划保留历史，后继计划使用新编号 |
| 常规调整 | 在同一计划内修改目标或准备安排，确认后迭代版本，保留原计划编号 |
| 本位币变化 | 停止受影响旧计划，以新本位币创建独立后继计划；不作为旧计划的版本更新 |
| 记录归属 | 原交易、分配及使用记录保留原计划归属，不迁移或复制到后继计划 |

后继计划建立时，展示目标总额、全部历史实际使用、本计划承接金额。本计划承接金额＝目标总额−建立时该目标全部历史实际使用；之后新使用继续累计到同一目标。

例如目标10,000 USD，旧计划已实际使用4,000 USD；更换本位币后，新计划承接6,000 USD，不能再按10,000 USD准备。新计划再使用2,000 USD后，目标累计使用为6,000 USD，目标剩余需求为4,000 USD。目标总额仍为10,000 USD，旧4,000 USD记录仍在旧计划中。

## 已有外币怎样分配

分配是告诉系统“这部分外币留给哪个计划”，不会减少账户总余额。

1. 填写计划并选择分配金额。
2. 先看计划和金额计算结果；草稿和确认前都不占用余额。
3. 点击确认时，重新检查余额，检查通过才保存计划和分配。
4. 同一笔金额不能重复分给多个计划。

例如账户有3,000 USD，给计划A分配1,000 USD后，只剩2,000 USD可分给其他计划。

| 金额 | 算法 |
|---|---|
| 计划还需要使用多少 | 目标总额−该目标全部历史计划累计实际使用，最低为0 |
| 计划还缺多少 | 还需要使用的金额−计划剩余分配，最低为0 |
| 账户可分配余额 | 账户余额−所有计划的剩余分配 |
| 本次最多新增分配 | 取“账户可分配余额”和“计划还缺多少”中较小的金额 |
| 修改分配总额时的上限 | 取“计划还需要使用多少”和“账户可分配余额＋该计划原剩余分配”中较小的金额 |

例如计划还需10,000 USD，已经分配6,000 USD，即使账户余额充足，也最多再分配4,000 USD。输入5,000 USD时提示超出1,000 USD，不能提交。系统不自行把输入金额改小。

新增分配与修改分配总额是两种计算方式，不能把原有分配再当作可新增的金额。

## 修改目标金额

修改前先显示对计划进度、分配和缺口的影响，用户确认后保存。保留原目标及每次修改记录。

下表中的“已经使用”均指该目标全部历史计划的累计实际使用；不能因停止旧计划或创建后继计划而清零。

| 情况 | 处理 | 例子（USD） |
|---|---|---|
| 新目标低于已经使用的金额 | 不能提交，提示已使用金额和差额 | 已用4,000，目标不能改成3,000 |
| 调低目标后，原分配超过剩余需求 | 显示需释放金额，确认后同时修改目标并释放 | 目标10,000、已用4,000、分配6,000；目标改8,000后，分配改为4,000，释放2,000 |
| 进行中计划调高目标 | 保持现有分配，增加部分显示为缺口 | 目标10,000改12,000、已用4,000、分配6,000；缺口由0变2,000 |

释放分配只增加账户可分配余额，不改变账户总余额和真实使用记录。目标修改和释放必须全部成功才保存；取消或失败则不改原数据。

提高目标后，即使账户还有足够余额，也由用户另行选择分配，不自动补齐。

仅修改名称或其他目标信息时，成功页显示“目标已更新”，回到同一目标及其当前计划；不显示与实际动作不符的“新计划已创建”。核对页返回修改时保留目标、计划编号和输入内容；每页返回来源的按钮只有一个，名称、位置和返回对象保持一致。

## 本位币变更时停止旧计划并创建后继计划

1. 在设置中选择新本位币，先展示变更预览，不立即修改设置或停止计划。
2. 预览逐项列出**本位币等于当前旧本位币、且状态为进行中**的受影响计划。每项显示目标、旧计划编号及本位币、目标总额、全部历史实际使用、剩余需求、将释放的分配、新本位币及后继计划安排。
3. 对每项核对剩余需求和原分配；仍有剩余需求的项，再检查新本位币与目标币是否不同、可生成的准备日期与金额。已停止、已完成、已取消计划不纳入本次批量处理；其他本位币的历史计划也不修改。
4. 用户确认且全部检查通过后，原子保存新本位币、受影响旧计划的停止状态、旧计划剩余分配的释放、截至停止时的报告依据／快照及生成任务，并为需要继续准备的目标建立新编号的后继计划。各目标只保留一个进行中计划。报告 PDF 随后生成；生成失败按报告任务重试，不撤销已完成的停旧建新，详见[成本摘要与报告](<11_成本摘要与报告_待确认.md#报告生成与重试>)。
5. 后继计划不自动分配账户余额或旧计划释放的资金。用户进入后继计划，另行查看分配影响并确认；未分配前按完整剩余需求显示准备缺口。

| 变更预览结果 | 确认处理 | 不改变的内容 |
|---|---|---|
| 剩余需求大于0，A≠B，新安排可生成 | 停止旧计划并创建新本位币后继计划 | 目标总额、账户余额、历史使用及来源成本币 |
| 累计实际使用恰好等于目标、剩余分配为0 | 明确显示无需新建计划；受影响旧进行中计划停止，不新建零额计划，也不自动标记已完成 | 实际使用、账户余额和历史记录 |
| 剩余需求大于0，A=B | 阻止本次确认，提示改选本位币或取消；不显示创建成功 | 当前设置、旧计划状态、分配和账户余额 |
| 新方案无法生成、任一金额或状态检查失败 | 阻止整次变更，返回对应内容修正后重新预览 | 当前设置、全部旧计划、分配和账户余额 |
| 确认时依据已变化 | 更新预览，由用户再次确认 | 再次确认前不改正式数据 |
| 重复提交同一次变更 | 返回同一次处理结果，不重复停止、释放或创建计划 | 后继计划数量和有效记录不增加 |

“无需新建计划”仅适用于累计实际使用恰好等于目标且剩余分配为0。累计使用超出目标、零需求但仍有剩余分配等情况不能按成功处理，须先核对原记录与分配。若任一仍有剩余需求的受影响目标存在 A=B 或不可生成方案的情况，整次变更不得部分生效。

停止旧计划不改账户余额，不恢复已经使用的金额，不重估历史金额和成本，也不把旧记录改挂新计划。旧计划的提醒停止，旧报告停止持续更新，并自动生成截至停止时的报告；即使尚无使用记录也生成停止报告。报告按来源成本币展示，未来使用旧持仓仍按原来源成本币计成本。详见[成本摘要与报告](<11_成本摘要与报告_待确认.md>)。

成功后逐项显示已停止的旧计划与新建的后继计划；无需新建的目标明确显示处理结果，不生成空计划入口。预览中的取消或返回修正均不改变正式数据。

## 完成、取消和重新开启

**完成计划：**该目标全部历史计划的累计实际使用等于目标金额、当前计划剩余分配为0时，显示“资金已使用完成”，提示用户确认当前计划完成。用户确认后才变为“已完成”，不会再扣一次钱，全部记录保留。

**取消计划：**释放该计划尚未使用的分配，账户余额和换汇记录保留。已经使用的金额不会恢复；其他计划的分配不变。释放的余额由用户之后重新分配。

**已完成计划增加目标：**该目标累计实际使用等于原目标、该计划剩余分配为0、目标下没有其他进行中计划，且计划本位币仍与当前设置一致时，可以提高目标并重新开启原计划。先展示变化，再由用户确认；保持原计划编号并迭代版本。本位币不一致时不开放原计划重开入口，不能通过重开改写历史本位币。

| 内容 | 原来 | 重新开启后 |
|---|---:|---:|
| 目标金额 | 10,000 USD | 12,000 USD |
| 目标累计实际使用 | 10,000 USD | 10,000 USD |
| 还需要使用 | 0 | 2,000 USD |
| 剩余分配 | 0 | 0 |
| 资金缺口 | 0 | 2,000 USD |
| 计划状态 | 已完成 | 进行中 |

重新开启与目标修改必须全部成功才保存。账户余额、旧使用记录及成本不变，不自动补分配；保留原完成记录和本次修改记录。提交时如果数据已经变化，重新显示结果，让用户再次确认。

**已完成计划纠正误录金额：**原本正常完成的计划，把误录的使用金额调小后，仍保持“已完成”。差额回到账户可分配余额，目标和剩余分配不变，不提示补齐。

例如目标和已用均为10,000 USD、账户余额及分配均为0；其中一笔4,000改为3,600后，已用变为9,600，账户可分配余额增加400，计划仍已完成。页面展示目标、实际已用、差额和账户可分配余额。详见[资金使用记录更正](10_资金使用记录更正.md)。

此时累计实际使用已不等于原目标，不满足重新开启条件，页面不开放“提高目标并重新开启”按钮；不能保留一个点击后只能报错的入口。已停止计划保持历史状态，不通过提高目标重新开启。

| 当前状态 | 允许的核心操作 | 后续状态 |
|---|---|---|
| 目标尚无计划 | 保存目标、制定计划 | 无计划或进行中 |
| 进行中 | 记录使用、分配、常规调整版本、确认完成、取消 | 进行中、已完成或已取消 |
| 进行中且受本位币变更影响 | 预览并确认停旧建新 | 旧计划已停止；符合条件时建立新进行中计划 |
| 已停止 | 查看历史、停止报告及后继计划（如有） | 保持已停止 |
| 已完成且满足重开全部条件 | 提高目标并重新开启同本位币原计划 | 进行中，沿用编号并迭代版本 |
| 已完成且使用更正后不满足重开条件 | 查看更正后的金额、成本和差额 | 保持已完成，不开放重开按钮 |
| 已取消 | 查看保留的目标、计划及历史记录 | 保持已取消；其他编辑权限仍待确定 |

## 日期怎样计算

已有计划支持修改日期；哪些日期可以修改、计划在什么状态下可改，以及怎样影响旧安排，待确定。

预计使用日期是预计需要用钱的日期；最晚准备日期是应当把钱备齐的日期。两者都不会自动生成实际使用记录。

从预计使用日期的前一天开始向前数，跳过非工作日，默认扣除3个工作日。创建时调整天数后，显示新的日期和计算依据，再确认保存。

例如预计2026年11月23日（周一）使用，假设只跳过周末：向前数11月20日、19日、18日，最晚应在11月18日备齐。这是示例，实际采用的节假日日历还需确定。

3个工作日是提前准备的默认天数，不是银行到账时效。提醒见[提醒与到期处理](08_提醒与到期处理.md)。

## 待确定

- 名称、页面顺序、草稿保留多久，以及具体输入方式。
- 目标金额允许的范围、保留几位小数。
- 采用哪个工作日日历、时区；提前天数的可选范围和是否允许0天。
- 是否允许直接选择最晚准备日期、增加个人更早的截止日期。
- 已有计划修改日期的具体字段、适用状态，以及对旧安排和报告比较日期的影响。
- 已取消计划如何编辑；已完成计划调低目标、金额调大或日期更正怎样处理。
- 超额使用、完成时仍有剩余分配等异常情况如何处理。
- 使用更正中的“补充分配并立即使用”，怎样在同一次操作中检查目标上限。

| 界面 | 字段与内容 | 主要操作与返回 |
|---|---|---|
| 我的目标 / 换汇计划 | 目标金额与日期、计划状态；同目标当前计划与历史计划明确区分 | “新建目标” / “新建计划”；逐行查看选定目标或计划 |
| 新建目标 | 目标名称、目标币种、目标总额、预计使用日期 | “保存目标”；成功“目标已创建”后可“制定计划”或“稍后再说”；取消回进入前页面 |

| 制定换汇计划 → 确认换汇计划 | 目标总额、全部历史实际使用、本计划承接金额、本位币、拟分配金额、准备安排 | “下一步”→“查看计划”→“确认创建计划”；核对页“返回修改”保留同一目标及草稿 |
| {目标名称}（计划详情） | 具体计划编号、本位币、状态、当前分配、目标累计使用与缺口；历史计划保留原归属 | 进行中计划提供“录入换汇”“管理分配”“记录实际使用”“调整计划”“更多操作”；唯一返回按钮回原列表、目标或记录来源 |
| 编辑目标（尚无计划） | 当前目标名称、币种、总额、日期 | “保存修改”；成功“目标已更新”后查看同一目标；“取消”回原目标，不生成计划 |
| 编辑目标 → 确认目标修改（已有计划） | 目标信息、前后差异、释放分配与缺口影响 | “查看影响”→“确认修改”；“返回修改”保留输入；成功“目标已更新”后“查看计划” |
| 历史版本 | 当前选定计划的版本、修改时间、修改内容；不同本位币计划不混作版本 | 查看选定版本；“返回当前计划”回同一计划；历史版只读 |
| 修改本位币 → 确认本位币变更 | 当前与新本位币、受影响旧计划、释放金额、后继需求及安排、无需新建项 | “查看影响”→“确认更改并新建计划”；无法生成时返回修正或取消；无后继项时确认文案不声称新建计划 |
| 本位币已更新 | 各旧计划停止结果、实际新建计划、停止报告生成状态 | 对实际存在的新计划“查看新计划”；“查看成本报告”；唯一“返回设置” |
| 提高目标并重新开启 → 确认重新开启 | 原目标、新目标、累计使用、分配与缺口；仅满足全部条件时提供入口 | “查看变化”→“确认重新开启”；“返回修改”保留输入；取消回原已完成计划 |
