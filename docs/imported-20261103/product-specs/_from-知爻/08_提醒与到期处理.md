# 08 提醒与到期处理

MVP通过站内通知提醒，首页和计划详情同时显示当前状态。用户可以关闭主动提醒，但页面仍显示日期、缺口和计划进度。

## 什么时候提醒

准备日期和使用日期的提醒适用于进行中的计划。

| 场景 | 显示或提醒内容 |
|---|---|
| 到了某次准备日期 | 提醒查看本次安排；钱已备齐则停止准备提醒 |
| 旧安排需要更新 | 提示先查看并确认新安排，不再按旧日期提醒 |
| 最晚准备日仍缺钱 | 显示“未备齐” |
| 最晚准备日过了仍缺钱 | 从次日起显示“准备逾期” |
| 到了预计使用日 | 提醒核对实际用了多少钱；钱已备齐也可以提醒 |
| 预计使用日已过 | 从次日起显示“预计使用日已过” |
| 目标全部历史计划累计实际使用等于目标，当前计划剩余分配为0 | 提示确认当前计划完成 |
| 计划已完成、已取消或已停止 | 停止主动提醒 |
| 计划重新开启 | 按当前状态恢复提醒，不补发以前的提醒 |
| 本位币变更建立后继计划 | 旧计划停止提醒，新计划按自己的编号、日期及剩余需求生成提醒 |

准备提醒不表示已经换汇，使用日提醒也不会自动扣钱或判断用户未付款。钱备齐、计划完成、取消或停止后，清除对应计划的准备逾期提醒。

本位币变更预览期间，旧计划仍按原状态处理；只有整次确认成功后才停止旧提醒。新方案无法生成、校验失败或用户返回修正时，不提前停止旧计划提醒。只处理当前旧本位币下的进行中计划，不重新发送或改写其他历史计划提醒。完整规则见[创建换汇计划](<06_创建换汇计划.md#本位币变更时停止旧计划并创建后继计划>)。

## 避免重复打扰

- 同一计划同一天合并为一条提醒。
- 逾期状态持续展示，不每天重发。
- 刷新、更新安排、重新开启计划，都不重复发送当日已有提醒，只更新内容。
- 关闭后重新打开提醒，同一天也不重复发送。
- 错过的日期不补发，只显示当前状态；以后的新日期仍正常提醒。
- 提醒绑定具体计划编号；后继计划使用新编号，不把旧提醒改挂新计划。点击历史通知仍进入对应旧计划，不能跳转到同目标的其他计划。
- 从通知进入计划后，返回按钮回到原通知位置，名称及所在位置保持一致；旧计划没有可执行动作时，只展示其历史状态和实际存在的后继计划入口。

## 还缺多少钱

缺口＝目标总额−该目标全部历史计划累计实际使用−当前进行中计划剩余分配，最低为0。账户未分配的余额不会自动抵扣；停止旧计划释放的余额也不自动抵扣后继计划缺口。

| 例子（USD） | 结果 |
|---|---|
| 目标10,000，已用4,000，剩余分配6,000 | 缺口0，停止准备提醒；进行中计划到使用日仍提醒核对 |
| 目标10,000，已用4,000，剩余分配5,000，账户另有未分配1,000 | 缺口仍为1,000，用户分配后才计入 |

## 完成后纠正使用金额

正常完成的计划，把误录的使用金额调小后，仍显示“已完成”。页面列出目标、修改后的实际使用、两者差额和账户可分配余额，不把差额标成待补资金，也不催用户补齐。

例如目标10,000 USD，已用由10,000改为9,600，原账户余额为0且无剩余分配：账户可分配余额增加400，计划仍已完成。这400属于账户，不专属于原计划。

更正后不满足重新开启条件时，不开放“提高目标并重新开启”按钮，也不发送重开或补齐提醒。重新开启条件见[创建换汇计划](<06_创建换汇计划.md#完成取消和重新开启>)。本位币变更停止旧计划时，旧计划报告同步停止持续更新，保存截至停止时的报告依据与生成任务；即使没有使用记录也生成停止报告。文件生成失败仅重试报告，不恢复旧提醒或撤销停旧建新，见[成本摘要与报告](<11_成本摘要与报告_待确认.md>)。

## 待确定

提醒使用的时区、当天截止时间、跨天处理，以及更新后的剩余准备日期怎样对应原安排。邮件等其他通知方式放在后续版本。

## 界面要求

| 界面 | 字段与内容 | 主要操作与返回 |
|---|---|---|
| 通知 | 每条通知所属目标、具体计划、日期、提醒内容与当前状态 | 对应通知“查看计划”进入原计划；返回时仍定位原通知，不改为同目标后继计划 |
| 计划提醒 | 当前计划名称与身份、主动提醒开关；停止计划显示停止状态 | 进行中计划“保存设置”；“取消”返回原计划管理；每页只保留一个返回来源按钮 |
| {目标名称}（计划详情） | 当前准备日期、目标累计使用、剩余分配、缺口及日期状态；已完成更正差额与待补缺口区分 | 条件满足才显示“确认完成”；从通知进入时“返回通知”回原通知；停止计划只开放其历史及实际存在的后继计划入口 |
