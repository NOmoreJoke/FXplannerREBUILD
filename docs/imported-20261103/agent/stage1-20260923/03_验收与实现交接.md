# 实现交接与验收清单

本清单是未来实现的验收条件。只有validation目录明确记录的设计检查已执行。

## 应通过的场景

| 编号 | 场景 | 必须结果 |
|---|---|---|
| A01 | 新计划，已明确均衡，数据完整 | 首/中/尾合法日期与三等分；尾差归最后一批 |
| A02 | 用户明确前置/后置 | 选择对应合法候选；文字不能声称更高预期收益 |
| A03 | 仅有两日或一日 | 按MVP缩批，不在同日硬挤三批；仍为待确认预览 |
| A04 | 缺行情、曲线过期或超出期限 | 成本/时间规划可用部分保留；撤掉无依据比较 |
| A05 | 未知费用、初始折算持仓、多成本币 | 不补零；初始与实际区分；不同成本币分列 |
| A06 | 只回填交易，未分配 | 账户事实更新，计划缺口不自动减少 |
| A07 | 已有部分执行 | 展示原确认安排与最新事实，无新重排候选 |
| A08 | 正常使用已分配资金 | U和A反向等量变化；不重复减少准备缺口 |
| A09 | 模型无配置或不可用 | 固定事实模板；明确mode=template，语义审计不假装通过 |
| A10 | 撰写草稿程序校验通过，语义审计拒绝 | 丢弃草稿，模板回退；审计记录绑定被拒绝草稿哈希 |
| A11 | 生成成功但报告保存失败 | 503，不能返回generated；同键恢复保存 |
| A12 | 同键重试 | 相同请求复用；不同请求409；不重复发起副本 |
| A13 | 已结束计划生成新规划 | 拒绝；有权限时可读取已保存历史报告 |
| A14 | 明确缺口为零 | 无新增购汇候选；不推断目标已使用或完成 |
| A15 | 全部已有资金来源是初始持仓 | 不把初始折算参与收益比较或写成0%收益 |
| A16 | 活跃计划无可靠确认基线或执行状态未知 | 门控unknown，无新候选；不以未匹配为未执行 |
| A17 | 已核实确认安排生效后尚未开始 | 门控not_started_verified；其他资格通过才生成预览 |
| A18 | 生成安排前已有分配，之后无活动 | 按可信基线判断，不仅凭已有分配误判部分执行 |

## 应拒绝或降级的输入/输出

- 前端提交本金余额、持仓数组、任意模型或工具名称等额外字段。
- 伪造对象归属、版本不匹配、用户身份作为业务字段、越权引用。
- 快照中余额与分配冲突、缺必需目标量、严重状态矛盾。
- 模型更改candidate_id、日期、金额、mandatory_notice_codes或policy.eligibility。
- 用裸数字或汉字数字替代可信metric占位符；引用不存在、不可用或不适用的指标。
- 给未来获利概率、保证节省、把期货曲线当未来即期或可执行银行价格。
- 把目标币净到账与购买前数量混淆；把关联交易等同分配。
- 把仅有部分执行的旧安排强制改成新三批；自动重开终态。
- 把同目标数量成本比较与同来源币支出下所得数量比较混用。
- 审计pass却有issues、reject却无issues、审计草稿哈希不匹配、请求/快照ID不匹配。
- facts冲突时使用模板掩盖；模板里继续使用被拒绝AI内容。
- GET历史报告触发新行情/模型；报告追问暗中改数据或重新规划。

## 开发前需配置

1. 用户/资源权限与一致快照适配，现有表与MVP概念的准确映射。
2. 工作日日历、截止时间、币种精度与准备安全日规则。
3. 数据质量、费用和比较范围，缺失状态及明确原因。
4. 模型部署与密钥在服务端的管理；遵守既有数据发送与保留政策。
5. 报告、任务、幂等与审计持久化；原子完成状态与恢复路径。
6. 计划页按钮和报告展示；渲染可信表格与metric替换；需要PDF时共用同一快照。

本文不要求先创建Chatbot。先把上述报告路径接通并验证，再开放绑定报告的只读追问。
