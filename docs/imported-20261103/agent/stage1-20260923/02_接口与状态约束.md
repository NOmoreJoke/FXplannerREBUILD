# 接口与状态约束

本文件与 contracts/openapi.json、stage-a.schema.json共同构成设计契约。没有已部署接口。

## 1. 客户端接口

### POST /api/v1/planning-agent/generate

认证：产品JWT；服务端从认证上下文取得用户身份。需要Idempotency-Key和资源expected_version。请求采用V0.2 GenerateRequest，阶段A只接受PLANNING、PROGRESS。

客户端只提交已保存的plan或preview引用、报告类型、语言、关注点及可选说明。金额、持仓、成本、行情、策略政策不能作为此请求的权威字段；额外字段直接拒绝。预览仍由业务服务先保存和授权。

成功返回PhaseAResponse，其result是兼容V0.2的ServiceResponse，外层pipeline_audit记录程序与独立语义审计。不是让模型直接生成整个响应。

PLANNING适用于draft/active；PROGRESS只适用于active且有已确认安排。completed/cancelled/stopped或不匹配报告类型返回422/REPORT_STAGE_MISMATCH。不改变旧报告的读取资格。

现有旧路由及其响应不变；应用接入新路由时需要显式读取外层result，不能假设顶层仍是V0.2 ServiceResponse。

### GET /api/v1/planning-agent/reports/{report_id}

认证和归属检查后返回原先持久化的同一PhaseAResponse，不重新跑模型、不刷新行情、不改变快照。不存在或不属于用户统一404。读取终态历史报告允许，但不得附带新的准备候选。

生成后事实有更新的提示由业务版本比较提供；不能覆盖此接口的历史内容。PDF如接入，必须使用相同ReportContent；本阶段不另定义PDF生成接口。

### 可选未来 POST /api/v1/planning-agent/reports/{report_id}/questions

只预留请求/响应Schema，不加入当前OpenAPI可用路径，也不启用路由。请求绑定report_id及expected_snapshot_id，回答只引用该快照的指标和证据，不能重新计算或修改事实。

## 2. HTTP与领域状态

| HTTP | result.delivery_status | 主要错误码/含义 |
|---|---|---|
| 200 | generated | 报告、审计和幂等结果已持久化；report非空，error为空 |
| 400 | rejected | INVALID_REQUEST：JSON或结构错误 |
| 401 | rejected | UNAUTHORIZED |
| 404 | rejected | RESOURCE_NOT_FOUND：不存在或无权访问 |
| 409 | rejected | RESOURCE_VERSION_CONFLICT、IDEMPOTENCY_CONFLICT |
| 422 | rejected | REPORT_STAGE_MISMATCH、SNAPSHOT_INCONSISTENT |
| 429 | rejected | RATE_LIMITED |
| 503 | retryable_error | SNAPSHOT_UNAVAILABLE、REPORT_IN_PROGRESS、REPORT_PERSISTENCE_FAILED、REPORT_TEMPLATE_FAILED |

非generated结果中report必须为null，error必须非null。generated时反之。当前设计同步返回；不把202当作generated，不隐式引入异步Job契约。进行中同键请求在预算内等待相同任务，超时用503及Retry-After，不能启动并行副本。

## 3. 幂等与冻结

幂等范围是认证用户＋键＋规范请求体。相同键和内容复用逻辑任务；同键不同内容409。冻结后重试不替换快照、不因新行情改写基准。需要刷新时显式新请求和新键。

报告和审计提交失败时保留待恢复的冻结结果，重试先恢复保存，不再调用模型。若进程中断导致某供应商结果丢失，只能按持久化尝试预算恢复；不得承诺外部模型请求恰好一次。

context_hash沿用V0.2：ProviderInput递归键排序、数组原顺序、UTF-8、紧凑JSON、非ASCII不转义、无NaN。narrative_hash对ModelOutput采用相同规范化。审计输入、输出与交付报告逐字匹配request_id/snapshot_id及哈希，防止审错草稿后放行另一版本。

## 4. 内部工具接口

这些是应用服务接口设计，不是LLM可任意调用的HTTP URL。认证上下文由服务端绑定；模型不能传user_id或SQL。

| 工具 | 输入 | 输出 | 权限 |
|---|---|---|---|
| resolve_report_snapshot | 授权资源引用、类型、预期版本 | 经领域核验的ProviderInput及DataManifest | 业务只读，可保存冻结快照 |
| select_fixed_candidate | 经核验的候选、结构化偏好、计划状态 | 服务端Selection及固定StrategyRationale | 仅快照服务内部使用；冻结前完成选择 |
| validate_report_output | ProviderInput、ModelOutput | 校验通过或具体内部问题码 | 程序校验，不由模型自评 |
| review_report_semantics | SemanticAuditInput | SemanticAuditOutput | 独立模型，无其他工具 |
| save_validated_report | 验证后的报告、审计摘要、幂等身份 | 持久化报告引用 | 只写报告/审计/任务状态 |
| load_authorized_report | 报告引用及认证上下文 | 已保存报告与快照 | 只读 |

resolve_report_snapshot在冻结最终ProviderInput前可调用选择服务；被冻结后禁止StrategyRationale回写policy.selection。数据和策略角色都不产生权威财务数字。策略说明角色不在冻结后再次调用选择工具。

### 执行门控 ExecutionGate

DataManifest、SemanticAuditInput及成功响应的pipeline_audit包含同一个服务端ExecutionGate；它与snapshot_id及资源版本一起冻结，不接收客户端或模型修改。旧ProviderInput不新增字段；禁止候选的原因通过已有issues投影。context_hash仍仅覆盖旧ProviderInput；完整冻结记录还必须原样保存门控并核验跨对象一致性，不能只凭context_hash验证新增元数据。

| progress_state | 可进入候选生成 | 依据 |
|---|---|---|
| draft | 是 | 可信计划状态为草稿 |
| not_started_verified | 是 | 服务端核实当前确认安排生效之后没有准备执行活动 |
| started | 否 | 有确定的准备执行活动，记录PARTIAL_EXECUTION_REPLAN_DISABLED |
| unknown | 否 | 无可靠基线、来源不完整或存在无法判断的相关记录，记录EXECUTION_STATUS_UNKNOWN |

允许表示通过此一道门控，仍须满足缺口、日历及其他资格要求。禁止时candidates=[]、policy.selection.candidate_id=null；选择原因采用旧枚举NO_ELIGIBLE_CANDIDATE，并提供对应Issue。不是阻止展示既有安排或当前成本。

核验基线是当前确认安排生效时冻结的计划版本与数据截止点；生成该安排前的初始/已有持仓分配不自动算作其后执行。服务端从基线之后的分配贡献、相关准备事件及交易关联状态核验；关联记录无法确定用途时归unknown，不能据此确认已完成某批次，也不能据“未匹配”确认未开始。缺可靠基线按unknown处理，第一阶段不用模型猜测。每个evidence_id必须在同快照证据目录中可解析，并支持门控结论。

首次生成新候选仍为预览；冻结门控不授权覆盖正式计划。交易、分配、使用回填改变业务版本后，应重新生成事实快照并重新核验门控。

## 5. 独立语义审计

先通过程序校验，再把SemanticAuditInput交给审计模型。审计检查“是否有证据支持陈述”，包括语义不一致、未授权建议、混淆成本和收益、虚构来源、把预览说成已执行及提示注入。

审计输出decision=pass时issues必须为空；reject时至少有一个问题。所有问题都触发丢弃AI草稿，第一阶段不让模型通过互相说服反复修改到通过。

SemanticAuditOutput只是一个模型意见，最终程序仍校验其结构、引用、request_id、snapshot_id、draft_hash及调用状态。审计模型不能填写facts_validation或delivery_status。

## 6. 外层审计摘要语义

pipeline_audit由服务器生成：

- execution_gate：本次冻结的执行门控；尚未成功核验事实时可为null，成功响应必须有值。
- facts_validation：passed / failed / not_run，表示领域数据检查。
- delivered_output_validation：passed / not_run，只有已完成交付前检查的内容才能为passed。
- semantic_review.status：passed / rejected / unavailable / not_run。
- semantic_review.scope：delivered_ai / discarded_ai / undelivered_ai / none。
- semantic_review.narrative_hash：所审草稿哈希；无草稿时null。
- delivered_narrative_hash：最终交付ModelOutput哈希；失败响应为null。
- model_calls：report、quality及total真实发出次数。total=report+quality，上限三次。

送达AI报告时：语义审计必须passed、scope=delivered_ai、审计草稿哈希=交付哈希。送达模板时不能标delivered_ai；被拒绝或审计不可用的旧草稿可以记录scope=discarded_ai，但不能让这段记录成为模板内容“已通过AI审查”的证据。

输入被拒绝或存储失败时，delivered_output_validation=not_run表示没有已交付对象；不否定服务端可能已完成的草稿检查。审计已通过但持久化未成功的草稿记录scope=undelivered_ai，保持可恢复而非宣称已交付或已丢弃。详细内部审计另存。

模板回退原因为V0.2已有枚举：语义拒绝映射INVALID_OUTPUT；审计网络故障映射PROVIDER_UNAVAILABLE；时间耗尽映射TIMEOUT。具体发生于quality阶段通过pipeline_audit记录，不偷偷扩展旧枚举。

## 7. 结构不能替代业务校验

必须额外检查：ID目录闭合、指标状态与值、占位符集合、候选总额与相应缺口、合法日期、币种精度、分母与比较范围、未知费用、初始来源剔除、模型状态与服务一致、原确认安排与新预览区分、终态、部分执行禁重排、snapshot/hash一致、幂等与对象归属。

Schema中的日期需启用format检查。服务拒绝重复JSON键、NaN/Infinity、指数/浮点金额和超限输入，不静默丢字段或截掉账本记录。具体数值范围以业务校验为准。
