# 登录后页面与交互评估

核验日期：2026-09-20。环境：用户已登录的 Codex 内置浏览器，`https://fxplanner.zyaoai.com`。在约20:29—20:51可见页面状态之间完成操作，未将该时间段作为性能测量。

## 结论

**当前版本的页面骨架和部分计算已可用，但不宜按当前状态完成 MVP 业务验收。** 本轮新增19项页面／交互问题：5项P1、12项P2、2项P3。最先修正的是排期金额、切币后的旧数据、更正计算入口、同币种计划预览、补录初始成本依据。此前未登录检查的3项差异另见[原报告](<00_核验结果与整改清单.md>)，不重复计入本轮19项。

P1表示优先修复、会影响金额理解或阻断核心操作；P2表示已确认设计差异或明显交互问题；P3表示展示与一致性问题。这里不是后端安全等级，也不意味着已发生真实账本错误。

已覆盖13个页面及使用、计划修改、取消计划、导出、清空、注销等弹窗。执行了输入、切换、预览、校验、返回、取消、筛选、重新进入及刷新；**未点击任何业务最终保存／入账／使用／更正／取消计划／清空／注销确认**。因此本轮是已登录页面、表单和预览验证，不是完整写入闭环或生产验收。未改变线上代码。

## 最高优先级：5项

### UI-01 / P1：新计划排期不扣拟计入的已有外币

- 位置：`/plans/new`。账户可分配余额为10,000 USD；目标100 USD时，表单显示分配上限100。
- 复现：目标100 USD、预计使用2026-12-01、计入已有外币40、均衡。页面仍显示33.33／33.33／33.34 USD，合计100；切换节奏触发重算后仍如此。计入100时，安心型仍显示50／30／20。
- 应有结果：拟分配40应按缺口60排为20／20／20；拟分配100时缺口0，不再排100。草稿中的拟分配不等于正式占用资金。
- 调整：所有预览从“目标剩余需求−拟分配”计算；提交前再校验可分配余额，条件变化先重新核对，不能静默换方案。
- 验收：分配0／40／100时，准备合计分别100／60／0；正式提交与确认的方案一致；超分配明确阻止。
- 依据：07模块“需要安排多少金额”，06模块“已有外币怎样分配”。证据E08。**未提交，不推断正式创建后的账务结果。**

### UI-02 / P1：切换买入币种时沿用旧交易对数据

- 位置：`/transactions/new`。
- 复现：USD，本金72,480 CNY、成交汇率7.248、费用42，显示到账10,000.00 USD、总成本72,522.00 CNY。切CAD后参考汇率变为4.807，但旧7.248仍在，到账只换成10,000.00 CAD，“保存”仍启用，无重新核对提示。
- 应有结果：旧交易对的确认状态和自动到账结果失效；保留原草稿，让用户明确新交易对与实际成交输入后重新核对。
- 调整：切币清除旧的“已核对”状态，提示原值属于USD；用户重新选择／确认CAD的实际数据后才开放下一步。不要用新参考价自动覆盖用户真实成交价。
- 验收：切币后不能直接沿用旧值保存；返回原币可恢复其草稿；关联计划随币种更新。
- 依据：05模块“币种与计算状态”。证据E12。**未保存，不能称CAD账本已被错误入账。**

### UI-03 / P1：本位币与目标币相同仍生成换汇方案

- 位置：`/plans/new`。
- 复现：本位币CNY，目标币选择CNY，目标100，使用日2026-12-01；生成33.33／33.33／33.34 CNY三批，“创建计划”启用。
- 应有结果：只支持A→B且A≠B；同币种应直接阻止换汇计划预览及提交。
- 调整：选项排除当前本位币，前后端均校验A≠B；设置变化后重新核对旧草稿。
- 验收：同币种不能进入可确认状态；提示改选目标币；不产生计划。
- 依据：06模块第7、17行。证据E08。**已证实前端守卫缺失，后台保存是否阻止尚未测。**

### UI-04 / P1：实际到账数量更正被不可操作的汇率校验阻断

- 位置：交易详情→更正，`/corrections/new?targetType=TRANSACTION&targetId=…`。
- 原记录：USD到账10,000，本金67,134 CNY，费用0，成交汇率6.7134。
- 复现：只把到账改为9,999并填原因，点“查看影响”，报“本金、汇率与到账数量不匹配：请按其中一种填法重新核对”。表单没有汇率字段或两种计算方式。将本金改60,420.6、到账改9,000以维持旧汇率，才可生成预览。
- 应有结果：用户可按真实本金＋真实到账反算新汇率；67,134÷9,999约为6.71407141。不能迫使用户改错本金以适配旧汇率。
- 调整：更正页复用买入的两种计算方式，并展示新旧本金、到账、汇率、费用及影响；后台只核验本次一致的事实。
- 验收：本金不变、到账9,999时能预览新汇率及余额／成本影响；更正原因必填；取消保留原记录。
- 依据：09模块修改数量／本金与成本重算规则、05模块两种填法。证据E11。隐藏旧汇率造成冲突是根因推测，须由源码确认。

### UI-05 / P1：补录初始持仓的成本时点说明与设计冲突

- 位置：首页“去补录”→`/onboarding?backfill=1`。
- 复现：说明“记账起点当日已持有的金额，按当前有效报价折算初始成本”；填100 USD，展示6.71274000、来源农行现汇卖出价、报价时间仅2026-09-20、成本671.27 CNY并启用确认。未显示真实记账起点、原成本币确认信息、原时点报价时间或有效性核对。
- 应有结果：首次建账用本次有效报价；建账后补漏用原记账起点及当时成本币，并核对原确认时点前不足5分钟的历史报价，不能混为“现在补录就用现在价”。
- 调整：分开首次初始化和补漏界面；显示完整记账起点、历史报价时间与来源、取得历史报价的依据。没有符合条件的报价时保留输入并阻止确认。
- 验收：补漏不采用今天的新本位币或新行情重估；原日期不能随意改；已有买入不能重复记作初始持仓；缺历史价明确说明。
- 依据：02模块“首次补充与已有记录更正”“初始记录填错了怎么改”。证据E17。**目前证明的是页面及核对依据冲突，未证明后台已经使用当前价写入。**
