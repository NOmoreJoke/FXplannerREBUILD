# 交互优化方案

适用：2026-09-20已登录站点评估。区分“当前确认规则必须对齐”与“建议优化”；不以本方案擅自确认收益公式、节假日日历或扩展终态编辑权限。以下是开发可实施的页面要求，未改线上界面。

## 1. 首页：让用户知道下一步该做什么

建议将主区域按任务安排：

1. 顶部主操作“录入换汇”，次操作“新建目标”；已有目标可“制定计划”。
2. 优先展示最近准备节点及金额、该计划尚缺金额、进入计划的按钮。当前首页用全年最晚日期作为主要指标，下一次应准备什么不够突出。
3. 账户摘要明确“余额／已分配／可分配”，金额加千分位和币种。
4. “补录初始持仓”作为相关入口保留，但不长期占据已有用户首页最大提示区；明确是补录记账起点漏填余额，不能重复记入已经录入的买入。
5. 汇率更新时间移为次要说明，写明是报价观察时间，不能替代各币种报价时点。

以上层级、卡片位置为优化建议；独立目标入口和准确成本时点是既定规则。

## 2. 创建计划：分清目标、分配和排期

```mermaid
flowchart LR
  A[新建目标或选择已有目标] --> B[目标总额与全历史使用]
  B --> C[选择计入已有外币]
  C --> D[开始准备日与准备节奏]
  D --> E[核对缺口 日期 批次 金额]
  E --> F[确认创建并重新校验]
  E -->|返回修改| C
  F --> G[具体计划详情]
```

- 目标可独立保存，成功页提供“制定计划／稍后再说”。
- 分配区同时显示账户可分配余额、用户拟分配、还需准备；不可只等预览后才给上限。
- 关键等式直接写给用户：**目标100 USD − 已用0 − 计入已有40 = 还需准备60 USD**。
- 本位币从设置带入，目标币排除本位币；不能在这里提供中间币路径。
- 开始准备日与最晚准备日分别显示，不能用一个“提前准备天数”替代两者。
- 核对区显示真实批数及合计；缩批时说明原因。仅当目标剩余需求大于0且拟分配覆盖该需求时，显示确认后可备齐、无需新增准备，不能再排目标全额；拟分配还未正式生效，不冒充账户已占用。累计使用恰达目标且剩余分配0时另示使用完成／无需新建，不能统称已备齐。
- 最终按钮“确认创建计划”；预览数据变化时“方案已变化，请重新核对”，不写“实际以创建后的计划为准”。
- 当前保存草稿按钮禁用且标开发中：在功能未可用时，建议移除无效按钮或只给简短说明；不能据此扩大草稿期限等未定规则。

## 3. 计划详情：按动作拆开“修改”

建议保持四个清楚的操作：“录入换汇”“管理分配”“记录实际使用”“调整准备安排”，再把目标修改、历史版本和取消放入更多操作。它们可复用同一底层组件，但入口及字段应贴合当前任务。

- 零分配时，不让用户进入只能填0的使用死路；提示“当前没有可使用分配”，给“管理分配／录入换汇”。仍有余额但未分配时，不自动替用户分配。
- 完成按钮只在规则允许时出现；准备达标与实际使用完成分开。
- 取消预览加上“将释放0 CAD”“账户总余额不变”“已用0 CAD不恢复”等实际数字，保留最终确认。
- 版本入口显示该计划本身的历史；普通调整沿用编号，变更本位币的新后继计划单独展示关系。

## 4. 买入与更正：复用同一金额计算组件

```mermaid
flowchart LR
  A[确认直接交易对] --> B{填写方式}
  B --> C[本金与实际汇率]
  B --> D[本金与实际到账]
  C --> E[核对本金 到账 汇率 费用]
  D --> E
  E --> F[显示账户及计划影响]
  F --> G[确认保存或更正]
```

- 新录入与更正都支持两种输入；更正额外要求原因、原值、新值和影响。
- 手续费有“明确金额／未知”，0是明确没有费用，不以空值当0。
- 切币后显示“交易对已变为CNY→CAD，请重新核对实际成交数据”；旧计算结果不继续当有效结果。
- 不要求用户手工维持第三个隐藏字段。按本金＋到账输入时反算汇率，再按明确精度校验。
- 保存前的核对区只呈现已确认数据，信息变化后重新核对；“保存”入口是否已有后续确认仍待写入测试，不能凭按钮名断言后台无核对。
- 关联计划显示名称、币种、缺口；明确关联只是标签，分配是另一项动作。

## 5. 补录初始持仓：先把时间与来源讲清楚

核对卡至少包含：真实记账起点（含时间／时区）、原成本币、漏填持仓币种与金额、原时点历史报价、来源、完整报价时间、折算成本。

首次初始化可以显示本次报价有效性与剩余时间；历史补漏必须按原时点报价规则判断，不能把历史报价与“距离现在5分钟”混用。找不到符合条件的历史价，保留输入并明确不能提交。已记为普通买入的余额不能再次补成初始持仓。

## 6. 设置：明确本位币变更的后果

```mermaid
flowchart LR
  A[选择新本位币] --> B[列出受影响计划与剩余需求]
  B --> C[展示释放分配和后继安排]
  C --> D{整体校验通过}
  D -->|否| B
  D -->|是| E[确认变更 停旧 建新 保存报告依据]
  E --> F[实际结果与报告生成状态]
```

“查看影响”之前不改设置；取消保持原状。无进行中计划时仅更新默认值。仍有剩余需求、需要后继计划的目标存在A=B或无法生成有效新安排时，阻止整次变更；累计使用恰等目标且剩余分配0时，受影响旧进行中计划只停止、不新建后继，不因无需生成的交易对A=B而阻止。旧账原币成本保留，释放资金不自动给新计划。报告文件失败单独重试，不重复停旧建新。

## 7. 报告、空状态与返回

| 状态 | 建议文案 | 主要动作 |
|---|---|---|
| 当前筛选无匹配 | 当前筛选下没有报告 | 清除筛选 |
| 普通非停止计划尚未实际使用 | 该计划尚无实际使用记录，使用后可查看使用成本报告 | 查看计划 |
| 本位币变更后已停止的计划，即使零使用 | 显示截至停止时的摘要、零使用状态及实际报告生成状态 | 文件就绪后下载停止报告 |
| 没有目标或计划 | 先创建目标，再安排资金准备 | 新建目标 |
| 报告生成中 | 报告正在生成，完成后可下载 | 查看进度 |
| 报告生成失败 | 报告文件暂未生成，账本记录不受影响 | 重试原报告任务 |

这些状态不能都显示同一个“去创建计划”。列表返回保留筛选、位置和对象。所有面包屑用中文，交易详情回原币种账户，更正回原交易，计划来源的录入回原计划。

## 8. 可直接替换的文案

| 现文案 | 替换建议 | 性质 |
|---|---|---|
| 净到账金额（计划） | 目标总额（USD），最终需要准备的外币金额 | 术语澄清 |
| 用途日期 | 预计使用日期 | 与已定设计一致 |
| 用途日期前开始准备的天数 | 在预计使用日前，提前几个工作日备齐 | 修正含义 |
| 首批轻仓试探，后续逢低加码 | 后期多准备：20%／30%／50%，不代表更优汇率 | 修正规则描述 |
| 建账时确定，不可更换 | 默认本位币：CNY；修改前需查看对进行中计划的影响 | 依赖变更功能落实，不能只改字而不提供流程 |
| 已为你预填分配总额上限 | 当前最多可分配0 CAD，请修改输入后重新预览 | 不宣称未发生的改值 |
| CAD · 剩余0.0000 CAD | 未命名计划 · CAD · 还需准备12,000.00 CAD | 区分缺口与分配 |
| principalAmount／quantity | 本金（CNY）／到账数量（USD） | 使用实际币种 |
| 所有记录永久保留、不可删除 | 更正会保留原记录和修改历史；整套数据清理请前往账号与数据 | 与数据清理规则一致 |
| 按所选节奏拆分为3批（实际2批） | 当前仅有2个可安排日期，本方案分2次准备 | 显示实际次数与原因 |

## 实施顺序

1. 先修UI-01—05，增加针对复现数据的计算／输入／预览回归；再做正式提交回归，不能只看按钮变灰。
2. 补独立目标、本位币变更、开始准备日等已确认缺失链路，并验证原子性、旧记录、版本及报告依据。
3. 统一字段、金额、返回、筛选空态、操作名称和提示；验证已存在的正确计算没有回归。
4. 最后在明确可用的测试数据范围内跑完整“买入→分配→使用→更正→完成／取消→报告”链路与PDF一致性。

本方案未量化点击节省、效率提升或性能改善；这些需要实施后的用户任务测试。
