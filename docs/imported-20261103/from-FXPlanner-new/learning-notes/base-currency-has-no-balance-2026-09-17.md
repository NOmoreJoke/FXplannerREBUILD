# 本位币没有余额：系统只管外币库存，分配锚定外币

**提问时间：** 2026-09-17

**问题：** 我是本位币转外币，分配应该是把本位币的余额分配到计划里吧？现在的"分配外币余额"逻辑是不是很奇怪？

---

## 核心要点

- 本位币在系统里**没有账户、没有余额**——刻意设计（`02_初始化与录入闭环_待确认.md:7`「不能把本位币填作外币」）；它的唯一用途是记录买入成本的记账单位（`14_业务逻辑清单.md:8`）
- 系统边界：**只管外币库存这一侧**，本位币资金由用户自己负责；产品定位是外汇库存+成本管理，不是记账 App
- 计划目标必须锚定**外币金额**：汇率波动，本位币金额是波动的成本，外币金额才是稳定的目标；预算只能锚定稳定的东西
- 分配发生在**买入之后**：换汇动作在买入交易那一刻已完成（本金/汇率/手续费都记了），分配不做兑换，只是给到手的外币贴标签
- 若"分配本位币"则：预留数随汇率漂移要反复修正、使用时二次折算误差、还得先给本位币建账（范围爆炸）
- 仓库类比：账户=仓库，买入=采购入库，分配=贴标签，使用=出库；给货贴标签，不给采购预算贴标签

## 关键示例

```
计划目标：10,000 美元（不是 72,000 人民币！）
  9/1  买入 6,000 USD @7.20 → 美元账户 6,000，人民币只记成本 43,200
  9/15 买入 4,000 USD @7.30 → 美元账户 10,000，成本累计 72,400
  分配 10,000 USD 给计划    → 美元余额不变（贴标签）
  使用 4,000 USD 交学费     → 余额 6,000，FIFO 从前批算成本
  计划完成 → 最终答案：这个用途共花 72,400 人民币（结果是输出，不是输入）
```
