# onboarding 与 rate 模块边界

**提问时间：** 2026-09-08

**问题：** onboarding 和 rate 什么区别，为什么要分成两个模块？

---

## 核心要点

- 本质区别：onboarding 管"人"（首次设置的流程状态），rate 管"数据"（汇率报价的获取与新鲜度）。
- 触发频率相反：onboarding 每用户一次、写完冻结（本位币锁定）；rate 每次录入/每 60 秒/每次确认都在调、5 分钟滚动过期。
- 变化原因不同：onboarding 因业务流程/条款版本变；rate 因外部数据源/币种支持变 → 单一职责原则，一个模块一个变化理由。
- 依赖必须单向：持仓入账要查汇率，所以 `onboarding → rate`；rate 不依赖业务模块，才能被多个场景复用（录入、更正、市值显示）。
- 实际收益：W1 波次隔离性 `auth/+onboarding/ ∥ rate/` 文件集不相交，可串行/并行开发互不冲突。

## 三模块分工

| 模块 | 职责 | 关键词 |
| --- | --- | --- |
| auth | 证明你是谁 | 验证码登录、JWT 凭证 |
| onboarding | 登录后第一次的设置 | 条款、本位币锁定、记账起点、草稿 30 天 |
| rate | 记账用的汇率数据 | 报价有效期、缓存、落库、异常兜底 |

## 相关概念

- 单一职责原则（一个模块只有一个变化理由）
- 单向依赖（业务模块 → 基础数据服务，禁止反向）
- NestJS 模块化（按业务域分模块，app.module.ts 唯一注册点）
