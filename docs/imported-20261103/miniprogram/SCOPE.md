# FXplanner 小程序 — 范围文档（SCOPE）

> 本文件是 MVP 的边界契约：**做什么 / 坚决不做 / 加功能的触发证据**。
> 动手开发任何功能前先回到这里对照。没有文档，每次会话从零倒推会导致架构漂移（AI 技术债带复利）。
> 最后更新：2026-06-18（新增服务号联动 Roadmap、真实成本明细、实际成交成本记录、多模态录入含小票 OCR、FIFO 成本核算）

---

## 0. 一句话定位

FXplanner 小程序是 FXplanner 在**微信生态内的轻量端**——做的是「快录 + 查看 + 分享」，
不是 Web 端的完整复刻。

**战略理由**：核心变现漏斗「学生算完成本 → 转发报告给家长 → 家长付费」天然发生在微信里。
小程序把这条转化链路焊死在微信内（原生转发卡片 + 家长免登录看报告 + 未来微信支付）。

## 1. 做什么（MVP 范围）

| 模块 | 说明 | 交互 | 后端依赖 |
|---|---|---|---|
| **微信登录** | `wx.login` → `code2session` → JWT | 轻 | `/auth/miniapp/login`（待建） |
| **多模态快速录入** | 三种入口：①文本「一句话」②语音描述（STT）③拍照银行换汇小票（OCR）→ 后台自动识别金额 / 汇率 / 手续费 / 对应银行 → AI 解析 → 二级确认弹窗 | 中 | `/api/v1/ai`、`/api/v1/transactions`、OCR 服务（待接） |
| **真实本币成本（明细）** | 展示具体换汇真实成本：逐层转换链路（牌价点差 + 手续费 + 电汇费等）→ 最终到手本币成本，不只显示总额 | 中 | `/api/v1/transactions` |
| **潜在损耗查看** | 基于 365 天历史汇率，测算"最差比最好可能多花多少" | 中 | `/api/v1/tracking` |
| **记录实际成交成本（执行确认）** | 实际换汇后录入成交汇率 / 手续费 / 金额 → 计算实际本币真实成本 + 实际节省，作为成本记录留存（与"计划成本"对照） | 中 | 执行确认 API（ExecutionConfirm，端点以后端为准） |
| **购汇额度查看** | 年度 5 万美元额度环形进度 + 四级告警 | 中 | `/api/v1/quota`、`/api/v1/region-rules` |
| **汇率行情 / 历史图表** | 实时汇率 + 线图 + MA7/MA30 | 高（图表） | `/api/v1/rates`、`/api/v1/bank-rates` |
| **分批方案【查看】** | 展示"分几批、每批多少、风险下降%" | 中 | `/api/v1/planning` |
| **报告生成 + 转发家长** | 生成快照 → `onShareAppMessage` 转发 → 家长免登录看 | 中 | `/api/v1/reports`（share_token） |
| **兑换码兑换** | 输入 FXP-xxxx → 确认 → 解锁权益 | 轻 | `/api/v1/billing` |
| **WebSocket 实时告警** | 额度 / 汇率 / 续期提醒，顶部告警条 | 轻 | `wss://api.fxplanner.cn/ws` |
| **设置** | 本币、通知偏好 | 轻 | `/api/v1/users` |

> **成本记录 = 两类**：①「计划成本」录入要换的交易 → 预估真实本币成本（逐层明细）；②「实际成本」换汇成交后录入实际汇率/手续费 → 实际真实成本 + 实际节省。二者对照即 ROI 闭环。
>
> **成本核算方法**：后端按时间顺序、**FIFO（先进先出）**逐笔计算每笔换汇的真实成本，并汇总持仓的**平均成本**。需后端维护「币种批次账本」（买入/使用按时序匹配）——属后端计算依赖，具体算法与端点以后端为准。

## 2. 坚决不做（留在 Web / 桌面端）

> 这些不是"以后不做"，而是"小程序这一版明确不碰"。要加须满足第 3 节触发证据。

- ❌ **分批方案的配置 / 调参**：选风险档位、改 deadline、重算方案——重交互，留 Web。小程序只「查看」已生成的方案。
- ❌ **复杂历史回放 / 多指标叠加分析**：超出"看一眼汇率走势"的深度分析留 Web。
- ❌ **执行确认台账的批量 / 复杂管理**：单笔实际成交成本录入已纳入 MVP（见 §1）；批量编辑、历史台账的复杂管理留 Web。
- ❌ **桌面端能力**：本地语音 STT（Whisper）、Tauri 相关，与小程序无关。
- ❌ **在线支付**：MVP 用兑换码。微信支付是 P1（届时小程序反而是支付主场，见第 3 节）。
- ❌ **完全离线**：不做离线编辑方案。无网时展示"部分功能不可用"，核心操作要求在线。
- ❌ **多端 UI 框架抽象**：选定原生开发，不引入 uni-app/Taro/Vue。需要复用的是纯逻辑层，不是 UI 层。

## 3. 加新功能的触发证据

> 防止"行动快于认知"。每条新功能要先有证据，不靠拍脑袋。

| 候选功能 | 触发证据（满足才做） |
|---|---|
| 小程序内做分批**配置** | 有 ≥N 个用户反馈"在手机上就想直接改方案，不愿回 Web" |
| 接入**微信支付** | 兑换码验证了付费意愿（有真实兑换转化），且家长付费场景确认在微信内 |
| 执行确认**写入** | 用户在小程序完成换汇后，确实有在手机上记账的需求数据 |
| 个性化主动提醒 | WebSocket 告警的打开率 / 转化数据证明推送有效 |
| 扩展 H5 / App | 出现明确的非微信渠道需求（届时再评估是否值得重构，而非现在预留） |

## 6. 规划中（Roadmap，非本期 MVP）

> 已确认要做、但不在当前 MVP 范围内的功能。开工前回到此节细化设计。

### 6.1 服务号联动 + flomo 式快捷输入 🌟

**目标**：把 FXplanner 的「一句话录入」搬进微信聊天框。用户直接给**服务号**发消息
（文本或语音）即可记一笔，无需打开小程序——对标 flomo 服务号的快捷记录体验。

**一鱼两吃（共用同一套服务号基建）**：
1. **输入侧（flomo 式）**：服务号收到「9月交4万美元学费」→ 后端 AI 解析 → 推断方向 → 创建交易 → 客服消息回复确认。语音消息复用微信语音识别结果（`Recognition` 字段）。
2. **触达侧（加成）**：额度 / 汇率 / 续期告警改用**服务号模板消息（订阅消息）主动推送**，触达强于小程序内 WebSocket（用户无需打开小程序）。

**关键地基 ⚠️**：服务号与小程序须绑定在**同一微信开放平台账号**下，共享 `unionid`，
才能把"服务号发来的消息"认到"小程序里的同一 FXplanner 账户"。
（正好补上调研发现的"小程序单独拿不到 unionid"的坑。）

**技术依赖**：
- 认证**服务号**（订阅号无客服接口/模板消息权限），开通「接收消息」「客服消息」「接收语音识别结果」接口权限。
- 后端新增微信消息 webhook（如 `POST/GET /wechat/mp/callback`）：URL 验签 → 解析消息类型 → 路由到 AI 解析 → 客服消息回复。
- **账户绑定流程**：服务号首次发消息的未绑定用户，回复引导其在小程序内登录完成 `openid ↔ FXplanner 账户` 绑定（靠 unionid 串联）。
- **回复时效**：用户发消息后 48h 内可用客服消息即时回复（满足"录入即确认"）；超窗口的主动提醒走订阅消息（需用户授权）。

**触发证据（满足才正式开工）**：
- 小程序 MVP 已上线，AI 一句话录入在小程序内验证有效（解析准确率可接受）。
- 服务号资质 + 微信开放平台账号绑定就绪。

**与现有规划的关系**：
- 替代 / 增强 `SCOPE.md` 第 3 节的「个性化主动提醒」——服务号模板消息是其落地渠道。
- 输入侧复用 MVP 的 `/api/v1/ai` + `/api/v1/transactions`，AI 解析逻辑不重复造。
