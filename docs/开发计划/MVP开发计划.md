# MVP 开发任务表（按模块拆分）

> 依据：`docs/MVP功能模块&业务逻辑&专业术语/` 15 份文档 + 15 个计算例子（doc 14）。
> 原则：待确认项不阻塞主线——核心逻辑按文档明确部分实现，边缘分支留 TODO，产品确认后补齐。

## 模块依赖关系

```
M0 基础设施 ──> M1 认证与首次设置 ──> M3 账户 ──> M4 买入交易 ──> M5 换汇计划 ──> M7 资金使用
                    │                                                │              │
                    └──> M2 汇率（并行）──────────────────────────────┴──> M6 分批准备
                                                                     M8 更正 ──> M9 提醒 ──> M10 报告
                                                                                  M11 账号与数据
                                                                                  M12 首页（前端整合）
```

**推荐顺序**：M0 → M1 → M2（可与 M1 并行）→ M3 → M4 → M5 → M7 → M6 → M8 → M9 → M10 → M11 → M12

## M0 基础设施（所有模块前置，最先做）

- [ ] 币种精度工具库（`packages/money`）：15 币种小数位（JPY/KRW 整数、其余 2 位）、汇率 8 位小数（勘误：原写 4 位，以 doc 02/05 为准）、Decimal 十进制乘除、仅最终结果舍入一次、正数舍入为 0 拦截入账
- [ ] 契约管线（替代 contracts 包）：后端 DTO 为唯一来源，前端 openapi-typescript 生成类型；新增 Currency 表 + seed（15 币种，引用 money 常量）+ 公开接口 GET /api/currencies；错误码由后端 DTO enum 经 OpenAPI 生成，不再手写共享类型
- [ ] Prisma schema 全量设计：User/Settings、Account、Transaction（买入）、Plan、Allocation、Usage、Correction（含修改历史）、Reminder、TermsConsent、DataRequest、账本起点
- [ ] 15 个计算例子 → 测试用例清单（作为各模块测试的断言依据）

## M3 外汇账户

## M4 买入交易

- [ ] 两种填法互算：本金+汇率 → 到账外币；本金+到账 → 反算汇率
- [ ] 手续费单列（本位币）：0 = 无手续费、留空 = 未知，未知≠0
- [ ] 关联计划（仅标记，不触发分配）
- [ ] 交易详情：数量/本金/手续费/成本 + 费用未明确提示

**前端**：首页快速录入表单、交易详情页

## M5 换汇计划

- [ ] 创建：目标币种/目标金额/预计使用日期/提前准备天数（默认 3 工作日，可调）/最晚准备日推算
- [ ] 分配上限两套公式：新增分配 = min(未分配余额， 还需准备金额)；修改总额 = min(还需使用金额， 未分配余额+原剩余分配)；超额提示但不自动截断（例 09）
- [ ] 确认时重新检查余额，草稿/预览不占资金
- [ ] 目标修改预览：低于已用拦截（例 08）、调高产生缺口不自动分配（例 06）、调低同步释放分配（例 07）、保留原目标与修改记录
- [ ] 完成：使用达标 + 剩余分配 0 → 用户确认（例 13）
- [ ] 取消：释放未使用分配，买入/使用记录保留
- [ ] 重新开启并提高目标：一次确认整体生效（例 14）

> 待确认项影响：改日期边界、已取消计划编辑 —— 先实现文档明确部分，改日期功能留接口。

## M6 分批准备

- [ ] 缺口计算：目标 − 已用 − 本计划剩余分配（最低 0）
- [ ] 默认 3 次，三种节奏：安心 50/30/20、均衡三等分（默认）、主动 20/30/50；仅剩 2 天降级（60/40、50/50、40/60）、1 天 100%、0 天不可生成
- [ ] 日期取可安排日期首/中/末，偶数中间取靠前
- [ ] 零头：前几次按币种最小单位向下取整、差额入最后一次、出现 0 金额不生成
- [ ] 安排变更：先预览新安排及影响，确认后替换，保留旧安排与实际记录

> 待确认项影响：工作日日历 —— 先用「仅跳过周末」简化实现 + WorkCalendar 接口抽象，日历确认后替换。

## M7 资金使用

- [ ] 记录使用：确认后扣账户余额 + 扣该计划分配，支持分次
- [ ] FIFO 使用成本：同日先初始持仓 → 再买入 → 后使用，同类按首次录入顺序
- [ ] 状态联动：资金已备齐 / 资金已使用完成 / 缺口（还需金额 = 目标 − 已用，最低 0）
- [ ] 使用更正——改小：差额回未分配余额，计划剩余分配不变，不自动恢复分配（例 02）
- [ ] 使用更正——改大：先用原剩余分配，不足从未分配补分配并立即使用，一次确认整体生效（例 03-05），不重复扣整笔
- [ ] 使用更正——改日期：校验新日期当时资金充足，重算 FIFO 成本与统计期间

> 待确认项影响：金额改 0、超目标使用、已完成计划改大 —— 分支先拦截并提示，确认后放开。

## M8 更正与日志（交易更正）

## 并行开发波次（worktree）

> 编号规则：`M<波次>.<序号>`，同一波次内的模块可各开一个 worktree 并行开发，
> 波次内全部合入 main 后才进入下一波次。

| 波次 | 可并行模块                                                                            | 前置 | 隔离性（改动的文件集）                                      |
| ---- | ------------------------------------------------------------------------------------- | ---- | ----------------------------------------------------------- |
| W0   | M0 基础设施（**串行，单独先做**）                                               | 无   | prisma/schema、`packages/money`、currency 模块、前端契约管线切换 |
| W1   | **M1.1** 认证与首次设置 ∥ **M1.2** 汇率                                  | M0   | `auth/`+`onboarding/` ∥ `rate/`（互不相交）          |
| W2   | **M2.1** 外汇账户 ∥ **M2.2** 账号与数据                                  | W1   | `account/` ∥ `account-data/`                           |
| W3   | **M3.1** 买入交易 ∥ **M3.2** 换汇计划                                    | W2   | `transaction/` ∥ `plan/`                               |
| W4   | **M4.1** 资金使用 ∥ **M4.2** 更正框架+交易更正                           | W3   | `usage/` ∥ `correction/`                               |
| W5   | **M5.1** 分批准备 ∥ **M5.2** 使用更正 ∥ **M5.3** 报告（成本摘要） | W4   | `prep-schedule/` ∥ `correction/`（续作）∥ `report/` |
| W6   | **M6.1** 提醒 ∥ **M6.2** 单计划 PDF                                      | W5   | `reminder/` ∥ `report/`（续作）                        |
| W7   | **M7.1** 首页与导航（前端整合）∥ **M7.2** E2E 全链路                     | W6   | `clients/chat-web/` ∥ `e2e/`                           |

### worktree 并行纪律（必须遵守）

1. **M0 必须先合入 main**：schema、money 包、契约生成产物是所有 worktree 的公共地基，禁止多人抢写
2. **schema 冻结**：W1 起 Prisma schema 只读，需要加字段/索引时停手，回主分支统一改后各 worktree rebase
3. **`app.module.ts` 是已知小冲突点**：各模块注册行由最后合并者统一处理，rebase 时勿强行保留两份
4. **一个 worktree 只做一个模块**：只改 `src/<自己的模块>/` + `test/api/<自己的模块>.spec.ts` + `test/helpers/`（只增不改）
5. **同模块续作（M5.2→correction、M6.2→report）不并行**：上一波完成合入后再开新 worktree 续作
6. **前端页面与所属模块同 worktree 开发**（M1 向导、M3 账户页等），M12 首页整合放 W7 统一做
