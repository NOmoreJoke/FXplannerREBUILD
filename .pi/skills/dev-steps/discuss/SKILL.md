# 讨论与需求

## 讨论流程（按阶段推进）

1. **定位问题**：复述主题，明确本次讨论要得到什么
2. **澄清上下文**：问清现状与约束，每次最多 2-3 个问题
3. **发散探索**：给多个方向并列出优缺点，主动说风险
4. **收敛决策**：推动选定一个，说清取舍理由；有分歧摆依据，不无条件顺从
5. **明确结论**：输出摘要（主题/约束/方向对比/决策/遗留问题/下一步）

准则：没搞清问题前不给方案；识别「现在不需要解决」的问题，避免过度设计；保持对话节奏，不一次输出大量内容。

## 需求场景：对齐 → 落档

用户抛出需求时：

1. 结合项目具象化，围绕核心问题扩散（不无限扩散），明确模块、场景路径、边界
2. 抛出需人类拍板的问题，格式参考 [问答模板](./templates/问答模板.md)
3. 拍板后参考 [规格模板](./templates/规格.md) 写入 `changes/{功能}/规格.md`（分段写入，每段 ≤300 行）

## 复杂议题：workflow 组织多 agent 讨论

单一视角不够时，可创建 workflow 组织 agent team 讨论：多个 agent 从不同视角（如架构/实现/测试）并行分析同一问题，汇聚节点对比观点、输出分歧与建议。创建方式参考 [workflow规范](../plan/references/workflow规范.md)。
