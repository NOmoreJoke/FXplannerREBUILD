# 规则提取流程

## 触发

用户说"提取规则"、"总结纠错"、"记住这个错误"

## 流程

1. **扫描对话**：找出用户的纠正（关键词：不对、错了、不要、禁止、必须）
2. **分析原因**：AI 为什么会犯这个错误
3. **生成规则**：用"必须/禁止"表述，一句话原因
4. **检查现有目录**：运行 `find .claude/rules -type f -name "*.md" | sort` 查看已有分类
5. **判断位置**：
   - 有合适的现有文件 → 更新该文件（追加或修改）
   - 有合适的目录但无对应文件 → 在该目录下创建新文件
   - 没有合适的目录 → 创建新的合适目录和文件
6. **展示确认**：给用户看规则建议和保存位置，确认后写入

## 输出格式

```

识别到 N 个纠错点：

### 纠错1：

- 错误行为：{AI做了什么}
- 根本原因：{为什么}
- 规则建议：
  **禁止**：xxx
  **原因**：xxx
- 建议位置：{路径}

确认写入？
```

## 规则文件格式

```markdown
---
title: 规则标题
description: 一句话描述
paths:
  - "适用路径/**"
---

## 规则名称

**禁止**：xxx
**原因**：xxx

**必须**：xxx
**原因**：xxx
```

## 约束

- 只提取硬性规则（必须/禁止），不提取建议
- 必须先运行 `find .claude/rules -type f -name "*.md"` 检查现有目录
- 检查是否已有类似规则，避免重复
- 优先更新现有文件，而不是创建新文件
- 必须用户确认后再写入
