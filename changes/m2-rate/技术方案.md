## 1. 数据如何获取（获取链路全景）

### 1.1 数据源：frankfurter（保留，M0 已定）

| 事项 | 说明 |
| --- | --- |
| 服务与地址 | `https://api.frankfurter.app`（欧洲央行 ECB 数据），免费无鉴权 |
| 最新报价 | `GET /latest?from={base}&to={t1,t2,…}`，一次可取多个目标币种；响应 `{ amount, base, date, rates: { CNY: 7.85, … } }`，`date` 为报价所属日（**日精度**） |
| 历史报价 | `GET /{start}..{end}?from=…&to=…` 按日序列（保留现状，供更正用） |
| 超时 | 5 秒（既有 `RATE_PROVIDER_TIMEOUT_TOKEN` 可覆盖），超时视为数据源不可用 |
| 更新节奏 | ECB 每个交易日更新一次（约 CET 16:00），**周末/节假日不更新，`date` 停留在最近交易日** |
| 币种能力 | 支持本文 15 币种中的 14 种；**TWD 不在 ECB 币种表**，请求返回 404 → 币对不支持（见 §4 错误语义） |

### 1.2 获取链路（单次查询）

```
请求 base+targets
  → 参数校验（15 币种、去重、剔除 base 自身 → 恒等报价）
  → 查本地库（ExchangeRate 表 = 持久化缓存层，无内存缓存）
  → 组内全部币对均在 5 分钟窗口内 → 直接返回（不外呼）
  → 任一过期/缺失 → 整组一次外呼 frankfurter（to=全部目标，天然同一时点）
      → 成功：逐币对 upsert 落库（原值 rate + source + observedAt）→ 返回
      → 404 / 响应缺某目标币种：该币对标记"不支持"，其余正常返回
      → 网络/5xx/超时：502 RATE_SOURCE_UNAVAILABLE + 库中最后报价时间
  → 同 base+targets 的回源进行中 → 后续请求复用进行中的结果（单飞，§3.3）
```

### 1.3 为什么要批量（同一时点的一组报价）

doc 02 要求「每次入账使用**同一时点的一组报价**，计算过程可以复核」。逐币对独立查询在不同时刻回源，可能混入不同 `date` 的报价，不满足该要求。frankfurter 一次 `from=X&to=A,B,C` 的响应中所有目标共享同一 `date`，**批量接口整组返回是满足"同一时点"的唯一干净方式**。初始持仓多币种核对（最终确认前重查）因此一次调用完成。

### 1.4 外呼量估算（确认不放大）

录入页 60 秒轮询走 5 分钟窗口内的缓存 → 命中不外呼；每个 `base` 组每 5 分钟最多 1 次外部调用（批量合并），叠加单飞去重后，单实例外部调用量 ≈ 币种组数 × 12 次/小时/组，可控。

## 2. 报价有效期基准（修正原方案，文档冲突裁决 ★ 待审核）

### 2.1 原方案的漏洞（自我否定）

原方案以 `createdAt`（行创建时间）为 5 分钟期限起点，并规定"同一份旧报价（observedAt 相同）upsert 不触碰 createdAt → 不延长有效期"。结合 frankfurter **日更**特性推演：5 分钟窗口过期 → 回源拿回**同一份**（ECB 日内不变）→ createdAt 不变 → 返回即又过期 → **每次请求都外呼，缓存机制死循环失效**。该设计与现实数据源矛盾，废弃。

### 2.2 修正后的裁决

- **窗口基准 = `ExchangeRate.updatedAt`**（Prisma `@updatedAt` 自动维护）＝「最后一次向数据源**确认**这份报价的时间」。
- 回源成功（无论拿到新份还是同一份）→ update 分支触碰 updatedAt → **窗口重置**。语义：这份报价刚被数据源确认为"当前最新报价"，它不是被洗白的旧数据。
- **doc 02「刷新后若仍拿到同一份旧报价，不延长有效期」的意图是防止"刷新洗白"——即把明知陈旧的报价伪装成新鲜的。本方案用三条规则守住该意图**：
  1. 响应始终如实返回 `observedAt`（报价所属日，可能是最近交易日，如周五的价在周一仍显示周五）；
  2. 窗口重置**仅发生在真实回源成功之后**，缓存命中绝不重置；
  3. 数据源不可达时**拒绝服务**（502 + 最后报价时间），绝不把过期缓存充当有效报价返回（doc 05：无有效报价不得入账）。
- `fresh` = `now < updatedAt + 5min`（严格小于，恰好满 5 分钟视为过期）。
- 前端展示语义：「报价日期 = observedAt（如实展示）+ 剩余有效时间 = validUntil − now（可计算）」，两者含义分离，不混用。

### 2.3 同币种恒等报价

base = target 时 rate 恒为 1，属数学事实而非数据源报价：本地直接生成（不外呼），落库方式与普通报价一致，observedAt 取当前时刻。

## 3. 关键实施细节

### 3.1 落库与查询

- upsert 键 `[base, quote, observedAt]`（M0 唯一约束）：同报价日重复确认更新 rate/source 并刷新 updatedAt；新报价日自然落新行，历史保留（`GET /rates/history` 不变，供更正）。
- 落库存**原始报价**（frankfurter 返回值转字符串，Decimal(20,10) 容纳）；响应 rate 用 money 包 `roundRateTo8` 输出 8 位（doc 02：显示与计算用 8 位值，原值与来源一并保存）。

### 3.2 接口契约（增量）

`GET /api/rates/latest/:base`（公开，同现状）：

| 参数 | 位置 | 说明 |
| --- | --- | --- |
| `base` | path | 15 币种之一 |
| `targets` | query，可选 | 逗号分隔，≤15 个 15 币种币种；**缺省 = USD（向后兼容）** |
| `refresh` | query，可选，默认 `false` | `true` 忽略窗口强制回源（录入页进入刷新、确认前重查用） |

- 单目标（缺省）：响应平铺 `{ base, target, rate, source, observedAt, validUntil, fresh }`（**移除** `rate_to_usd`/`fetched_at` 旧别名，前端业务代码未使用）。
- 多目标：响应 `items[]`，每项 `{ target, rate?, observedAt?, validUntil?, fresh?, error?: { code, message } }`，HTTP 整体 200、错误下沉到项（部分币对不支持不拖垮整组）；base 自身出现在 targets 中 → 恒等项。
- 错误：`400` 参数非法（币种不在清单、targets 超量）；`502 RATE_SOURCE_UNAVAILABLE`（单目标）或 items 中该项 error（多目标），响应体含 `lastObservedAt`。

前端行为映射：打开录入页 → `refresh=true` 取组报价；60 秒轮询 → 默认（窗口内命中缓存）；切后台暂停 → 纯前端，后端无感；最终确认前 → `refresh=true` 重查整组；改本位币 → 以新 base 重查（旧组作废由前端状态保证）。

### 3.3 并发单飞（single-flight）

窗口过期瞬间多个并发请求会同时回源。实现：进程内 `Map<"base:targets", Promise<结果>>`，进行中的回源被后续同键请求 await 复用，结束后清除。前提：单实例部署（M0 compose 现状即单实例）；多实例时退化为每实例一次外呼，可接受，不做分布式锁（防过度设计）。

### 3.4 不做的事（边界）

- 不做内存缓存层（DB 即缓存，60s 轮询查询量可忽略）；
- 不做定时预热任务（惰性按需拉取）；
- 不做用户手填汇率通道（doc 05 禁止）；
- 不改 history 行为（工作日完整性校验保留）。

## 4. 错误语义（doc 05 兜底）

| 场景 | HTTP | code | 语义 |
| --- | --- | --- | --- |
| 数据源 404 / 响应缺目标币种 | 422（items 内为项级 error） | `RATE_PAIR_UNSUPPORTED` | 数据源不提供该币对（如 TWD），重试无用 |
| 数据源网络失败 / 5xx / 超时 | 502 | `RATE_SOURCE_UNAVAILABLE` | 暂时不可用可重试；响应体含库中 `lastObservedAt`（取该币对最后一条报价时间，可为 null） |
| 币种参数不在 15 币种清单 | 400 | — | 参数错误 |

任何路径都不返回过期报价供入账；禁止 0 兜底、禁止手填汇率。

### 9.1 追加：dev 启动失败修复（2026-09-08，M0 遗留基线问题）

首次真实 `bun run dev` 暴露：`ERR_MODULE_NOT_FOUND ... money/src/currencies`。根因：money 包 `package.json` exports 直指 TS 源码，chat（CJS 产物）经 `require(esm)` + Node 类型剥离加载 money 源码时，ESM 相对导入**必须有显式扩展名**；而 tsc（bundler 解析）与 vitest（vite 解析）均容忍无扩展名，故测试全绿但运行时崩溃。修复（M0 基线勘误，非 schema 改动）：

- `packages/money/src/`：6 个文件的相对导入补 `.ts` 扩展（index/calc/rate/round + 2 个 spec）；
- `packages/money/tsconfig.json`：加 `noEmit` + `allowImportingTsExtensions`；
- `packages/typescript-config/nestjs.json`：加 `rewriteRelativeImportExtensions`（TS 5.7+，chat 为 emit 构建，允许跨包检查 money 源码中的 `.ts` 后缀导入且 emit 时自动重写）。

验证：money `tsc --noEmit` PASS；`nest build` exit 0；Node 运行时冒烟 `import('@fxplanner-new/money')` 成功（18 导出）；双包 vitest **27/27 + 130/130** 全绿。dev 需重启生效。
