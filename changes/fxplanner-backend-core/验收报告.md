### 数据库和迁移

- `services/chat/prisma/schema.prisma` 当前包含：`User`、`ExchangeRate`、`OtpChallenge`、`OtpIdentity`、`WorkflowCheckpoint`。
- `User.email`、`User.passwordHash` 改为可空，用于支持没有邮箱和密码的 OTP 独立账号。
- 新增 `services/chat/prisma/migrations/20260803170000_add_exchange_rates/migration.sql`。
- 新增 `services/chat/prisma/migrations/20260803190000_add_otp_and_workflow_checkpoints/migration.sql`。
- 删除旧的 `services/chat/src/database/migrations/20260721_add_workflow_checkpoints.sql`，`workflow_checkpoints` 已由 Prisma migration 统一管理。
- 使用 `prisma migrate diff --from-empty --to-schema-datamodel` 校验最终 Schema SQL，与 migration 链最终结构一致。

### 认证和 OTP

- 密码认证继续使用 bcrypt；注册/登录邮箱统一 `trim + lowercase`，避免大小写产生逻辑重复账号。
- 密码登录要求 `passwordHash` 非空，OTP 独立用户不会被当作密码用户登录。
- 新增 `POST /api/auth/otp/send-code`（发送登录验证码）和 `POST /api/auth/otp/login`（校验验证码并登录）；不再暴露语义含混的 `request/verify` 旧路由。
- OTP 验证码为 6 位数字，仅保存带独立密钥的 HMAC-SHA256；`OTP_CODE_SECRET` 必填且不得复用 `JWT_SECRET`。
- OTP 具备 5 分钟过期、错误次数上限、一次性消费、条件更新防并发重放。
- 同一目标重新请求 OTP 时，旧的未消费验证码会立即失效。
- 发送限流同时按目标和客户端 IP 限制；“限流检查、作废旧码、创建新码”在数据库事务中执行，并使用 PostgreSQL advisory lock 防并发绕过。
- `OtpIdentity(channel,target)` 唯一；OTP 首次验证会创建没有邮箱和密码的独立 User，同一 identity 后续复用同一 OTP User，不查询或合并密码账号。
- JWT strategy 增加 payload 基本校验，并继续只选择公开用户字段。

### 前端和契约

- `packages/contracts/src/auth/` 新增共享 Auth/OTP 类型，前端不再重复定义认证契约。
- `/login` 增加“密码登录 / 验证码登录”双入口；验证码登录支持 email/phone channel、发送冷却和 6 位数字输入。
- `apiClient` 对 `skipAuth` 的 401 响应不自动跳转，登录页可以就地展示“密码错误/验证码错误”。

### 汇率缓存

- 最新汇率：24 小时内的数据库记录直接命中；过期或缺失时调用 Frankfurter，并按 `(base,quote,observedAt)` upsert。
- 历史汇率：先查数据库；缓存完整时直接返回；部分缓存不再直接返回，而是继续调用 Provider 补齐后按 `skipDuplicates` 写回。
- 完整性按 Frankfurter 的工作日报价粒度判断：周六/周日不要求有报价，当前 UTC 日也不要求已入库，避免在供应商发布当日数据前反复请求。
- 相同币种的历史查询保留本地恒等汇率特殊处理。
