## 2. 方案

### 2.1 登录邮箱-only + 邮件 Mock（R1/R2）

```
前端 login-form                 后端
┌────────────────┐   send-code  ┌──────────────────┐
│ 密码登录        │─────────────▶│ OtpService       │
│ 验证码登录(邮箱)│◀─────────────│  └ EmailChannel  │── devMode? → console.log([MOCK])
└────────────────┘ {devCode?}   └──────────────────┘
  devCode 自动填充+toast 提示
```

- `otp-channel.ts`：接口增加可选 `readonly devMode?: boolean`。
- `email-otp.channel.ts`：`mockEnabled = env.OTP_EMAIL_MOCK === "true" || (NODE_ENV !== "production" && 未配置 RESEND_API_KEY/RESEND_FROM_EMAIL)`；mock 时 `send()` 打印 `[MOCK] 发送邮件 to=… code=…`，`devMode = true`；非 mock 行为不变（未配置 key → 503）。
- `otp.service.ts`：`sendCode` 对 `channel.devMode` 的渠道，返回值附加 `devCode`。
- `otp-challenge-result.dto.ts`：可选 `devCode`（Swagger 标注 dev only）。
- `config/env.ts`：新增可选 `OTP_EMAIL_MOCK`（"true"/"false"）。
- 前端 `login-form.tsx`：删除渠道切换按钮组与 E.164 校验；响应含 `devCode` 时 toast「验证码已发送（模拟）：xxxxxx」并自动填入输入框（本地演示/E2E 依赖）。

### 2.2 统一面包屑（R3）

- 新增 `components/base/app-breadcrumb.tsx`（base 层，单向依赖 ui/breadcrumb）：
  - `usePathname()` + 静态映射表渲染；动态段按配置渲染（`:id` → 计划详情/交易详情；`:currency` → 币种大写）；
  - 未知路径兜底显示段落原名；末级 `aria-current="page"` 不可点。
- `(protected)/layout.tsx`：`main` 顶部统一渲染面包屑条（底边框 + 统一 padding），子页面零改动自动获得。

映射表：`/home`→首页；`/accounts`→外汇账户；`/accounts/:c`→外汇账户/`{C}` 账户详情；`/plans`→换汇计划；`/plans/new`→换汇计划/新建计划；`/plans/:id`→换汇计划/计划详情；`/transactions/new`→快速录入；`/transactions/:id`→交易详情（交易无父级列表页，面包屑单级，不造假链接）。

### 2.3 菜单高亮 + Logo（R4/R5）

- active：`bg-mint-700 text-white`（icon 同步），hover 态不变；匹配规则 `/home` 精确、其余 `startsWith`（已有逻辑保留）。
- Logo：`<Link href="/home">` + hover 反馈 + `aria-label="回到首页"`。

## 4. 测试设计（红线：0 failed + 附证据）

### 4.1 后端单测（vitest，随服务跑）

- `otp.service.spec.ts`：devMode channel → 响应含 `devCode`；真实 channel → 不含 `devCode`（防泄漏）。
- `email-otp.channel` mock 行为：dev 未配置 key → `devMode=true`、send 不抛错；显式 `OTP_EMAIL_MOCK=false` → 维持 503。

### 4.2 E2E（Playwright headed，真实前后端）

| 编号 | 文件 | 覆盖流程 |
| ---- | ---- | ---- |
| 01-auth（已有） | 注册成功/重复邮箱/登录成功/密码错误/落地页公开与跳转/登出 |
| 02-account（已有） | 账户列表三值/详情流水/行级跳转/空态引导 |
| 03-plan（新） | 创建计划 → 列表可见 → 详情可见 → 状态筛选 |
| 04-transaction（新） | 计划详情「录入买入」→ 表单填写提交 → 交易详情金额一致 |
| 05-otp-login（新） | 邮箱验证码登录（mock devCode 取码）→ 登录成功进 /home |
| 06-navigation（新） | 菜单高亮断言（首页/计划子页面）、面包屑渲染断言（多级/动态段）、Logo 点击回 /home |

截图策略：`e2e/helpers/save-screenshot.ts` 统一存 `e2e/test-results/screenshots/<模块>/<编号>-<节点>.png`（关键页面必截）；auto-screenshot fixture 步骤截图照旧。

### 4.3 运行方式

`e2e/scripts/run-e2e-tests.sh --headed`：清理端口 → `bun run dev`（turbo 同时拉起前后端）→ 健康检查（后端 /api/health、前端 3001）→ `playwright test --headed` → 截图/日志/报告汇总 → 关闭服务。AI 不手工持有服务进程，生命周期全部由脚本管理。

## 5. 验收标准

1. 登录页无手机号入口；邮箱验证码登录在未配置 Resend 的 dev 环境可完整走通（验证码见服务端日志 + 前端自动填充）。
2. 所有 (protected) 子页面顶部出现统一风格面包屑，动态路由显示语义化名称。
3. 侧边栏当前模块菜单项深绿高亮，子页面（如 /plans/[id]、/accounts/[currency]）同样高亮。
4. Logo 点击回到 /home。
5. E2E 全部 0 failed，headed 运行过程可见，关键页面截图留存于 `e2e/test-results/screenshots/`。
