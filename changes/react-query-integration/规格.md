# React Query 数据请求升级规格说明书

> 规格只写「用户/业务能得到什么」，用业务语言。

## 一、引言

### 1.1 编写目的与读者

本规格面向开发团队，用于对齐前端数据请求方案升级的需求与验收标准。

### 1.2 项目背景

当前系统使用原生 fetch 封装的 apiClient，每个页面需手动管理 loading/error 状态，无缓存机制。已安装 `@tanstack/react-query` 但未使用。需升级为统一的数据请求层，提升开发效率和用户体验。

### 1.3 术语与缩写

- **React Query / TanStack Query**：前端数据同步库
- **Query**：查询操作（GET）
- **Mutation**：变更操作（POST/PUT/DELETE）
- **乐观更新**：请求发出前先更新 UI，失败后回滚

## 二、总体描述

### 2.1 系统目标

将现有的手动 fetch + useState 模式升级为 React Query 统一管理，实现：

- 自动缓存、重试、后台刷新
- 消除重复的 loading/error 状态管理代码
- 支持乐观更新提升交互体验

### 2.2 用户角色

| 角色 | 能得到什么 |
| --- | --- |
| 登录用户 | 页面切换时数据即时显示（缓存），网络失败自动重试，无需手动刷新 |
| 开发者 | 减少 60% 数据请求相关代码量，统一的错误处理和加载状态 |

### 2.3 边界（明确不做什么）

- 不改变后端 API 接口
- 不涉及 WebSocket / SSE 实时数据流
- 不改变现有的路由守卫逻辑

## 三、功能需求

### 模块1：React Query 基础设施

1. **能力简述**：在应用根布局配置 QueryClientProvider
2. **业务流程**：应用启动 → 初始化 QueryClient → 所有子组件可使用 useQuery/useMutation
3. **核心场景与验收路径**：

   **系统行为型**：
   > `当应用启动 → 预期：QueryClient 正确初始化，控制台无错误，React Query Devtools 可在开发环境打开`

4. **配置要求**：
   - 默认缓存时间 5 分钟
   - 失败自动重试 1 次
   - 窗口重新获得焦点时自动刷新数据

### 模块2：项目列表查询升级

1. **能力简述**：将 `/projects` 页面的项目列表请求改为 useQuery
2. **业务流程**：进入页面 → 自动加载项目列表 → 5 分钟内再次进入直接显示缓存
3. **核心场景与验收路径**：

   **用户操作型**：
   > `项目列表页 初次加载 → 预期：显示 loading 状态，数据加载后展示项目卡片`

   > `项目列表页 加载后离开再返回 → 预期：立即显示缓存数据（无 loading），后台静默刷新`

   > `项目列表页 网络失败 → 预期：自动重试 1 次，失败后显示错误提示`

### 模块3：项目增删改 Mutation

1. **能力简述**：将创建/删除/重命名项目改为 useMutation + 乐观更新
2. **业务流程**：
   - 创建：点击创建 → UI 立即显示新项目 → 请求成功则保留 / 失败则回滚并提示
   - 删除：点击删除 → UI 立即移除项目 → 请求失败则恢复并提示
   - 重命名：提交新名称 → UI 立即更新 → 请求失败则恢复并提示
3. **核心场景与验收路径**：

   **用户操作型**：
   > `项目列表页 点「+ 创建项目」→ 填写名称提交 → 预期：新项目立即出现在列表顶部，不等后端响应`

   > `项目列表页 创建项目时网络断开 → 预期：新项目先出现后消失，显示错误提示`

   > `项目卡片 点删除确认 → 预期：卡片立即消失，网络失败则恢复并提示`

   > `项目卡片 重命名提交 → 预期：名称立即变化，失败则恢复旧名称`

### 模块4：认证状态查询

1. **能力简述**：将 `/me` 用户信息请求改为 useQuery
2. **业务流程**：应用启动/刷新 → 自动获取用户信息 → 缓存复用
3. **核心场景与验收路径**：

   **系统行为型**：
   > `当用户刷新页面 → 预期：用户信息从缓存立即显示，后台验证 token 有效性`

   > `当 token 过期（401） → 预期：清除缓存，跳转登录页`

## 四、非功能需求

### 4.1 性能

- 缓存命中时数据显示延迟 < 50ms（同步读取）
- 列表页首次加载时间不增加（与当前持平）

### 4.2 开发体验

- 减少单个列表页数据请求代码从 ~30 行降至 ~10 行
- 统一错误处理，无需每个请求写 try-catch
- 开发环境提供 React Query Devtools 调试

### 4.3 向后兼容

- 保持现有 apiClient 函数签名不变
- 不影响未迁移的页面（渐进式升级）
