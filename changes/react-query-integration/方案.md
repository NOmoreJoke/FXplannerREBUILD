# React Query 数据请求升级技术方案

## 一、整体概述

将前端数据请求层从原生 fetch + 手动状态管理升级为 React Query 统一管理。核心思路：

1. 在根布局配置 QueryClientProvider
2. 封装 useQuery/useMutation hooks 复用 apiClient
3. 渐进式迁移现有页面（先项目列表，后续可扩展）

## 二、全局架构 & 数据流

```
app/layout.tsx (根布局)
└── QueryClientProvider (new)
    ├── 配置：缓存 5min、重试 1 次、窗口聚焦刷新
    └── ReactQueryDevtools (dev only)

页面组件
├── useQuery → queryFn: apiClient.get → 自动管理 loading/error/data
└── useMutation → mutationFn: apiClient.post/put/delete
    └── onMutate: 乐观更新
    └── onError: 回滚 + toast
    └── onSuccess: 刷新缓存
```

**选型理由**：

- React Query 已安装，功能完整（Mutation/Devtools/类型推导）
- 与 Next.js App Router 兼容（服务端组件用原生 fetch，客户端组件用 React Query）
- 社区成熟，适配中大型项目


**核心逻辑**：

```typescript
// lib/query/config.ts
export const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 5 * 60 * 1000,      // 5 分钟内视为新鲜
      gcTime: 10 * 60 * 1000,        // 10 分钟后垃圾回收
      retry: 1,                       // 失败重试 1 次
      refetchOnWindowFocus: true,     // 窗口聚焦时刷新
    },
    mutations: {
      retry: 0,                       // Mutation 不重试
    },
  },
});

// lib/query/provider.tsx
'use client';
export function QueryProvider({ children }) {
  return (
    <QueryClientProvider client={queryClient}>
      {children}
      {process.env.NODE_ENV === 'development' && <ReactQueryDevtools />}
    </QueryClientProvider>
  );
}
```

**异常/降级**：

- QueryClient 初始化失败 → 抛出错误，阻止应用启动（符合预期）
- Devtools 仅开发环境加载，生产环境不引入

**测试设计**：

- 单元：`lib/query/config.spec.ts` (1 个用例，验证 QueryClient 配置正确)
- 集成：参与链路 A（项目列表查询）

### 模块2：项目列表查询升级

**文件变更**：

```plain
clients/chat-web/
├── + lib/query/
│   └── + hooks/
│       └── + use-projects.ts    # useProjects / useCreateProject / useDeleteProject / useUpdateProject
├── # app/(protected)/projects/page.tsx
│   ├── - useState / useEffect   # 删除手动状态管理
│   ├── + useProjects()          # 替换为 hook

│   ├── # handleDeleteProject()  # 调用 useDeleteProject
│   └── # handleRenameProject()  # 调用 useUpdateProject
└── # lib/api/projects.ts
    └── # 保持不变                # apiClient 函数签名不变
```

**核心逻辑**：

```typescript
// lib/query/hooks/use-projects.ts
export const PROJECTS_QUERY_KEY = ['projects'];

// 查询 hook
export function useProjects() {
  return useQuery({
    queryKey: PROJECTS_QUERY_KEY,
    queryFn: async () => {
      const response = await projectsApi.getAll();
      return response.data || [];
    },
  });
}

// 创建 hook（乐观更新）
export function useCreateProject() {
  const queryClient = useQueryClient();
  return useMutation({
    mutationFn: projectsApi.create,
    onMutate: async (newProject) => {
      // 取消进行中的查询
      await queryClient.cancelQueries({ queryKey: PROJECTS_QUERY_KEY });
      
      // 快照当前数据
      const previousProjects = queryClient.getQueryData(PROJECTS_QUERY_KEY);
      
      // 乐观更新
      queryClient.setQueryData(PROJECTS_QUERY_KEY, (old: Project[]) => [
        { ...newProject, id: 'temp-' + Date.now(), createdAt: new Date(), updatedAt: new Date() },
        ...(old || []),
      ]);
      
      return { previousProjects };
    },
    onError: (err, newProject, context) => {
      // 回滚
      queryClient.setQueryData(PROJECTS_QUERY_KEY, context?.previousProjects);
      toast.error(err.message || '创建失败');
    },
    onSuccess: () => {
      toast.success('创建成功');
    },
    onSettled: () => {
      // 无论成功失败，都重新获取
      queryClient.invalidateQueries({ queryKey: PROJECTS_QUERY_KEY });
    },
  });
}

// 删除和更新 hook 同理
```

**异常/降级**：

- 网络失败 → 自动重试 1 次，失败后显示错误 toast（由 onError 处理）
- 乐观更新失败 → 回滚到 previousProjects 快照

**测试设计**：

- 单元：`lib/query/hooks/use-projects.spec.ts` (4 个用例：查询成功/失败、创建乐观更新/回滚)
- 接口：`services/chat/test/api/project.spec.ts` (已存在，保持不变)
- 集成：参与链路 A

**核心逻辑**：

```typescript
// lib/query/hooks/use-auth.ts
export const CURRENT_USER_QUERY_KEY = ['auth', 'me'];

export function useCurrentUser() {
  return useQuery({
    queryKey: CURRENT_USER_QUERY_KEY,
    queryFn: authApi.getCurrentUser,
    staleTime: 10 * 60 * 1000,    // 用户信息缓存 10 分钟
    retry: false,                  // 401 不重试，直接跳转登录
  });
}

// 登出时清除缓存
export function useLogout() {
  const queryClient = useQueryClient();
  return () => {
    authApi.logout();
    queryClient.clear();          // 清除所有缓存
  };
}
```

**异常/降级**：

- 401 错误 → apiClient 已有处理逻辑（清除 token + 跳转登录），无需额外处理
- 网络失败 → 不重试，显示错误状态

**测试设计**：

- 单元：`lib/query/hooks/use-auth.spec.ts` (2 个用例：查询成功、401 清除缓存)
- 集成：参与链路 B（认证流程）

## 五、风险与对策

| 风险                                   | 对策                                                   |
| -------------------------------------- | ------------------------------------------------------ |
| 乐观更新后服务端返回数据与预期不一致   | onSettled 中强制 invalidateQueries 重新获取真实数据   |
| 多个 Mutation 并发执行导致缓存冲突     | 使用 cancelQueries 取消进行中的查询，串行化更新        |
| 服务端组件误用 useQuery（App Router）  | 明确约定：服务端组件用原生 fetch，客户端组件用 React Query |
