# AI 助手（对话 + ReAct Agent）需求规格说明书（SRS）

> 规格只写「用户/业务能得到什么」，用业务语言。
> 不写 API、命令、状态码、数据库——那些是技术方案的事。
> 铁律：预期必须可判定，禁止"体验良好""响应快"这类虚词。

## 一、引言

### 1.1 编写目的与读者

本文档用于与产品/开发对齐「AI 助手」模块的业务范围与验收标准，是技术方案与测试设计的输入。读者：项目所有者、前后端开发、测试。

### 1.2 项目背景

FXPlanner 是面向有外币兑换需求用户的工作台。本次新增 AI 助手：用户在菜单栏进入对话界面，用自然语言询问汇率相关问题（当前价格、历史走势等），后端由具备「汇率数据查询」工具的 ReAct 模式智能体回答。

### 1.3 术语与缩写

| 术语 | 含义 |
| --- | --- |
| ReAct 模式 | 智能体「思考 → 调用工具 → 观察结果 → 再思考/作答」的循环工作模式 |
| 汇率工具 | 智能体唯一可调用的数据能力：查询最新汇率与历史区间汇率 |
| 会话 | 一次完整的多轮对话及其全部消息，归属于创建它的用户 |
| 本位币 | 用户在引导流程中选定的基准币种 |

## 二、总体描述

### 2.1 系统目标

为登录用户提供一个菜单可达的 AI 对话入口：能以自然语言获得准确的汇率数据回答（最新价与历史区间），对话按用户持久保存、可随时回看与继续。

### 2.2 用户角色

| 角色 | 能做什么 |
| --- | --- |
| 未登录用户 | 不可见此模块；直接访问对话页跳转登录页 |
| 登录用户 | 发起/继续对话、查看与删除自己的历史会话；只能看到自己的会话 |

### 2.3 边界（明确不做什么）

- 智能体本期**只有一个工具**：汇率数据查询（最新 + 历史区间）。不接交易、计划、账户等任何其他内部数据。
- 聊天内**不做图表渲染**（汇率走势图由独立的「汇率行情」页承担，见 `changes/rate-chart/规格.md`）。
- 不做用量计量、限额与计费（是否接入现有 usage 模块由技术方案评估，本期不实现）。
- 不做多模态（图片/语音/文件输入）。
- 不做会话分享、导出。
- 不做智能体人设/温度等面向用户的可配置项。

## 三、功能需求（按模块）

### 模块1：AI 对话页（菜单入口与聊天界面）

1. **能力简述**：保护区菜单栏新增「AI 助手」入口，进入后是与智能体的多轮文字聊天界面。
2. **业务流程**：登录 → 点菜单「AI 助手」→ 进入对话页 → 输入消息发送 → 逐字看到回复 → 可继续追问。
3. **核心场景与验收路径**：

   > `登录 → 点菜单「AI 助手」→ 预期：进入对话页，菜单项「AI 助手」高亮，界面含消息区、输入框、发送按钮、「新建对话」入口`
   >
   > `对话页 输入"你好"并发送 → 预期：我的消息立即出现在消息区，回复以流式逐步呈现（发送后 5 秒内出现首个文字，而非长时间空白后一次性出全文）`
   >
   > `输入框为空时点发送 → 预期：不发出任何消息，输入框保持聚焦`
   >
   > `智能体处理期间 再次点发送 → 预期：处于禁用状态（或消息排队提示），不出现回复交叉错乱`
   >
   > `未登录状态直接访问对话页 → 预期：跳转登录页并带回跳地址`

4. **权限与状态规则**：页面位于登录保护区，复用现有守卫，页面本身不写校验代码。

### 模块2：汇率智能体（ReAct Agent）

1. **能力简述**：智能体基于唯一工具「汇率数据查询」回答汇率问题：支持查询指定币种对的最新价，以及指定币种对在历史区间内的走势描述。
2. **业务流程**：用户提问 → 智能体判断是否需要数据 → 需要则调用汇率工具（可能多次）→ 综合结果用自然语言回答 → 回复中体现数据的时间点。
3. **核心场景与验收路径**：

   > `问"现在美元兑日元是多少" → 预期：回复包含 USD→JPY 的具体数值，且该数值与「汇率行情」页展示的最新价一致，并注明数据时间`
   >
   > `问"过去30天欧元兑人民币走势怎么样" → 预期：回复包含该区间的走势描述（至少含起止值或最高/最低值），与行情页同区间数据一致；若该币对暂无历史数据积累，回复须如实说明，不得编造走势`
   >
   > `一次问多个币种（"美元兑人民币和日元分别多少"） → 预期：一条回复同时给出两组数值`
   >
   > `问不支持的币种（"比特币现在多少"） → 预期：回复明确提示无法查询该币种，并说明可查询范围，不编造数值`
   >
   > `问与汇率无关的问题（如"帮我写首诗"） → 预期：正常给出非数据回复，不强行报汇率错误，也不调用汇率工具`
   >
   > `当汇率数据源暂不可用 → 预期：回复明确说明当前拿不到数据并建议稍后再试，不编造数值`

4. **权限与状态规则**：智能体仅代表当前登录用户工作；工具查询不区分用户（汇率是公共数据）。

### 模块3：会话管理（历史持久化）

1. **能力简述**：对话按用户持久保存；提供历史会话列表，可切换、新建、删除会话。
2. **业务流程**：发送首条消息 → 生成会话并进入左侧（或顶部）会话列表 → 点列表项切换会话 → 点「新建对话」开始新会话 → 可删除不需要的会话。
3. **核心场景与验收路径**：

   > `新会话发出首条消息 → 预期：会话出现在列表中，标题取自首条消息的摘要，无需用户手动命名`
   >
   > `对话页 刷新浏览器 → 预期：会话列表仍在，当前会话的消息完整可见，可继续追问`
   >
   > `点列表中另一个会话 → 预期：消息区切换为该会话的历史消息，顺序正确`
   >
   > `点「新建对话」→ 预期：进入空白新会话，原会话保留在列表中`
   >
   > `删除某会话（含确认）→ 预期：从列表消失；刷新页面后不再出现；其他会话不受影响`
   >
   > `用户 A 登录 → 预期：只能看到 A 自己的会话，看不到用户 B 的任何会话`

4. **权限与状态规则**：会话严格归属创建用户；删除为物理删除或标记删除由技术方案定，但删除后对所有入口不可见。

## 四、非功能需求

### 4.1 性能

- 回复流式输出：发送后首字出现 < 5s；汇率工具命中表缓存时 < 1s，需回源补齐时受上游源限制（单次外呼最长约 6s），此时助手须明确说明数据暂不可得，不得让用户无反馈等待
- 会话列表加载 < 2s；历史会话消息加载 < 2s；发送频率限制（每分钟/每日配额）超出时收到明确的友好提示

### 4.2 安全

- 仅登录用户可用；会话按用户严格隔离（越权访问他人会话 → 拒绝）。
- LLM 的 key 与端点配置仅存服务端环境变量，任何情况下不下发到浏览器。
- 用户消息内容仅用于本次对话处理与会话存储，不用于其他用途。

### 4.3 运行环境

- 与现有 chat-web 一致：现代桌面浏览器（Chrome/Edge/Safari 最新两个大版本）；移动端可用但不做专门优化。
