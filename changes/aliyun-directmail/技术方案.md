# OTP 邮件通道接入阿里云邮件推送（DirectMail SMTP）

## 背景与决策

- 原邮件 OTP 通道基于 **Resend HTTP API**（`RESEND_API_KEY` 等），本地从未配置、一直处于 mock 模式。
- 参照 LingJi 项目（`LingJi/services/chat/src/auth/mail/`）的成熟做法，切换为**阿里云邮件推送 DirectMail SMTP + nodemailer**。
- 决策：**直接替换**而非并存。理由：Resend 从未启用、保留双通道徒增维护成本（YAGNI）；`OtpChannel` 接口不变，OtpService/频控/验证链路零改动。

## 行为语义（保持不变）

- **mock 降级**：`OTP_EMAIL_MOCK=true` 强制 mock；非生产 && 未配置 `SMTP_USER/SMTP_PASS` → 自动 mock（验证码打日志 + 响应带 `devCode`，E2E/本地联调依赖）；生产永不 mock，未配置抛 503。
- **错误分类**：SMTP 发送失败 → 502 BadGateway；超时 → 503 ServiceUnavailable。
- **频控/验证码规则**（有效期、发送上限、输错锁定）不变，由 OtpService 承载。

## 人工操作步骤（接入阿里云）

1. 开通服务：阿里云控制台 → 邮件推送（DirectMail）→ 开通服务。
2. 创建发信域名：邮件推送 → 发信域名 → 新建（如 `mail.<你的域名>.com`）→ 按提示在 DNS 添加 SPF/DKIM/MX 记录 → 点击「验证」直至通过。
3. 创建发信地址：邮件推送 → 发信地址 → 新建（如 `noreply@mail.<你的域名>.com`）→ 类型选「SMTP」→ 设置 SMTP 密码（只显示一次）。
4. 配置环境变量：编辑 `services/chat/.env.local`，填入：

   ```bash
   SMTP_HOST=smtpdm.aliyun.com
   SMTP_PORT=465
   SMTP_USER=noreply@mail.<你的域名>.com
   SMTP_PASS=<SMTP密码>
   SMTP_FROM_NAME=FXPlanner
   ```

5. 重启后端（`bun run dev`），在前端登录页发送邮箱验证码，到收件箱确认收到真实邮件。
6. 生产环境：在部署环境注入同样 5 个变量（生产未配置会因「永不 mock」直接 503，不会静默假发送）。

> 退信/收不到：先查垃圾箱；再在阿里云控制台「发送记录」查投递状态；新域名有 72 小时信誉预热期，失败率高属正常。

## 追加修复（E2E 链路，2026-09-21）

接入真实 SMTP 后首轮 E2E 暴露 14 个失败，根因两个（均与 SMTP 实现无关）：

1. **turbo 严格环境变量白名单**：`turbo.json` 的 `tasks.dev.env` 未声明 `OTP_EMAIL_MOCK`，E2E 脚本 export 的开关被 turbo 过滤，dev 后端拿不到 → 走真实发信且无 `devCode` → OTP 登录/账号数据/建账向导 10 个用例失败。修复：白名单补 `OTP_EMAIL_MOCK`。
2. **E2E 注册用例与前端脱节**（存量）：注册表单的合规勾选拦截（onboarding-rework）落地后，`01-auth.spec.ts` T-AUTH-001 未同步勾选 → 请求被前端拦截 → 注册/登出/落地页 4 个用例连锁失败。修复：用例补勾 `consent-age18` / `consent-terms`。

**最终验收**：E2E 全量 **49/49 通过（0 failed，10.0 分钟）**，运行日志含 13 条 `[MOCK]` 发送记录（mock 生效证据）；`services/chat` 单测 689 通过；真实发信连通性测试通过（收到真实邮件）。
