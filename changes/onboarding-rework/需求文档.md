# 首次设置重构（登录即用 + 最小建账 + 偏好后置）需求文档

> Mini 档：变更描述 + 术语表 + 验收标准。详细模块规则见同目录 `规格.md`。

## 1. 需求概述

**用户故事**：作为新用户，我想登录后立即开始使用产品，以便不被冗长的首次设置拦路；我持有的外币和个人偏好可以之后再补充、随时调整。

**业务价值**：新用户登录并输入验证码后（此两屏维持不变），强制经过的设置类页面从最多 6 屏减为最多 2 屏（确认本位币 → 初始持仓选填可跳过）；偏好类设置从「只在首次设置出现一次」变为「随时可改」。

**范围边界**：

- ✅ 本次包含：登录页两项确认（已满 18 周岁、已阅读并同意服务条款与隐私说明）；最小建账向导（地区与本位币确认 + 初始持仓选填、可跳过）；初始持仓补录（空账本状态下从首页/外汇账户入口录入）；设置页（地区、语言、准备偏好、准备提醒随时改，本位币只读展示）
- ❌ 本次不包含：本位币建账后更换（不做，涉及历史成本重算，如开放另行立项）；设置草稿（不做，向导中断下次从头填）；邮箱等账号资料变更（不做）

## 2. 术语对照表

| 业务术语 | 本次含义界定 |
| ---------- | -------------- |
| 建账 | 未完成设置的用户确认本位币并完成初始设置的动作；完成时刻即记账起点 |
| 记账起点 | 账本开始时刻，等于建账完成时刻；不由用户回填到过去 |
| 初始持仓 | 建账或补录时确认的「某币种现在实际持有的金额」，按确认时刻的汇率折算初始成本 |
| 有效汇率 | 建账/补录确认时刻可采用的官方渠道报价（来源、币种方向、报价时间齐全且未超过 5 分钟），规则详见规格与 docs 02 |
| 补录初始持仓 | 建账时未填写初始持仓，之后第一次录入（从无到有）；每币种仅一笔 |
| 更正初始记录 | 已有初始记录后的修改（从有到改），沿用既有更正规则 |
| 偏好 | 地区、语言、准备偏好（安心/均衡/主动）、准备提醒开关；随时可改，无记账后果 |
| 空账本 | 已建账但没有任何初始持仓记录的状态，此状态显示补录引导 |

## 3. 验收标准

**登录门槛**

- **场景 1（边界）**：假如任一项确认未勾选，当点击发送验证码，那么验证码不发出，且发送按钮不可用并提示「请先勾选确认 age 与条款」。
- **场景 2（正常）**：假如两项已确认且验证码输入正确，当登录，那么未建账用户进入建账向导，已建账用户直接进入首页（或登录前正在浏览的页面）；正在清空数据或注销的账号进入对应进度页。

**建账向导**

- **场景 3（边界）**：假如已在向导第二步填写外币金额，当返回第一步修改本位币，那么已显示的汇率和初始成本作废，金额保留，页面重新展示核对内容供用户确认。
- **场景 4（正常）**：假如在向导第二步填写外币金额并在核对页确认入账，当建账完成，那么进入首页，且能看到对应币种的初始金额记录在未分配余额中。
- **场景 5（正常）**：假如在第二步选择「没有，直接开始」，当完成建账，那么进入首页，且首页出现补录初始持仓引导卡。
- **场景 6（异常）**：假如在向导第二步中途退出，当下次登录，那么重新从第一步开始，无上次填写残留。
- **场景 7（边界）**：假如建账已完成，当在产品任何页面寻找修改本位币的入口，那么找不到；设置页本位币仅展示并注明不可更换。
- **场景 8（异常）**：假如已建账用户拒绝新版重要条款，当登录，那么只能查看已有记录、导出、删除数据或注销，不能新增或修改业务记录。

**初始持仓补录**

- **场景 9（正常）**：假如用户处于空账本状态，当从引导卡进入补录并确认，那么按确认时刻的有效汇率折算初始成本入账，金额先进入未分配余额。
- **场景 10（异常）**：假如填写的补录金额会导致记账起点之后某一天资金不足，当点击确认提交，那么无法提交，并显示该日期与缺少的金额。
- **场景 11（边界）**：假如用户已存在任一币种的初始记录，当查看首页和外汇账户页，那么不出现补录入口；漏填币种只能走更正流程。

**设置页**

- **场景 12（正常）**：假如把语言改为英文并保存，当切换完成，那么界面语言变化，记账币种不变，同一版本条款不要求重新同意。
- **场景 13（正常）**：假如把准备偏好改为「安心」并保存，当保存成功，那么已有计划的目标、分配、状态不受任何影响。
- **场景 14（正常）**：假如关闭准备提醒并保存，当保存成功，那么不再收到准备/使用提醒，且计划状态页面仍正常展示。
