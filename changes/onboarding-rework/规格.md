# 首次设置重构（登录即用 + 最小建账 + 偏好后置）需求规格说明书（SRS）

> 规格只写「用户/业务能得到什么」，用业务语言。
> 技术方案另出（本文档不含 API、数据库设计）。
> 依据：2026 年讨论拍板。V2.5 原型「登录与初始化」「设置」两排画板为目标形态。

## 一、引言

### 1.1 编写目的与读者

本文档用于对齐首次设置流程重构的范围与验收标准。读者：产品、前端/后端开发、测试。

### 1.2 项目背景（决策演化链）

首次设置方案经历三次演化，本变更为第三次，**取代前两次的相关决策**：

### 1.3 术语与缩写

| 术语 | 含义 |
| --- | --- |
| 建账 | 未完成设置的用户确认本位币并完成初始设置的动作；完成时刻即记账起点 |
| 记账起点 | 账本开始时刻 = 建账完成时刻；不由用户回填（沿 docs 02） |
| 初始持仓/初始记录 | 建账或补录时确认的「某币种现在实际持有金额」，按确认时刻汇率折算初始成本 |
| 补录初始持仓 | 建账时未填写初始持仓，之后从首页/外汇账户入口第一次录入（从无到有） |
| 更正初始记录 | 已有初始记录后的修改（改金额/币种/改 0），沿 docs 02 既有规则（从有到改） |
| 偏好 | 地区、语言、准备偏好（安心/均衡/主动）、准备提醒开关——均可随时改，无记账后果 |

## 二、总体描述

### 2.1 系统目标

新用户登录后即可使用产品：登录页完成年龄与条款确认，建账向导只强制确认一次本位币，初始持仓可跳过、以后补录；地区/语言/偏好/提醒全部在设置页随时修改。已建账用户行为不受影响。

### 2.2 用户角色

| 角色 | 能做什么 |
| --- | --- |
| 未登录用户 | 登录页勾选年龄与条款、邮箱验证码登录 |
| 已登录未建账 | 建账向导：确认地区与本位币、选填初始持仓；仅此两条路径，不能跳过本位币确认 |
| 已建账用户 | 全部业务功能；设置页修改偏好；未录初始持仓时可补录 |

### 2.3 边界（明确不做什么）

1. **不做本位币切换**：建账完成后锁定，任何页面无修改入口（含设置页、清空数据后）。未来如开放属独立立项（涉及历史成本全量重算与审计，本期明确不做）。
2. **不做设置草稿**：建账向导中断即丢弃，下次从头填（沿 m1 变更记录）；docs 01「设置草稿怎么保存」一节整体废弃。
3. **每币种初始记录仅一笔**：补录完成后如需修改，一律走「更正初始记录」，不提供第二次补录。
4. **记账起点不因补录延后**：补录初始持仓不改变记账起点，只补金额。
5. **不做账号资料变更**：设置页不提供改邮箱等功能（沿 docs 01「丢失邮箱使用权先联系邮箱服务商」）。
6. **不改变空状态引导页**：已建账、无账户且无计划的用户仍见 home-dashboard 的空状态页；本变更只在其上叠加「补录初始持仓」引导入口。
7. **导出/清空/注销流程不变**：仍按 docs 01「账号与数据」执行，本期是否实装按开发计划排期。

## 三、功能需求（按模块）

### 模块1：登录与合规门槛

1. **能力简述**：登录页在发送验证码前完成年龄与条款确认，登录后直接可用，不再被向导拦截偏好类设置。
2. **业务流程**：登录页填邮箱 → 勾选「已满 18 周岁」「已阅读并同意服务条款与隐私说明」（两项独立、默认不勾；隐私同意并入条款确认记录，与 V2.5 原型登录卡两个勾选框一致）→ 发送验证码 → 输入验证码登录。
3. **核心场景与验收路径**：

   > `登录页 不勾选任一项 → 预期：发送验证码按钮不可用，并提示「请先勾选确认年龄与条款」，验证码不发出`

   > `两项全勾 → 发送验证码 → 输入正确验证码 → 预期：登录成功；未建账用户进入建账向导，已建账用户直接进入首页或登录前正在浏览的页面；正在清空数据或注销的账号进入对应进度页`

   > `已完成建账的账号遇到新版重要条款且拒绝 → 预期：可查看已有记录、导出、删除数据或注销，但不能新增或修改业务记录（沿 docs 01 只读规则）`

4. **规则**：验证码全部规则（时效、频控、输错锁定、用途隔离）沿 docs 01，本变更不改；年龄与条款确认记录沿用现有 `consents` 接口语义（幂等、记版本与时间）。

### 模块2：最小建账向导

1. **能力简述**：未建账用户登录后进入两步向导——①确认地区与本位币；②选填初始持仓（可跳过）。完成即记账起点。
2. **业务流程**：
   - 第一步：所在地区（香港/中国大陆，按默认预填）→ 本位币（随地区预填，如大陆→CNY）→ 页面明示「本位币完成建账后不可更换」。
   - 第二步：问「是否现在持有外币」→ 选「没有，直接开始」则跳过 → 完成建账进首页；选「有，填写」→ 按 docs 02 规则填币种金额、核对汇率与初始成本（报价 5 分钟时效、8 位精度、多币种一起核对入账）→ 确认入账 → 进首页。
3. **核心场景与验收路径**：

   > `未建账用户登录 → 预期：看到建账向导第一步，地区与本位币已预填，页面出现「完成建账后不可更换」提示；看不到准备偏好、提醒设置步骤`

   > `改本位币 → 预期：确认前可改，改后各外币报价与已算初始成本作废、金额保留重新核对（沿 docs 01）`

   > `第二步选「没有，直接开始」→ 预期：完成建账进入首页，无任何初始记录，首页出现补录引导入口（模块3）`

   > `向导第二步中途退出 → 预期：本位币未确认、未建账；下次登录重新从第一步开始，无草稿残留`

   > `建账完成后任何页面 → 预期：找不到任何修改本位币的入口；设置页本位币只读展示`

4. **权限与状态规则**：年龄与当前必要条款未确认时不能完成建账（后端沿用现有校验）；记账起点 = 第二步完成（或跳过）确认时刻；首页三分流逻辑维持 `onboardingCompleted` 判定不变。

### 模块3：初始持仓补录

1. **能力简述**：已建账但从未录入初始持仓的用户，可从首页引导卡或外汇账户页进入补录，语义为「这些金额在记账起点当日已持有」。
2. **业务流程**：入口（首页引导卡 / 外汇账户页）→ 按币种填写现在实际持有金额（可不只补一个币种，每币种一行）→ 系统按**补录时刻**有效报价折算初始成本（沿用 docs 02 报价 5 分钟时效与 8 位精度规则）→ 核对页确认「以上是记账起点当日已持有的金额」→ 一起入账，先入未分配余额。
3. **核心场景与验收路径**：

   > `已建账、无任何初始记录 → 打开首页 → 预期：看到「补录初始持仓」引导卡；点击进入补录流程`

   > `补录完成后再次打开首页 → 预期：引导卡消失；此后修改该币种初始金额只能走「更正初始记录」`

   > `补录后回溯检查发现记账起点后某日使用资金不足 → 预期：阻止提交，显示该日期与缺口金额（复用 docs 02 更正检查规则）`

   > `建账时已录入初始持仓的用户 → 预期：首页与外汇账户页均不出现补录入口`

4. **规则**：补录与「更正初始记录」的分工——从无到有走补录，从有到改走更正（含 docs 02「漏填一个币种」的更正路径）；补录的初始成本不计入收益率比较（沿 docs 02「初始持仓是否计算收益」）；同一天成本顺序不变：初始持仓 → 普通买入 → 实际使用。

### 模块4：设置页（偏好随时改）

1. **能力简述**：设置页承接全部偏好类设置的查看与修改，替代原向导中的偏好步骤；本位币只读。
2. **分区与内容**：

   | 分区 | 项 | 可改性 |
   | --- | --- | --- |
   | 个人设置 | 邮箱 | 只读 |
   | 个人设置 | 地区 | 可改（香港/中国大陆） |
   | 个人设置 | 语言 | 可改（简体中文/英文，默认简体中文） |
   | 个人设置 | 本位币 | **只读**，旁注「建账时确定，不可更换」 |
   | 偏好 | 准备偏好 | 可改（安心/均衡/主动，默认均衡） |
   | 偏好 | 准备提醒 | 可改（默认开启） |
   | 账号与数据 | 退出登录、导出个人数据、清空业务记录、注销账号、查看处理进度 | 按 docs 01 既有规则 |

3. **核心场景与验收路径**：

   > `设置页 改语言为英文并保存 → 预期：界面语言切换；记账币种不变；同一版本条款不要求重新同意（沿 docs 01）`

   > `设置页 改准备偏好为「安心」并保存 → 预期：保存成功；已有计划的目标、分配、状态不受任何影响`

   > `设置页 关闭准备提醒 → 预期：不再收到准备/使用提醒；计划状态页仍正常展示（沿 docs 01）`

   > `设置页 尝试修改本位币 → 预期：本位币行无任何编辑入口，仅展示`

4. **规则**：修改即时生效，影响范围仅偏好本身；不产生记账记录、不触发汇率查询。

## 四、非功能需求

### 4.1 性能

- 建账向导、设置页首次加载 < 2s（本地开发环境，与现有 chat-web 标准一致）。

### 4.2 安全

- 建账、补录、设置修改接口全部要求登录（复用现有 JWT 守卫）。
- 完成建账沿用现有后端校验：年龄+当前版本条款已确认、本位币为支持币种之一、重复完成返回冲突（本位币锁定由「无任何更新入口」保证）。
- 本位币锁定不变式：UserSettings 建立后，全代码库不存在更新 baseCurrency 的写路径。

### 4.3 运行环境

- 与现有 chat-web 一致：现代桌面浏览器，最小宽度按现有工作台布局。

## 六、验收总原则

1. 未建账用户从打开登录页到进入首页，强制停留的页面只有：登录 → 输入验证码 → 向导第一步 → 向导第二步（可跳过）；设置类强制页仅向导两步（最多 2 屏）。
2. 除向导第一步外，任何页面都找不到修改本位币的入口。
3. 偏好修改不产生任何记账数据变化；初始持仓补录/更正的每一步都遵守 docs 02 报价与精度规则。
