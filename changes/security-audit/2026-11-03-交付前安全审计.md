## 2. mimosa findings 人工复核结论（10/10）

### 2.1 「敏感操作未观察到角色或权限检查」— ai.controller.ts:190（MEDIUM，误报）

- Controller 级 `@UseGuards(JwtAuthGuard)`（ai.controller.ts:75）。
- 删除会话走 `assertOwned`：`where: { id, userId }`（ai.service.ts:90），非本人/不存在统一 404 防枚举，接口测试「追问他人/不存在 → 404」覆盖。

### 2.2 「整块请求对象进入资源写入」× 5（HIGH，误报）

涉及 data-request / plan / settings / transaction / usage 五个 controller 的 create/update 入口：

- 全局 `ValidationPipe({ whitelist: true, transform: true })`（main.ts:17）——白名单外的字段静默剥离，mass assignment 在框架层拦截。
- 五个入口签名全部为类型化 DTO（`@Body() dto: CreatePlanDto` 等），无 body spread 透传。
- 结论：候选消除。

### 2.3 「资源标识来自请求，未观察到所有权绑定」— rate.controller.ts:61（HIGH，by design）

- `GET /rates/latest/:base` 是**公开行情数据**（15 币种矩阵全员可读），不存在租户概念；同 controller 无任何用户数据读写。
- 结论：非漏洞。

### 2.4 「环境变量 → api/client.ts SSRF 污点」× 3（MEDIUM，已整改确认）

- 被标记的 `apiClient`（client.ts:68）正是上轮 CWE-918 整改落点：endpoint 仅允许站内相对路径，拒绝绝对 URL 与协议相对 URL（代码内注释明示）。
- 3 个 data-requests.ts 调用点均传常量相对路径。
- 结论：候选消除。
