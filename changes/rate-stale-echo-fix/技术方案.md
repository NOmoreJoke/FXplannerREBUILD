# 最新报价「回显已落库」——消除高频「获取中」等待（FXP 缺陷修复）

> 状态：实施中
> 关联：`changes/realtime-rate/技术方案.md` §3.5、`changes/rate-refresh-cron/`、`changes/m2-rate/`

## 1. 背景与问题（用户反馈，2026-09-21）

页面经常长时间停留在「正在获取参考汇率…」；用户期望优先回显已落库的报价（定时任务每 30 分钟落库），而不是每次进页都等外呼。

## 2. 根因

三个因素叠加，导致「进页必外呼、外呼必慢」：

| # | 位置 | 问题 |
| --- | --- | --- |
| 1 | 前端三处首拉强制回源 | `rate-reference-card.tsx:57`（录入页参考卡，硬编码 `refresh=true`）、`use-latest-rates.ts`（挂载/换 Key 强制）、`use-holdings-review.ts`（首次/换币种集合强制）——每次进页绕过缓存 |
| 2 | 后端窗口远短于落库周期 | 定时任务 30 分钟落库一次，`QUOTE_TTL_MS = 5 分钟` → 即使 `refresh=false`，库内报价大概率已超窗，仍同步回源外呼 |
| 3 | 主源响应慢 | ABC 农行源：6s 超时 + 全局并发 1 + 最小外呼间隔 10s（防滥用），排队时等待进一步放大 |

结论：**库里有数却不用，是设计断层**——`getLatest` 的二值逻辑（窗口内命中 / 否则同步回源）缺少「陈旧回显」档位。

## 3. 方案

后端 `getLatest` 引入 stale-while-revalidate（SWR）：**先回显，后刷新**。

### 3.1 后端 `rate.service.ts getLatest` 决策表（refresh=false 时）

| 库内状态 | 行为 |
| --- | --- |
| 全部目标窗口内新鲜 | 现状：命中返回（不外呼） |
| 全部目标**有行**但超窗 | **新增：立即返回库内旧值**（`fresh=false` 如实标注，validUntil 已过 → 前端展示「已过期，仅供参考」），同时**后台异步回源**（复用单飞 `refreshWithSingleFlight`，fire-and-forget，失败仅 `Logger.warn` 不上抛） |
| 任一目标无行（冷启动） | 现状：同步回源（首次部署后第一发必须等，之后 cron 持续落库） |

- `refresh=true` 语义不变：同步回源强一致（确认页先取数后锁数、手动刷新）。
- 后台回源成功走既有 upsert 通道：`createdAt = now` 窗口重置，前端 60s 轮询自然拿到新值——闭环无需新增接口。
- 「防刷新洗白」规则不变：回显旧值（缓存读）不触碰行；仅后台回源成功才重置窗口。

### 3.2 前端：首拉不再强制回源

| 文件 | 变更 |
| --- | --- |
| `rate-reference-card.tsx` | `ratesApi.latest(base, [target], false)`——参考卡仅作回填辅助，回显旧值 + 元信息展示「报价日期 / 已过期，仅供参考」足够 |
| `use-latest-rates.ts` | 挂载首拉 `refresh=false`；**queryKey 变化（换币种 / locked↔live）保留强制**（显式换目标 = 用户要新数据）；`refreshLatest` 保持 `refresh=true`（确认页锁数强一致） |
| `use-holdings-review.ts` | 首次取价 `refresh=false`；**币种集合变化保留 `refresh=true`**（N2 语义收窄：仅「非首次的集合变化」才强制） |

### 3.3 不做的事（防过度设计）

- 不新增接口/字段：复用 `fresh`/`observedAt` 元数据表达陈旧度。
- 不改 cron 周期与窗口时长：SWR 已消除「必等外呼」，窗口仅决定「新鲜」标签。
- 不改 onboarding 入账取价（服务端 `onboarding.service` 自主取价，强一致场景不受影响）。

## 6. 风险与回滚

- **旧值展示**：元信息行本就展示「报价日期 + 已过期，仅供参考」，用户可感知陈旧度；确认页锁数走 `refresh=true` 不受影响。
- **后台任务悬挂**：Nest 请求结束后 promise 继续执行属常规 fire-and-forget；单飞去重 + catch 吞错，最坏情况 = 这次后台刷新失败，下次轮询/进页重试。
- **回滚**：还原 `getLatest` SWR 分支与三处前端首拉参数即可，无 schema/接口形状变化。
