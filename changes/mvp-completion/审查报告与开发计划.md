## 一、先说清楚：「记录实际使用」是什么，和买入录入的关系

### 一句话

**现有的「录入」记的是钱怎么来的（买入），缺的「使用」记的是钱怎么花的（支出）。** 这是钱的一进一出两个方向，现在只做了"进"。

### 例子：留学交学费

| 阶段 | 动作 | 系统现状 |
| --- | --- | --- |
| 建计划 | 要准备 10 万日元，9 月底交学费 | ✅ 已实现 |
| 准备 | 分 3 次买入日元，每次录一笔交易 | ✅ 已实现（这就是你说的"录入"） |
| **使用** | 9/20 实际支付 5 万日元学费 | ❌ **系统里没有任何地方能记这个动作** |
| 再使用 | 9/28 交剩下 5 万 | ❌ 同上 |
| 完成 | 使用累计 = 目标 → 确认计划完成 | ❌ 无法判定，计划永远停在"进行中" |

### 不做"使用记录"的后果

- 计划无法完成：系统不知道你已经交完学费，"准备进度 100%"会一直挂着
- 账户余额虚高：日元实际已经花出去，账面却不动
- 成本摘要算不出：功能 25"这个计划最终花了多少人民币"依赖使用数据
- **功能 15/16/17/18/21/22/25 全部依赖它** —— 这就是它是当前最大断点的原因

### 「分次使用」（功能 16）

目标金额不用一次花完。10 万目标先交 5 万：只记一笔、只扣本次的 5 万，剩下 5 万继续留在计划里待使用。每次使用 = 一条 UsageRecord。

### 对账模型（两者关系）

```
买入交易（M4）  = 流入：+外币持仓（CostLot）、-人民币     → 准备进度 = 买入累计 / 目标
使用记录（M7）  = 流出：-外币余额、-计划分配、消耗 CostLot → 使用进度 = 使用累计 / 目标
```

- 现在"关联计划"只是**标记**，不产生任何扣减；使用记录才会真正动余额和分配
- 计划的两个进度是独立维度：钱备齐（准备 100%）≠ 钱花完（使用 100%）
- 注意：功能清单明确"不属于任何计划的使用记录"超出 MVP 范围——MVP 里每笔使用必须挂在某个计划下

## 四、后续开发计划

排序原则：**先打通钱的闭环（M7），再补纠错能力（M8），然后趁页面定型插入 i18n，最后三个独立模块并行收尾。**

### 阶段 1：M7 资金使用（P0，1 个迭代）

一切后续功能的地基，解锁功能 15/16/17/18 及 22 的完成判定。

| 事项 | 内容 |
| --- | --- |
| 后端 | `POST /plans/:id/usages`：扣账户余额 + 扣计划分配 + FIFO 消耗 CostLot，事务校验余额/分配充足；使用记录列表 |
| 前端 | 计划详情"记录使用"入口与表单（金额/日期/备注）、使用记录列表、准备/使用双进度条（功能 17） |
| 状态联动 | 还需使用金额、"钱已备齐"、"资金已使用完成"（功能 18） |
| 测试 | `services/chat/test/api/plan-usage.spec.ts` + 使用扣减 FIFO 集成测试 |
| 验收 | 功能 15/16/17/18 落地；使用达标后可确认完成计划 |

### 阶段 2：M8 更正框架（P0，依赖 M7，1 个迭代）

解锁功能 20/21/28，顺带修 onboarding 悬空文案。

| 事项 | 内容 |
| --- | --- |
| 交易更正 | 改金额/币种/日期，原因必填，影响预览，新版本+历史保留；改币种/日期触发 FIFO 重排与余额校验 |
| 使用更正 | 改小（差额回未分配）、改大（补分配校验）、改日期；已完成计划调小误录仍保持已完成（功能 21） |
| 手续费补录 | 未知手续费补录后重算成本 |
| 初始持仓更正 | 按原时点金额和汇率（需 M2 补"精确时点取价"端点），失败不部分保存 |
| 杂项 | 修 `onboarding.controller.ts:102` 悬空文案；交易详情接通"更正"入口按钮 |
| 测试 | api + integration（更正后成本/余额一致性） |
| 验收 | 功能 20/21/28 落地 |

### 阶段 3：i18n 接入（P1，0.5 个迭代，横切任务）

MVP 支持范围要求中英文，当前完全硬编码简体中文。**页面在 M7/M8 后基本定型，此时插入改造成本最低**；拖到报告/提醒模块之后，每个新页面都在加债。

- 引入 next-intl（或等价方案），默认 zh-CN，locale 挂用户偏好
- 提取 M0-M8 已有页面文案为词条
- 验收：语言切换全站生效，默认简体中文

### 阶段 4：M10 报告 + M9 提醒 + M11 账号数据（P1，1-1.5 个迭代，三者相互独立可并行）

| 模块 | 内容 | 解锁功能 |
| --- | --- | --- |
| M10 报告 | 计划成本摘要接口（依赖 M7 数据）、账户剩余成本、报告页、单计划 PDF 下载 | 25 |
| M9 提醒 | 提醒生成规则（准备安排到期/使用情况）、同计划同日合并、可关闭、首页提醒中心 | 24 |
| M11 账号数据 | 数据导出（ZIP+CSV）、清空业务记录、注销；邮箱验证复用 OTP；DataRequest 处理进度展示 | 27 |

验收：功能 24/25/27 落地；设置页三个占位按钮全部接通。

### 阶段 5：收尾（P2，1 个迭代）

- M12 补全：首页正常态"新建计划"直达入口
- 账户页"按计划分配视图"（功能 13 收尾）
- M1 补全：首次设置草稿 30 天保留（或明确降级并记录到待确认项）
- 功能 29"修改计划日期"：实施或明确移出 MVP 并记录
- M13 E2E：跨模块全流程（建计划→分批买入→分次使用→更正→完成→报告→导出）+ 回归

### 里程碑示意

```
M7 使用 ──→ M8 更正 ──→ i18n ──→ M10 报告 ┐
                                    ├─→（可并行）├─→ 收尾 + E2E 回归
                                    └─→ M9 提醒 │
                                         M11 账号数据 ┘
```
