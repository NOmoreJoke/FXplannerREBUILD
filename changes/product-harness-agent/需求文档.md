# PRD：产品即 Harness × 知禾 Agent × 双模存折工作台

> **状态**：已定稿（对应迭代计划 `Goal #6`–`Goal #9` / `W37`–`W51`）。
> **关联文档**：技术设计与分期切片见 `changes/product-harness-agent/技术方案.md`；视觉与语气底座见 `design-harness/README.md`；前置多租户与首版 Agent 基线见 `changes/tob-agent-workspace/需求文档.md`。

## 1. 背景与核心问题

FXPlanner 在完成个人 MVP 正确性收口与 ToB R1/R2 多租户权限地基后，仍存在三处核心体验与架构断层：
1. **确定性业务底座未统一成 Harness 协议**：后端已具备排期预览、更正重放预览、定点金额互算与 FIFO 批次核算，但 AI 仅接通了无状态单列 `ai_messages.plan_draft`，缺少防漂移、可追溯的全账本提案生命周期。
2. **界面割裂且企业审批感过重**：AI 被关在孤立的 `/chat` 页，拿草稿后还要跳去长表单；早期原型误用了脚手架残留词且充斥「总控/专员/组织审计/公章」等生硬企业词，让个人留学、旅行与独立主理人倍感疏离。
3. **两代 Agent 资产未合龙**：自由对话流缺乏槽位级数字防幻觉冻结，而归档包中的报告快照结构化解读与投顾封杀词门禁尚未落地。

## 2. 产品北极星与核心定位

- **唯一宗旨**：所有交互与视觉设计只服务 **① 提升用户信任感；② 降低操作理解难度**。
- **产品即 Harness**：账本、排期、FIFO、RBAC 与审计本身即为约束 AI 的确定性沙箱——模型绝不算账、绝不直接写账本，统一走 **「读取快照 → 零副作用试算预演（Proposal） → 人类亲手确认入账（Commit）」**。
- **温暖陪伴伙伴「知禾（小禾）」**：前台始终由唯一一位温和、沉静、守分寸的伙伴「知禾」以第一人称沟通，后台多专员路由与校验转化为知禾安静的核对步骤。
- **个人优先、团队渐进显露（Solo-First, Team-on-Demand）**：单人默认工作台（`memberCount === 1`）完全隐藏「组织/审计/角色权限」等企业术语，呈现温润的个人备款存折手账单；仅在多人团队（`memberCount > 1`）时按需浮现协作者姓名与角色分工。

## 3. 范围边界

### 3.1 纳入范围
1. **五类账本预演单（`AgentProposal`）**：新建计划（`PLAN_CREATE`）、调整计划（`PLAN_ADJUST`）、买入录入（`TX_BUY`，首期仅解析粘贴文字）、登记用款（`USAGE_RECORD`）、更正影响预演（`CORRECTION_APPLY`）。
2. **结构化快照解读**：计划详情页与报告页内嵌安静的「知禾账本解读卡」（与打印视图同源，带本地确定性事实模板兜底）。
3. **双模全宽翻转工作台**：顶栏「账本 ⇄ 知禾协作（含待确认角标）」URL 驱动切换，协作模式采用「左对话栏（32% 可拉宽）+ 右存折备款检视台（全 11 态）」，确认后可一键跳回账本高亮新记录。

### 3.2 明确排除（Non-Goals）
- 成员邀请、角色修改、所有权转移及数据导出/清空/注销等高危治理操作**严禁生成 AI 预演单**（知禾仅说明规则并提供设置页入口）。
- 首期不做银行回单图片 OCR、不做跨成员审批转交队列（坚持本人起草、本人确认，Schema 预留 `confirmedById`）、不做深色主题与真实资金划拨。

## 4. 用户可观察行为断言（Given-When-Then）

1. **GWT-H1（个人默认温润无企业词）**：假如用户处于单人默认工作台（`memberCount === 1`），当从计划页切入「知禾协作」试算并确认一笔支出，那么全程界面显示产品名 `FXPlanner` 与伙伴 `知禾`，使用存折状态回执签，不出现「灵积」「总控/专员」「组织审计日志」或「角色权限」字样。
2. **GWT-H2（团队协作按需显露）**：假如用户处于 ≥2 名成员的团队工作台且角色为 `OPERATOR`，当请求知禾登记资金使用，那么派单前权限门拦截并在检视台温和展示团队角色分工说明，明确告知「账本没有任何变化」且给出试调计划排期的替代入口。
3. **GWT-H3（原位微调与零幻觉入账）**：假如知禾生成一张预演备款单，当用户在检视台修改金额或日期，那么前端仅防抖调用后端 `preview` 刷新批次与成本（不重调大模型）；点击 `确认记入账本` 后同事务写入业务记录、更新提案为 `CONFIRMED` 并记录 `USER` 审计。
4. **GWT-H4（账本漂移防静默覆盖）**：假如预演单生成后该币种账本发生变动且重算结果有差异，当用户点击确认或刷新，那么后端返回 `409 PROPOSAL_STALE`，检视台展示删除线旧值与琥珀新值对照，未勾选「我已核对最新数字」前确认按钮保持禁用。
5. **GWT-H5（时效、上限与历史槽位冻结）**：假如实时参考报价超过 5 分钟（或预演单超过 24h），检视台进入 `expired` 态引导一键重算；待处理预演单达 20 张上限时拒绝静默顶掉旧稿并展示批量收起清单；回看历史会话时，知禾消息中的槽位数字恒定显示当时落库冻结值，不随今日余额漂移。
6. **GWT-H6（合规封杀词与事实模板兜底）**：假如模型输出试图包含涨跌预测、择时诱导词或未绑定快照槽位的裸数字，那么规则校验层/语义复核层立即拦截并重写或无缝回退至确定性事实模板，确保用户永不看到投顾违规话术或编造金额。
