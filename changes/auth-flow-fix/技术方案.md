# 认证链路修复（阶段 1 + 2 + 3c 前端同步）

> 关联：`changes/auth-otp-bind/`（后端 OTP 绑定，阶段 3c）
> 状态：已完成，测试 0 failed

## 1. 背景与问题

认证链路存在以下断裂点（按严重程度）：

| # | 问题 | 位置（修复前） |
| --- | ------ | -------------- |
| 1 | token 双存储（localStorage + cookie）各自过期，proxy 与 apiClient 判定分叉 | `login/page.tsx:57`、`client.ts` |
| 2 | apiClient 401 直接 `window.location.replace("/login")` 丢 redirect，与 layout 的 `router.push` 双重跳转竞争 | `lib/api/client.ts:78` |
| 3 | `(protected)/layout.tsx` 依赖 `[pathname]`，每次导航重复请求 `/auth/me` 并闪 loading | `(protected)/layout.tsx` |
| 4 | 登出缺失：`useLogout` 无 UI 调用，侧边栏用户卡为静态占位 | `(protected)/layout.tsx:121` |
| 5 | redirect 参数：login→register 链路丢失；无白名单校验（`//evil.com` open redirect） | `login/page.tsx:62` |
| 6 | 校验不一致：登录密码 min(6) vs 注册 min(8)+复杂度 vs 后端 LoginDto 非空；OTP 目标无格式校验 | `login/page.tsx` |
| 7 | `authStore.isLoading` 死状态 | `lib/stores/auth-store.ts` |
| 8 | 同邮箱「密码注册 + OTP 登录」产生两个独立账号（数据分裂） | `services/chat/src/auth/`（见关联文档） |

## 2. 方案（已拍板）

- **存储策略：cookie 单一事实来源**。`proxy.ts`（Next 16 服务端守卫）只能读 cookie；后端为 Bearer JWT，cookie 仅是存储介质不参与自动认证，不引入 CSRF；XSS 暴露面与 localStorage 等价。localStorage 全部移除。
- **401 职责分离**：apiClient 只清 token + 抛 `ApiError`；跳转统一走 `redirectToLogin(currentPath)`（带 redirect、防重复、已在 /login 时不跳）。
- **守卫降频**：layout 仅在 authStore 无 user 时校验一次 getMe；站内导航零请求。
- **OTP 绑定语义（后端）**：仅绑定不迁移，见关联文档。
