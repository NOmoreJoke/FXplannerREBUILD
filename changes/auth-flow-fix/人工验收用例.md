# 认证链路修复 · 人工验收用例

> 关联：`技术方案.md`（本次改动范围）
> 执行人：人工（浏览器 + DevTools）
> 每个用例结果记录：✅ 通过 / ❌ 失败（附截图与复现步骤）

## 0. 环境准备

| 步骤 | 操作 |
| ------ | ------ |
| 0.1 | 数据库与后端就绪：`infra/compose` 起依赖，`services/chat` 下 `bun run start:dev`（或项目现有启动脚本） |
| 0.2 | 前端就绪：`clients/chat-web` 下 `bun run dev`，浏览器打开 `http://localhost:3000` |
| 0.3 | OTP 验证码获取：配置了 `RESEND_API_KEY` 时收真实邮件；未配置时从后端控制台日志读取（dev 输出） |
| 0.4 | DevTools 常开两个面板：**Application → Cookies/Local Storage**（验 token 存储）、**Network**（验 `/auth/me` 请求频率） |
| 0.5 | 每个用例开始前点「退出登录」或手动清 cookie（Application → Cookies → 删除 `accessToken`），保证干净状态 |

## 1. 全局通过标准

- 所有断言以「用户可见行为」为准；涉及存储的断言以 DevTools 实际内容为准
- 任何 ❌ 即打回：附 URL、操作步骤、截图、Console 报错
- 与自动化测试重叠的路径（登录/注册主流程）人工只需抽测，重点放在自动化覆盖不到的「跨页面状态」「视觉」「DevTools 层面存储」

## 2. 用例

### A. 落地页

| # | 前置 | 步骤 | 预期 |
| --- | ------ | ------ | ------ |
| A1 | 未登录（无 cookie） | 访问 `/` | 标题品牌为 **FXPlanner**（无 `-new` 后缀）；文案为产品文案（非"全栈骨架已就绪"）；有「免费注册」主按钮和「登录」次按钮 |
| A2 | 未登录 | 点击「免费注册」 | 跳转 `/register` |
| A3 | 未登录 | 点击「登录」 | 跳转 `/login` |
| A4 | 已登录 | 访问 `/` | 自动跳转 `/home`（不得停留在落地页） |
| A5 | — | 目视检查落地页配色 | 无灰/蓝默认色块；品牌色与主站一致（mint 绿系）；无样式错乱 |

### B. 注册

| # | 前置 | 步骤 | 预期 |
| --- | ------ | ------ | ------ |
| B1 | 未登录 | `/register` 输入未注册邮箱、密码 `Abc12345`、确认密码一致，提交 | 跳转 `/home`；DevTools：**Cookie** 存在 `accessToken`；**Local Storage 中没有 `accessToken` 键**（关键断言） |
| B2 | 未登录 | 密码 `abc12345`（无大写）提交 | 前端拦截，提示复杂度不足，不发请求 |
| B3 | 未登录 | 两次密码不一致提交 | 提示"两次输入的密码不一致" |
| B4 | 未登录 | 用 B1 已注册的邮箱再次注册 | 提示注册失败（邮箱已存在类文案），**不跳转**，停留注册页 |
| B5 | `/login?redirect=/plans` 进入登录页 → 点「立即注册」 | 查看注册页 URL | URL 带 `redirect=%2Fplans`（redirect 参数不丢失） |

### C. 密码登录

| # | 前置 | 步骤 | 预期 |
| --- | ------ | ------ | ------ |
| C1 | 已有账号，未登录 | `/login` 密码模式，正确邮箱 + `Abc12345` 提交 | 跳 `/home`；cookie 有 `accessToken`、localStorage 无 |
| C2 | 未登录 | 密码只输 3 位提交 | **前端不再提示"密码至少 6 个字符"**（校验已对齐后端），请求发出后提示"邮箱或密码错误" |
| C3 | 未登录 | 错误密码提交 | 提示"邮箱或密码错误"，停留登录页 |
| C4 | 未登录 | 切换到验证码模式再切回密码模式 | 表单状态正常，无残留报错 |

### D. OTP 登录与账号绑定（本次核心修复）

| # | 前置 | 步骤 | 预期 |
| --- | ------ | ------ | ------ |
| D1 | 未登录 | OTP 模式输入非法目标（如 `abc`）点「获取验证码」 | 前端格式拦截提示，**不发请求**（Network 无 `otp/send-code`） |
| D2 | 未登录 | 合法**新邮箱**发送验证码 | 收到验证码（邮件/日志）；按钮进入倒计时不可再点；输入验证码登录 | 跳 `/home`，创建新账号 |
| D3 | **绑定语义**：先用邮箱 `t@x.com` + 密码注册并在 `/home` 或 `/plans` 创建任意数据 → 退出登录 → OTP 模式用 `t@x.com` 收验证码登录 | 登录后检查 | **回到原账号**：能看到退出前创建的数据；不出现空白的"新账号"（不分裂） |
| D4 | 已用密码注册的账号绑定过 OTP 后 | 退出，再用邮箱+密码登录 | 登录正常，仍是同一账号（回归） |
| D5 | 未登录 | 同一邮箱 60 秒内第二次点「获取验证码」 | 提示"请求过于频繁"类错误（后端频控生效） |
| D6 | 未登录 | 连续输错验证码 5 次 | 账号进入锁定，再发码/验码提示锁定类错误（15 分钟窗口） |
| D7 | 未登录（可选，未配置短信服务时） | OTP 切到手机号渠道发码 | 明确的错误提示（服务不可用类），无白屏/无未处理异常 |

### E. redirect 回跳链路

| # | 前置 | 步骤 | 预期 |
| --- | ------ | ------ | ------ |
| E1 | 未登录 | 直接访问 `/plans` | 跳 `/login?redirect=%2Fplans`；登录成功后**回到 `/plans`**（不是 /home） |
| E2 | 未登录 | 访问 `/login?redirect=%2F%2Fevil.com`（即 `//evil.com`）并登录 | 落在 `/home`，**不得跳转外站**（白名单拦截） |
| E3 | 未登录 | 访问 `/login?redirect=https:%2F%2Fevil.com` 并登录 | 落在 `/home`（协议地址被拒） |
| E4 | 未登录 | `/login?redirect=/plans` → 点「立即注册」→ 注册成功 | 注册后**直接回 `/plans`** |
| E5 | 未登录 | 不带参数直接进 `/login`，登录 | 落 `/home`（默认值） |

### F. 登出与状态清理

| # | 前置 | 步骤 | 预期 |
| --- | ------ | ------ | ------ |
| F1 | 已登录 | 查看侧边栏底部用户卡 | 显示**真实**用户名/邮箱与首字母头像（非静态"Kal / 已认证 · 试用中"）；右侧有登出图标按钮 |
| F2 | 已登录 | 点击登出按钮 | 跳转 `/login`；DevTools：cookie `accessToken` 已消失 |
| F3 | 刚登出 | 浏览器**后退** | 不回到受保护页（回到 /login 或落地页）；受保护页内容不可见 |
| F4 | 刚登出 | 手动访问 `/home` | 被踢回 `/login?redirect=%2Fhome` |

### G. Token 失效与服务端守卫

| # | 前置 | 步骤 | 预期 |
| --- | ------ | ------ | ------ |
| G1 | 已登录 | DevTools 把 cookie `accessToken` 值篡改为 `broken`，刷新 `/home` | 跳回 `/login?redirect=%2Fhome`；登录后回 `/home`（redirect 不丢） |
| G2 | 已登录 | 删除 cookie，刷新 `/home` | 服务端直接重定向 `/login?redirect=...`（**Network 里文档请求就是 307/307 类重定向，页面无白屏闪烁**——这是 cookie 单一来源的服务端守卫在起作用） |
| G3 | 已登录 | 在 `/home`、`/plans` 等页面间连续点击导航 5 次，看 Network | **`/auth/me` 只在最开始出现 1 次**，后续导航零请求、无整屏 loading 闪烁（守卫降频） |
| G4 | 已登录 | 任一受保护页打开 Network，手动删除 cookie 后点任意导航 | 被 `redirectToLogin` 带回 `/login?redirect=当前路径`；**Network 中只有一次跳转**（无双重跳转竞争） |

### H. 视觉与细节

| # | 前置 | 步骤 | 预期 |
| --- | ------ | ------ | ------ |
| H1 | — | 打开 `/login`、`/register` | 无 gray/blue 硬编码配色；品牌 mint 色系；输入框 focus 态为 mint 描边；报错文案红色（destructive） |
| H2 | `/login` | 检查密码输入框 | DevTools 或右键检查：`autocomplete="current-password"`；注册页密码为 `new-password`（密码管理器可正常识别） |
| H3 | `/login` | 走一次密码登录（让浏览器弹"保存密码"） | 密码管理器能识别并保存；再次进登录页能自动填充 |
| H4 | — | 目视两页 | 表单卡片有统一圆角/阴影；与落地页、主站视觉一致，无突兀混搭 |
| H5 | — | 窗口缩窄至 ~400px 宽 | 表单不溢出、按钮可用（基础响应式） |

## 3. 无法人工覆盖、由自动化兜底的项

| 项 | 兜底 |
| ---- | ------ |
| JWT 7 天过期后的行为 | 等待不现实，由 cookie max-age 与 JWT 同步保障；E2E/单测覆盖 401 路径 |
| 频控/锁定的精确阈值 | `test/api/otp.spec.ts`（内存时钟精确断言） |
| OTP 绑定的数据层断言（otpIdentity 唯一键） | `test/api/auth-otp-bind.spec.ts`（人工 D3 只验用户可见行为） |
| redirect 白名单全部分支 | `safe-redirect-path.spec.ts`（人工 E2/E3 抽测即可） |
