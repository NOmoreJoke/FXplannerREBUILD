## 1. 币对范围与回补来源

- **ErApi 受影响的路由**。多源模式按 `target` 选源，只有 `quote=TWD` 路由到 ErApi。本位币允许 15 种，排除恒等的 TWD，候选范围为 HKD、USD、GBP、AUD、CAD、CNY、JPY、EUR、SGD、NZD、CHF、KRW、THB、MYR，共 14 个有方向的币对。反向 `base=TWD` 按另一端 `quote` 走现有路由，单源降级另验。定时刷新使用 CNY，本地其他本位币的历史密度取决于实际流量。实际存量盘点状态见 §3.1。依据为 `services/chat/src/rate/rate.provider.ts:114-136`、`services/chat/src/rate/rate-cron.service.ts`、`services/chat/src/onboarding/onboarding.controller.ts:93`。
- **ErApi 无密钥路由**。仓库调用 `/v6/latest/{base}`，`ErApiSource.fetchHistory` 直接返回空数组。实测 CNY、HKD 最新接口均返回 TWD，响应中 `time_last_update_unix` 对应 `2026-11-19T00:02:31Z`。两个基准币的无密钥历史路径均为 HTTP 404。现存原时点历史的首选恢复来源是本库已保存、方向可证的 ErApi 快照。供应商的正式历史端点限付费方案，用日期提供参考中间价，本轮不引入密钥或付费依赖。依据为 `services/chat/src/rate/rate-source.erapi.ts:54-109`。 [无密钥接口](https://www.exchangerate-api.com/docs/free) · [正式历史接口](https://www.exchangerate-api.com/docs/historical-data-requests)
- **现有 Frankfurter v1**。仓库的 `api.frankfurter.app` 重定向到官方 v1。实测币种列表包含 MYR、缺少 TWD，CNY/TWD、HKD/TWD 区间请求均为 HTTP 404。保留 v1 的既有支持币对、MYR 历史和单源降级语义。依据为 `services/chat/src/rate/rate.constants.ts:43-48`、`services/chat/src/rate/rate-source.frankfurter.ts:50-96`。 [Frankfurter v1 文档](https://frankfurter.dev/v1/)
- **Frankfurter v2 日级参考历史**。无密钥的 `/v2/rates?base={BASE}&quotes=TWD&from={YYYY-MM-DD}&to={YYYY-MM-DD}` 可用于市场图表冷缺口。实测上述 14 个本位币在 2026-10-01 至 2026-10-14 各有 14 个唯一日期，在 2025-11-16 至 2026-11-15 各有 365 个唯一日期，报价均为正数。2026-10-08 样本为 1 CNY 兑 4.7567 TWD、1 HKD 兑 4.0572 TWD。返回字段为 `date/base/quote/rate`，默认混合多个供应商，样本也含周末日期。该覆盖只代表所测窗口，`date` 只证明序列日期。 [v2 API 文档](https://frankfurter.dev/) · [CNY 样本](https://api.frankfurter.dev/v2/rates?base=CNY&quotes=TWD&from=2026-10-01&to=2026-10-14) · [HKD 样本](https://api.frankfurter.dev/v2/rates?base=HKD&quotes=TWD&from=2026-10-01&to=2026-10-14)

**方向与精度。** 对上游 `1 base = raw quote` 用十进制定点或 Decimal 计算 `1 / raw`，按现有表精度 `Decimal(20,10)` 做一次 HALF_UP，再沿用入账的 8 位汇率与本位币金额舍入。沿用原始报价字段的来源含义，校验正数、有限、落库范围及舍入不归零。ABC 基准价和卖出价保持现行，恒等价 1 不外呼。三源等价用同一人工报价的独立夹具，各自真实报价允许有市场口径差。扫描建账、买入、成本报告、行情和 AI 汇率工具的消费者，防止二次取倒数。依据为 `services/chat/prisma/schema.prisma:37-49`、`services/chat/src/rate/rate-source.abc.ts:175-208`。

**首次建账与补录。** `recordInitialHoldings` 当前走 `getLatest`，随后用 `observedAt + 5min` 自行拒绝，错误为 `RATE_UNAVAILABLE`。拟统一采用最新报价 API 已有的系统确认时效 `fresh/validUntil`，陈旧回显时取一次真实同步刷新，确认失败或结果已过期则保留拒绝。保留真实 `observedAt`、采用价和来源写入持仓，成本及 FIFO 照旧。依据为 `services/chat/src/onboarding/onboarding.service.ts:387-446`、`services/chat/src/onboarding/onboarding.service.ts:508-535`、`services/chat/src/rate/rate.service.ts:138-181`。

**初始持仓币种更正。** 使用 `original.confirmedAt` 从目标币种历史取价。实时源沿用 `(at-5min, at]`，有真实供应商时间的日级快照先找 UTC+8 同日且 `observedAt ≤ at` 的最近合格点，再按已验证发布规则有限回看。计划以最多 7 个 UTC+8 自然日作为工作假设，实施开工按实际节假日、停更和产品口径确认，测试锁定最终边界。v1 的 `date` 目前会被解析为 UTC 午夜，此时间用于日期表示，原时点入账须另有可验证的当时可用性证据，例如可核对的本地实际取价记录，能证明该报价在 `at` 前已取得。共用缓存上可被 upsert 刷新的 `createdAt` 不单独充当此证据。仅保有日期的 v1/v2 点或其他源参考值无法证明原时点可用时，保留 `RATE_QUOTE_UNAVAILABLE`。如果预览后的报价或来源发生变化，提交须拒绝旧确认并重新预览。同币种改金额继续使用账本已存的报价快照。参考日价若要用于冷历史入账，需另行确认适用条件、发布边界和来源展示，再增加独立验收。依据为 `services/chat/src/rate/rate.service.ts:201-264`、`services/chat/src/rate/rate-source.frankfurter.ts`、`services/chat/src/correction/correction.service.ts:585-640`。

**图表与缓存隔离。** 单独提供 TWD 图表补点入口，按同日 ErApi 快照优先的规则合并，沿用图表日期桶，过滤区间并去重，展示中说明参考价来源。若在通用历史接口提供参考点，行情和 AI 历史工具都须区分参考价与原来源；如需扩展响应来源字段，由后端 DTO 定义并重生成前端类型。保留图表既有 7/30/90/365 档、单飞和负缓存；同币对不同窗口的请求按范围隔离，或复用覆盖整个请求的较宽窗口。v2 点经独立图表缓存或响应合并，禁止经现有 `fetchHistory` 回写 `exchange_rates`。该表唯一键是 `(base, quote, observedAt)`，不含来源；最新与原时点查询会读这张共用表，现有历史写入也按币对路由标注来源。隔离后，参考点不会占用现行键、刷新 `createdAt` 或出现在账本候选中。图表 `current_rate` 继续表示序列最后一点，单独的实时牌价仍走 latest API。依据为 `services/chat/prisma/schema.prisma:37-49`、`services/chat/src/rate/rate.service.ts:267-376`、`services/chat/src/rate/rate.service.ts:792-812`、`services/chat/src/ai/tools/rate-tool.ts:152`。

## 3. 旧缓存处理顺序

1. **只读盘点并冻结目标清单。** 按实际部署写入版本、`source/base/quote` 和时间分桶列出候选、主键、时间范围、方向证据及按日期可覆盖的原时点窗口。ErApi 候选限定历史 `source=er-api` 且 `quote=TWD` 的非恒等行。Frankfurter 候选按 `source=frankfurter` 的实际曾写币对查，包含早期单源与之后的降级写入，不能只从多源引入日期算起。审查曾用旧反向值入账的业务快照，记录数量与样本待单独处理。排除 ABC、identity、已正确写入的行及其他来源。大于或小于 1 均不能判定方向。记录有 `sellRate`、来源不符、舍入溢出/归零或无法溯源的冲突行。原值仍不可判定时停止该批。
2. **停旧写并做可恢复备份。** 在测试备份副本先走全流程。正式操作由人类另行批准和安排维护窗口，暂停并排空旧实例的受影响读写及在途请求，覆盖定时和手动刷新、冷启动、SWR、`refresh=true`、历史图表和更正回补。冻结主键与原字段快照（`id/base/quote/source/rate/sellRate/observedAt/createdAt`）以及清单校验和、切换版本、计数和恢复入口。旧 `createdAt` 可被最新报价 upsert 刷新，不能独立当作版本标记。缺少停写或可恢复快照即停止。
3. **先保 ErApi，再处理 Frankfurter。** 已证实是旧方向的 ErApi 快照，按清单用备份中的持久化十位原值计算新值并原位更新 `rate`，保留主键、真实 `observedAt`、原来源和确认时间。保留的精度以数据库原值为限。Frankfurter 优先用同样的可证原位转换；必须替换时，先用 v1 在暂存中取得同一币对与同一来源日期的合格替代数据，核对可用窗口后，在同一事务替换指定行。自然键冲突、非空 `sellRate` 或来源不明的行单列，核实真实来源与旧 upsert 是否保留他源卖出价；缺乏证据且仍可能被取价选中时，禁止放行该币对。ErApi 冷缺口由第 2 节决定，v2 图表数据不能作为清空旧缓存的依据。
4. **按清单事务执行，确认幂等。** 演练、实际执行及复跑均从同一份原值清单派生期望值，使用主键、原字段和版本标记或完成记录做条件更新。第二遍仅核对或处理尚未完成的批次，报告候选、转换、替换、冲突、缺失及已完成数，已完成批次更新数为 0。数值等于 1 或舍入后前后值相同的记录仍通过清单状态判定。验证事务失败、并发改写或中断后恢复，避免重复取倒数。
5. **只开放新代码并核验。** 用新读写版本在隔离副本回源、预热并验证。正式维护库的预热也在流量开放前执行，并记录全部新增键及覆盖前值，包含原迁移清单之外被触及的行。核对账本与非目标且非预热行逐字段一致，ErApi 可恢复日期仍可取，历史图表、原时点和最新接口均未读到旧方向。以真正成功的最新回源更新确认时间，再恢复流量与定时刷新。开放前若校验失败，保持隔离并按日志恢复所有覆写原值，只删除本维护窗新增的缓存行，再恢复配套读写版本。开放后的异常先暂停受影响流量，再盘点新增写入，避免用旧快照覆盖开窗后的记录。已记账的持仓、交易、分配、成本快照或更正日志不在本次缓存转换内。
